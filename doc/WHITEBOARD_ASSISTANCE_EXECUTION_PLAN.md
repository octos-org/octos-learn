# 小章鱼辅助融入白板：执行计划

日期：2026-09-07。状态：产品需求已由用户确认；实施中。当前证据和未完成项见 [实施状态](WHITEBOARD_ASSISTANCE_IMPLEMENTATION_STATUS.md)。

本文依据用户在本任务中的直接说明重新制定，替代两份 Kimi 计划在本次优化中的执行依据。
本文是执行依据；各阶段完成情况以实施状态及验收证据为准，不授权公网部署。

## 1. 优化原因与目标

用户对“小章鱼辅助”的主要不满不是辅助内容数量，而是它与白板的融合方式以及请求生命周期不可靠：

- 框选后直接语音问，曾因说话太快而看似无效；用户后来判断可能与 VAD 尚未识别有关。本次不据此调整 VAD 阈值或实施自动开麦。
- 选区提问却出现“正在准备课程”加载卡片和“我正在整理这道题，马上写到白板上”的教师文案，错误地表现为开课。
- 请求“将其更改为可以绘制函数图像的形式”时，系统擅自产生图形和辅助卡片。用户希望老师般的手写批注直接出现在原稿旁。
- 一次请求超时后，下一次提问成功又带出了前一次的迟到结果。用户要求超时请求永久失败，迟到内容不再显示，而非恢复成功或去重。

目标是让检查、建议和改写自然成为白板上的普通笔迹，并保留之前的速度优化成果。

## 2. 已确认的产品需求

### 2.1 首版范围

直接板书覆盖：

- “检查并建议”按钮。
- 文字或语音中的改写、纠错、转写请求。

普通解释暂时保留现有交付方式；明确要求绘图时继续使用现有图形展示。更广泛的解题板书、全面替代辅助卡片不纳入本次。
意图由现有模型调用判断，不新增独立分类往返，不用客户端关键词硬规则替代语义理解。

“改成可以绘图的形式”不等于“现在画图”。不得为了绘图改动数学含义，也不得把等价整理描述成纠正错误。

### 2.2 手写批注的具体形式

在原稿附近空白处，以手写体写简短说明，另起一行写公式；可有几行必要说明，不生成卡片背景。
例如原稿为 `y = x² + z³`，请求改成可绘图形式，期望类似：

> 原式可表示三维曲面，等价整理为：
> x² + z³ − y = 0

这是等价改写示例，不意味着原式错误，也不自动绘图。
检查出实际错误时写明具体问题和建议；没有错误就如实说明，不强行改写；识别不确定时明确表达不确定性。

模型只提供简短内容，程序负责落点、换行、字号、行距、公式行与普通文字行的排版。
采用手写体和线性公式记法，可程序化排版上标下标；本次不实现完整分式、根式、多行对齐的数学排版引擎。
不做逐笔动画；首版不提供板书复制成文本。

### 2.3 与普通笔迹同等对待

- 使用同一个 Editor，组件持久携带 `origin: student | ai`，无需双 Editor。
- AI 写入只能新增组件，不覆盖、修改或删除学生原稿。
- 可框选继续提问、移动、擦除、撤销、重做、保存并刷新恢复。
- 擦掉原稿不联动删除已经生成的 AI 板书。来源引用用于追溯，不是板书存活条件。
- 回放时与普通学生笔迹一起隐藏、结束后恢复；不增加 AI 板书专用隐藏层。
- 首版仍存在的解释卡片和图形展示继续沿用现有行为，不顺带移除其隐藏或来源管理逻辑。
- origin 用于保留来源和下游证据过滤；不要求用户学习 origin、artifact 等实现概念。使用可辨识的笔迹颜色，避免增加独立悬浮角标组件。

### 2.4 语音选区

用户常态是先开麦、再框选，未来可能长期开麦。不能以点击开麦作为唯一捕获时机。
本次有效说话开始时冻结选区 A；之后取消框选、改选 B 或等待返回，都不改变本次请求。下一次说话再使用当时的选区。
捕获和上传必须属于同一轮，不能图片来自 A、元数据来自 B。
无有效说话不记录学生操作；取消本次语音和 VAD 误触发要释放临时上下文。
“取消框选”不等于“取消本次语音请求”。

### 2.5 超时语义

- 保持现有 RPC 超时阈值，不增加自动重试，不做重复提问去重。
- 一旦请求被判为超时，该轮进入持久终态；此后到达的内容丢弃，不恢复为 answered、不上板、不播放旁白。
- 刷新、重连、重新枚举文件或其他提问完成，都不能让超时结果重新出现。
- 用户重新提问建立独立 turn，两次文字相似与否不影响处理。
- 丢弃指产品不再消费该结果；本次不要求删除服务端文件或取消服务端模型执行。

### 2.6 速度硬约束

不允许此次功能优化造成已有速度优化回退。沿用
[数学质量优化计划](../docs/MATH_QUALITY_IMPROVEMENT_PLAN.md)的硬约束和
[实施状态](../docs/MATH_QUALITY_IMPLEMENTATION_STATUS.md)的度量方法。
不能用延长超时、降低模型质量、删掉必要回答、占位符提前出现或旧 15 秒目标掩盖变慢。

## 4. 实施序列

### P0：复现与速度基线

先固化用户的原始请求、选区 SVG/图片与操作序列，使用隔离本地测试会话：

1. 开麦后再框选，直接语音提问。
2. `y = x² + z³` 配“将其更改为可以绘制函数图像的形式”。
3. 第一次超时、第二次成功、第一次结果随后被枚举到。
4. 检查正确式子、检查错误式子、识别不确定、明确绘图和普通解释。

记录语音事件的真实顺序，分别覆盖本地 VAD 与私有 ASR 路径。确认哪一事件可以及时冻结说话起始选区，不能把 `onTurnStart` 的名称当作发生在语音起始的证据。
阶段出口：复现夹具与基线记录齐全；若具体技术假设不成立，修正实现设计，不修改已确认需求。

### P1：请求生命周期与选区反馈（octos-learn 独立 PR）

#### 语音按轮冻结

- 在语音起始事件建立临时 utterance 身份，与后续正式 turn 关联；误触发可释放，不提前生成问题记录。
- 冻结所选组件内容、来源和白板上下文，再异步生成图片。不能只保存一个稍后读取当前 Editor 的函数。
- 图片、快照、录音、上传路径、路由和后续构建请求均读取该轮不可变上下文，不反复读取全局 pending ref。
- 捕获使用 generation/取消标记；取消语音、会话切换、组件卸载后，异步完成不得写回或启动已取消请求。
- 捕获失败应显示针对本次选区请求的错误或重试提示，不能静默转成新课程。
- 不调整 VAD 阈值、不让新字体加载或分类调用阻塞麦克风就绪；现有显式面板入口也走同一轮上下文。

#### 选区反馈

- 无实际问题时不显示生成 loading；准备快照不等于增强请求处理中。
- 从实际轮级状态派生选区反馈，避免再增加一个独立布尔状态导致并发请求互相清空。
- 选区问题处理期间使用选区文案，例如“小章鱼正在看你框选的这部分”；不用开课文案，也不在未确定交付类型前承诺正在写板书。
- 课程请求保持现有课程反馈；已存在课程不能吞掉新选区问题的反馈。
- 两个独立请求并行时，一个结束不得清除另一个仍在处理的状态。

#### 超时终态与消费屏障

- 建立按 session + turn 持久化的终态记录，区分超时、用户隐藏等原因；不单靠 question 是否存在过滤结果。
- 明确区分桥接超时异常与其他失败，核对现有错误传播是否保留超时类型。
- invoke 完成且结果校验成功前不正式展示该轮 artifact；超时与成功采用唯一终态决策，不能先上板后收到超时再留下内容。
- 超时标记落盘后，文件发现、artifact 加载前后、渲染、上板、恢复与旁白入口都检查终态。
- 标记前已开始的异步加载也必须在提交结果前复查，防止时序穿透。
- 保留失败反馈及独立重问入口，不通过删除失败问题来伪装成功。
- 历史记录若未保存失败类型，不能凭错误文案猜测超时：有可靠超时证据才迁移；上线前记录历史兼容限制，不把普通失败一并丢弃。

阶段出口：清空/改选不漂移、未说话不假 loading、超时在所有到达顺序下不可复活。此阶段不实现迟到成功 reconcile。

### P2：意图纠正与最小输出（learning-coach 独立 PR）

- custom-question 默认直接回答实际请求；明确绘图才执行绘图。“可绘图形式”作为改写夹具固定下来。
- generate-plot 保留其绘图规范；custom-question 保留必要的显式/隐式/三维表达式规范，并清楚限定适用意图。
- 不靠禁止 `implicit_surface` 等术语验证意图正确性；测试内容和适用条件。
- 不新增模型调用，不要求额外思维过程、重复排版版本或可复制代码块；用户明确首版不需要复制功能。
- 板书链路尚未启用时，用当前支持的回答类型交付正确内容，作为可独立验证的过渡修复；最终目标仍为 P5 直接上板。

阶段出口：原始改写请求不再擅自绘图；明确绘图、解释与检查回归通过；输入预算与时延符合第 6 节。

### P3：同 Editor 板书能力原型与持久化（OLL 独立 PR）

先做最小浏览器原型，验证字体轮廓到笔迹组件的真实接口、组件 origin 与持久 ID 的 SVG 往返、框选/移动/擦除/undo/redo。不能仅因 API 存在就宣布整个方案可行。

- 新增受控批量 AI 写入口，只追加组件；一份完整批注作为一个撤销事务。
- origin 与稳定组件 ID 经保存、加载、移动、复制及擦除拆分保留正确语义；新子组件不得复用导致身份冲突的 ID。
- 老文档无 origin 的组件按历史学生笔迹处理；不能把未知新版本静默解释成学生原稿。
- 快照 v5 表达每个组件的来源，并将来源纳入完整性校验；保留 v1–v4 的原校验和读取规则，不重写旧快照。
- 被框选的 AI 板书可再次参与识别；学习证据等纯学生消费端显式过滤 origin，不能把整个混合 SVG 当成学生作品。
- 已交付板书不受源组件存续约束；旧卡片删除规则不能误删新板书。
- 同普通笔迹参与回放与恢复，验证课程切换、刷新、回放合并的 ID 与文档身份稳定。

#### 原子保存、幂等与撤销

在 Runtime 持久化层统一保存笔迹文档与板书事务元数据，避免在 workspace 额外写一份互不原子的 localStorage 映射。
事务至少记录 session/document/turn、artifact 身份、组件映射及应用状态；同一 artifact 重载不能重写。

- 先准备整份批注，再批量提交；定义崩溃恢复可识别的事务状态，不逐字保存为多个不完整成功。
- 若当前存储结构不能原子容纳 SVG 与元数据，在该 PR 内引入版本化单记录或事务存储，并验证迁移后再接线。
- 用户部分擦除、移动和撤销属于主动编辑，不得被恢复程序当作写入缺失而补齐。
- undo 撤掉一次板书后保留已消费身份，重新枚举 artifact 不重新写入；redo 恢复原事务。
- 擦除后撤销、重做与刷新必须得到一致文档；持久记录不能覆盖当前用户编辑。

同步 SPEC、PLAYBACK、AUTHORING 与相关决定：原稿不被覆盖、来源可分离审计，不再沿用旧计划的双文档或联动删除口径。
阶段出口：原型交互通过、持久化故障注入通过，才能进入产品接线。

### P4：板书结果契约与兼容消费准备（跨仓库分别提交）

- 最小板书结果类型包含简短说明行、公式行；具体 schema 在实现中定稿，避免不必要字段。
- 位置锚定直接使用请求的选区，不让模型生成绝对坐标、SVG path、字号或组件 ID。
- 校验行数、文本总长、控制字符和公式表示；正常中文与数学符号不能被粗暴白名单删掉。
- 请求能力声明支持 board_writing 时才允许生成此类型；模型 schema 和程序结果校验共同约束，不能只靠 prompt。
- learning-coach 的 skill/action 参数、实际解析、结果类型和 artifact 版本同步；验证参数没有在桥接途中丢失。
- 客户端先加入版本化读取能力和对未知结果的安全处理，再启用新输出。能力声明只保护新请求，不自动解决历史 artifact 被旧客户端枚举的问题。
- 发布与回滚矩阵必须覆盖旧客户端读取新 session、缓存旧资源、新前端对旧服务端、旧结果恢复。若旧客户端无安全读取能力，明确最低兼容版本并先完成该版本发布，不宣称任意部署顺序安全。
- 功能开关在字体、Runtime 和新读取能力未就绪时不声明板书支持；不能在收到结果后悄悄改回卡片充当板书验收通过。

阶段出口：新旧请求、历史结果及回滚路径有明确测试证据；生产端输出仍默认关闭，等待 P5。

### P5：字体、排版与产品上板（octos-learn 独立 PR）

- 使用手写中文及西文字体，验证实际字体格式到 outline 的解码链路；不假设 WOFF2 可直接由所选解析库读取。
- 使用许可清楚的字体并随资产保留必要许可信息，不另设正式授权审批流程。
- 字体解析缓存、必要资源提前准备，避免首个请求返回后才下载大字库；预加载不得拖慢启动、语音或课程关键路径。
- 缺字优先使用覆盖该字的手写字体；原型阶段验证常用中文、数学符号和异常输入。不得静默丢字；仍无法表达时显示明确错误，不生成缺字公式或未经确认的卡片替代物。
- 限制排版行数、路径复杂度和同步计算预算；使用当前位置的 occupied bounds 避开已有内容，包括生成等待期间新增的笔迹。
- 简短说明与公式独立排版，整体邻近冻结的源选区；源被擦除时仍可按已冻结位置放置，不撤销已提交问题。
- 完整 artifact 通过终态检查与校验后，经 Runtime 一次事务写入；不创建同内容辅助卡片，也不遗留假 loading 问题卡。
- 普通解释、明确绘图保持现有交付；更新 OLL 精确 pin、BOM、contract 和交接记录。

阶段出口：用户确认的体验矩阵及速度门槛全部通过；本地验收完成不自动部署公网。

## 5. 必须覆盖的验收场景

| 场景 | 通过条件 |
| --- | --- |
| 先开麦，再框选 A 并说话 | 本次正确围绕 A，无课程 loading，无相机内容挤占选区 |
| 说话/捕获/上传/等待期间清空 A 或改选 B | 当前轮图片与元数据仍属于 A；下一轮使用新选区 |
| 误触发、取消语音、会话切换 | 无幽灵问题、无旧 capture 写回；选区变化本身不取消已发请求 |
| 超时后服务端晚到，或晚到结果随第二次成功被发现 | 首次保持失败且无内容；第二次独立正常显示 |
| artifact 加载与超时回调交错 | 无短暂成功上板后又失败，无迟到内容穿透 |
| 超时后刷新、重连、重新枚举 | 仍不消费该 turn；其他成功结果不受影响 |
| 原始 y=x²+z³ 改写请求 | 手写简短说明与等价公式出现在旁边，不声称原式错、不自动画图 |
| 检查正确/错误/不确定笔迹 | 分别如实说明、给具体建议、表达不确定性，不编造纠错 |
| 普通解释与明确绘图 | 保持现有类型；显式、隐式、三维绘图均有覆盖 |
| 擦原稿、擦部分 AI 字、移动 AI 板书 | 独立保留/真实擦除/真实移动，刷新不复活、不补字 |
| 上板 undo/redo，擦除 undo/redo | 与普通笔迹一致，artifact 重发现不抵消用户操作 |
| 写入或保存中断 | 恢复完整事务或未应用状态，无重复、半份内容或学生原稿损坏 |
| 再次框选 AI 与混合笔迹 | 可继续提问，来源与完整性校验正确 |
| 回放课程与结束恢复 | AI 与学生笔迹一起隐藏恢复；旧解释/图形行为不回归 |
| 新旧客户端、服务端与历史 artifact | 按兼容矩阵安全读取、降级或明确阻止，不静默丢内容 |

## 6. 速度验收：合入硬门槛

基线采用实施前当前已优化版本，不使用旧 Kimi 计划的“system prompt 可增加 200 bytes”额度。

1. 保持专用 action 快速路径，以及课程已有 bootstrap、流式、渐进交付、局部修复与 hedge 策略。正常成功路径不增加模型往返或自动重试。
2. 逐请求核算 system + 用户上下文 + capability + schema 的实际输入 token；对应原有案例不高于冻结基线。新增规则替换冗余内容，不叠加长 prompt。
3. 不要求双份可复制输出或长解释；模型只产出用户需要的批注。记录输出 token，不能通过省略必要内容获得假加速。
4. 选区辅助同时测语音起始至提交、提交至真实内容可见、完整内容可交互、字体/排版/持久化开销；手写路径真正可见才算交付，占位符不算。
5. 课程回归测首个可播放片段、整课耗时、播放断档、编译成本及修复率，不能只测新辅助功能。
6. 固定 provider/model、机器、输入和可比缓存状态，基线/候选交错重复；分别报告冷启动与热缓存、正常成功与含异常路径，以及 p50/p95、超时率、输入输出 token。
7. 不用三次样本证明 p95 达标；先采集足够重复数据，噪声或结论不确定时继续采样，不记为通过。不预先设“允许变慢百分比”。
8. 一旦证实可重复回退，即使功能正确也不合入；先修实现、减少输入或本地开销，再做对照。外部模型/网络无法保证每次耗时完全相等，但不得将这种波动当成接受系统性变慢的理由。
