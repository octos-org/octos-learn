# 小章鱼辅助与白板的空间融合方案

日期：2026-09-07。本文针对“已有辅助卡片时，新板书覆盖卡片”的问题，定义当前修复和后续统一模型。

## 结论

辅助卡片和 AI 板书必须参加同一套白板空间分配。输出形式可以不同，但不能各自根据原选区独立计算位置。白板上的每个可见对象都要提供世界坐标边界，生成中的占位和最终内容使用同一个位置。

产品上只保留两种表面：能像普通笔迹一样存在的“板书”，以及确实需要容器的“白板对象”。函数图、三维场景、较长解释仍可使用卡片，但卡片应是放在白板坐标系里的对象，而不是盖在白板上方的一层页面 UI。

## 当前修复

- 辅助卡片现在暴露稳定的 `data-enhancement-id`，板书排版会把其真实渲染边界加入障碍物集合。新板书优先放在原选区右侧；该位置已有卡片时向下寻找最近空白，不移动用户内容。
- 浏览器验收夹具同时放置一张已展开辅助卡片和一份新板书，直接断言两者的世界坐标边界不相交。
- 卡片型请求开始时立即在最终卡片槽位显示卡片 loading；结果替换该占位，不发生位置跳变。板书型请求不创建卡片占位，只保留右下角小章鱼气泡。
- 请求开始时冻结 `delivery_mode`，后端 schema 和结果解析共同禁止卡片与板书在完成时互相改道。这个判断不增加模型调用、重试或等待。

当前冻结规则覆盖有限且明确的产品意图：工具栏的检查直接板书，解释和明确绘图使用卡片；自定义请求只识别已经纳入验收的检查、纠错、改写、转写和明确绘图表达。它解决了“生成前必须知道该不该展示卡片 loading”的时序矛盾，但不是最终的开放语义分类器。以后扩展更多意图时，应让同一次模型调用先流出受 schema 约束的 `delivery_mode` 事件，再继续生成内容；不能额外增加一次分类调用，也不能让 pending UI 猜一种表面、终态结果再切换成另一种。

## 交付形式边界

| 内容 | 表面 | 行为 |
| --- | --- | --- |
| 简短检查、建议、纠错、改写、转写 | AI 板书 | 与学生笔迹相同，可选中、直接拖动、擦除、撤销和持久化 |
| 函数图、三维场景和需要交互的可视化 | 白板对象 | 可直接拖动、缩放、最小化和持久化 |
| 放不进一小段板书的长解释 | 白板对象 | 以便签形态存在，尺寸参与空间分配 |
| 问题与来源关系 | 轻量引用 | 连接线只表达来源，不控制删除和存活 |

## 统一对象模型

下一阶段把现在分散在 DOM、Ink Runtime 和课程 Runtime 中的空间信息收敛为 `WhiteboardObjectRegistry`。每个对象至少包含：

- 稳定 ID、类型、世界坐标边界和层级；
- `pending | ready | failed` 生命周期；
- 是否可移动、是否被用户固定；
- 可选来源引用，仅用于追溯和连接线，不控制对象存活。

对象类型覆盖学生笔迹合并区域、AI 板书、辅助卡片及其 loading、课程节点、问题卡和浮动白板控件。Ink Runtime 继续保存笔迹，卡片继续由 React 渲染；Registry 只统一空间事实，不复制内容状态。

Registry 还要维护单调递增的空间 revision。每次绘制、拖动、缩放、最小化、删除或课程节点落位都会增加 revision；异步排版只能在它读取的 revision 仍有效时提交。这比比较某一类 DOM 节点更可靠，也能防止生成期间用户移动对象后出现新的重叠。

## 统一放置流程

1. 请求开始时确定输出表面和预计尺寸。卡片立即预留固定槽位；板书等文本排版得到精确轮廓尺寸后再申请槽位。
2. 放置器从来源附近生成候选位置：右侧同一行、右侧下一行、来源下方、来源上方，再向外扩展。
3. 对候选位置计算分数：与现有对象相交直接淘汰；其余按距来源距离、连接线穿越数量、遮挡当前视口和阅读顺序评分。
4. 选择得分最低的位置并原子提交。生成期间新增或移动了对象时，在提交前用最新 revision 重算。
5. 用户移动过的对象标记为固定。后续输出只能另找位置，不能为了自动排版挪动用户已经摆好的内容。

卡片 loading 在第 1 步就注册为 `pending` 对象，并用预计尺寸占位；终态只替换内容和精确尺寸，再做一次局部碰撞复核。板书不显示白板内占位，但生成完成后用字体轮廓得到精确边界，再按同一流程申请空间。右下角小章鱼气泡只表达任务状态，不参加白板空间布局。

## 卡片的产品形态

保留卡片只用于本身需要容器的内容，例如可交互函数图、三维场景和较长解释。卡片应成为白板对象：可以直接拖动、缩放、最小化，位置持久化；与原选区的细连接线只表达来源。简短检查、建议、纠错、改写和转写继续使用普通 AI 笔迹。

这样卡片不再是覆盖在白板上的特殊 UI。课程播放需要处理的也是统一对象可见性策略，来源删除不会自动删除结果，空间避让也不需要为每种输出单独维护规则。

开始课程时，课程布局从 Registry 申请新的连续区域，镜头移动到该区域。旧辅助卡片和普通笔迹仍留在原来的白板位置，自然离开视口，无需全局隐藏；用户之后平移回去仍能看到它们。这样课程和辅助内容不会在同一屏幕争抢位置，也不会引入一套只对卡片生效的播放期隐藏逻辑。

## 落地顺序

1. 当前版本先让所有现有卡片暴露稳定 ID 与世界坐标边界，板书立即避让它们；这已修复附图中的覆盖问题。
2. 把卡片位置、缩放和最小化状态持久化，并让卡片支持整卡直接拖动；来源只保留引用关系。
3. 引入 Registry 和空间 revision，逐步接入课程节点、笔迹边界、卡片 pending/ready 状态及浮动控件。
4. 将自定义请求的交付形式改成同一模型调用的早期结构化事件，移除客户端有限意图映射。
5. 课程生成改为申请新区域并移动镜头，用空间分区取代播放期卡片隐藏分支。

## 验收标准

- 两张已展开卡片位于原稿右侧时，新的检查板书出现在最近空白处，边界与两张卡片均不相交。
- 卡片 loading 与最终卡片共用位置；板书请求从开始到完成都不出现卡片 loading。
- 缩放、平移、刷新后所有对象的世界坐标关系不变。
- 用户移动卡片或笔迹后再请求辅助，已有对象保持不动，新结果重新避让。
- 空间计算不新增模型调用；普通课程启动和播放路径不加载板书排版模块。
