# 学生讲师头像：转向二维插画角色

日期：2026-11-02。用户认为三维小样效果不好，明确不再要求接近苹果 Memoji，希望在只有用户与当前协作的条件下做出自身特色。本轮重新确定方向，不继续以修补三维形体作为主路线。

实施更新：用户随后要求制作效果，现已完成[可播放二维小样](LEARNER_AVATAR_2D_PREVIEW.md)，入口 `/teach/avatar-2d`。可看嘴眼/头部动作、试听本机中文示例、切换三种表现；聊天动图使用同一绘制函数。完整课程播放器尚未切换，本文后续范围仍为计划。

## 建议的体验

做“会讲课的二维绘本角色”：视觉上是一位有性格的小讲师，表现围绕讲解、思考、指向板书和讲完后的回应。相机保留孩子的部分表达，预设动作承担清晰的教学姿态；不把所有真人动作逐一复现作为体验目标。

建议保留星狐所属的学院世界观、橙色与奶油色、蓝色学院服和星形徽章，简化发束与服装纹样。学生角色与老师来自同一世界，但可有自己的配色、徽章和配饰，保留孩子作为作者的身份。先做好一个角色，再扩展角色选择和装扮。

视觉概念先展示同一个角色的四种状态：自然、讲解、思考、开心。静态概念图用于确认画风；不把生成出来的表情图当作已做好图层、嘴型对齐和绑定的运行资产。

本轮使用内置 image_gen，根据已有星狐参考生成了[四种表现概念图](avatar-animation-phase-a/2d-concept/star-fox-expression-direction-v1.png)。已检查为明确的手绘插画风，保留角色与学院服识别；姿态之间的头角度和部件位置有差别，不能直接当连续动画帧。[最终提示词和生成记录](avatar-animation-phase-a/2d-concept/GENERATION.md)随图保存。未调用项目 BYOK 语音服务，未修改应用资产或默认渲染器。

## 首版技术选择

采用少量透明图层、可替换的嘴眼素材与轻微位移/旋转，先用浏览器 Canvas 2D 实现。对于同一角色，用一个锁定的基础画稿组织图层；不要每帧重新生成角色，也不要直接将不对齐的多张全身图连续切换。

建议结构：后发与耳朵、身体/姿态、脸部底稿、左右眼与眼皮、眉毛、嘴型、前发、配饰。实际制作先取得没有旧嘴/旧眼残留的基础图层，补足遮挡处，再对齐替换部件；当前已选 PNG 是平面成图，不能假定已经具备这些图层。

首版范围：

| 部位 | 首版能力 | 之后再扩展 |
| --- | --- | --- |
| 嘴部 | 闭嘴、小开口、大开口，跟随最终配音的真实时钟 | 圆唇、横向口型等 6–8 种发音形状，需有对齐的发音信息 |
| 眼睛 | 睁眼、半闭、闭眼；小幅视线移动 | 非对称眨眼、与表情组合修正 |
| 头部 | 小幅点头、左右偏移和轻微歪头，限制形变范围 | 另画的三分之二角，不承诺任意转身 |
| 姿态 | 自然、讲解、思考、开心，少量预设的手势 | 更多教学姿态、可调整配饰 |
| 教学交互 | 段落结束回到待机，可明确选择姿态 | 根据有明确语义的白板步骤/指示事件看向板书或示意重点 |

嘴型、表情和姿态分开控制，避免“微笑时不能说话”。相机表情输入有数据时才使用；无相机时可以使用明确的角色待机动作。停顿不能被当作识别出孩子在“思考”，情绪不从相机推断。预设举手也不冒称来自真实手势捕捉。

## 如何做出 Octos Learn 的特色

1. **角色参与讲课。** 讲解时看着听众，明确的板书重点事件出现时转移目光或配合指示；不能仅依据音量随意摆动。
2. **孩子导演自己的讲述。** 可以在卡片上选择“讲解”“想一想”“我发现了”等表现。选择控制角色演出，不评价孩子当时的情绪，也不替孩子生成课程结论。
3. **同一学院，自己的身份。** 老师与学生的衣服和徽章语言一致；学生保留自己的角色名字、颜色和小配饰。作品呈现由孩子讲出来的学习成果。

首轮只落地四种表现和一个角色。姿态编排、板书事件衔接、装扮是后续产品功能，当前没有实现。

## 为什么不直接上完整 Live2D

[Live2D 官方素材拆分说明](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)要求将插画拆分成眼睫毛、眼球、轮廓等部件，再进行建模。二维能够保留插画风格，但高质量的拆图与绑定仍然是实际工作，不能把换技术名称当作免除美术制作。

因此先把有限动作的图层角色做漂亮、做稳定；之后若确实需要更大转头范围和柔性变形，再评估完整二维网格绑定。此轮没有采购工具、接受许可或安装新的运行 SDK。

## 现有代码可以复用的部分

- `FaceFrame` 中的眨眼、眉毛、嘴部和头部参数：增加二维映射与幅度约束即可复用捕捉输入格式，不需要为二维重新采集图片。
- `lip-sync.ts`、最终配音哈希和旁白媒体时钟：保留相同的同步来源，换成二维嘴部绘制。
- 表情片段、本机库、回放/定位和合成排练：参数与渲染分开，可用于二维检查。
- 作品预览与 `.olesson` 完整播放器：更换表现层即可复用板书与音频播放链路，不新增课程生成或语音模型往返。

不能直接复用三维 GLB、morph 绑定和三维眼皮。二维需要独立资产清单、图层顺序、锚点/遮罩和加载释放逻辑。现有课包 v2 没有角色资产/版本，正式支持二维角色随包分享仍需格式设计。网页 CPU 面部识别的负担也不会因为角色改为二维而自动消失。

## 落地顺序与验收

1. 确认一个容易拆分、在小头像下仍可读的画风。本轮先生成视觉概念，尚未替换应用中的渲染器。
2. 做一个嘴部与眼睛可分离的正面角色，接入已有校准音，只检查开闭口、眨眼和轻微点头。验收重点是美感、对齐、边缘干净和停止时自然，不拿接口或格式通过代替视觉通过。
3. 接入现有录课回看：以最终合成声音驱动嘴部，有表演轨时才使用对应眉眼/姿态；没有可用输入则自然待机。先保留原有音量包络开合的准确描述，不称其为精细发音。
4. 扩展四种可选择的教学姿态，并处理跨姿态嘴眼位置。姿态切换不能导致脸和服装忽然变形或跳位。
5. 在目标安卓触摸大屏与实际白板同时测试，优先稳定 30 FPS 的角色渲染，限制贴图尺寸/层数和设备像素比；设备尚未实测，因此不承诺具体帧率、电量或内存改善倍数。

三维源代码与小样保留作为历史成果；本轮没有删除它，也没有静默更改现有录课数据或默认播放器。是否采用概念图、何时切换默认角色，应由可运行二维小样的实际效果支持。
