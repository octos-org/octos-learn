## 为什么重复，如何修复

此前已有确定性复用，但登记的是“整个组件”，身份包含组件类型。一个复合组件内部生成的函数图没有单独登记；随后另一个组件生成相同图像，就绕过了复用。

编译器现在在课程内登记实际生成的 plot、geometry、scene3d、diagram 卡片。只有编译内容等价才复用；重定向整卡、片段、连接、分组及位置引用，保留复合组件其余内容。数学内容、实际变量绑定、单位、测量及交互设置均参与比较。有量纲坐标轴标签及非数学图的教学标签继续保留；标题及二维视窗范围延续原有的展示属性处理。不同绑定、额外曲线、不同测量方式和实际不同教学对象不合并。未知差异保守地保留为不同内容。

登记与身份处理延迟到请求第二个组件时，第一张画面不执行新的身份序列化或比较。既有整组件复用继续生效。

## 为什么出现大行距，如何修复

一个共享控制/练习的依赖列表跨了两行。旧布局在两行分别放置同一个附件，后一行的位置覆盖前一行的位置，但前一行已经计入的高度没有撤销。

新增可选 `ownerNodeId` 表达唯一显示归属。依赖列表仍表达所有受控画面；控件归属第一张绑定图，练习归属最终目标图。OLL 只在所属阶段放置和占位，归属节点未到达时等待。多张任务不覆盖彼此，任务下方的讲解卡避让其实际位置。未传新字段时有兼容默认值。

真实问题课的布局数据复测：原间距 229，修复后 72，恰好去掉 157 的重复占位，控件位置不变。九门内置课的结构对照中，所有卡片和附件矩形均不变；此项采用语义尺寸及相同布局参数，不等同于九门课逐门电视人工验收。
