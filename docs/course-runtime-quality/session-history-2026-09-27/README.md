# 会话入口与历史标题修复（2026-09-27）

## 用户可见变化

白板页恢复学习记录侧栏，替换原设置按钮。支持搜索、当前会话标记、新建白板和继续历史课程；首页保留设置入口。侧栏为模态抽屉，支持 Escape、焦点循环、关闭后恢复焦点，背景不可交互。切换或新建前等待当前笔迹保存；失败时阻止离开。

首页最近白板始终最多两行：桌面 4×2，中屏 3×2 或 2×2，手机 1×2。隐藏卡片不会留在键盘焦点顺序中。全部记录仍可从“全部学习记录”打开。

普通白板使用 `/board?session=<id>` 恢复明确的会话；课程实例保留原版本与实例参数。白板随路由导航重新初始化，避免从课程跳到普通白板或连续新建时沿用旧的入口状态。

## 标题调查

仅只读检查本机 `alan0x` profile 的学习会话与课程文件，没有修改或删除服务端数据：

- 53 个学习会话 JSONL 均非空，共 265 条消息记录。
- 51 个会话标题以内部 LEARNING 标记开头，1 个空标题，1 个可读标题。
- 41 个会话存在课程文件，共 134 个 `.octos-lesson.json`；这些 JSON 均可解析，41 个会话均有可恢复的 lesson.title。

旧实现只使用服务端列表标题，遇到内部标记就显示“已保存的学习”，从未读取已保存的课程标题；本地缓存一旦存入兜底标题，后续同步又不会替换。两者造成大量卡片同名。

这证明检查到的课程文件仍然存在，并定位到标题展示/恢复缺陷。此检查不是对全部历史内容的备份比对，不能由此证明每个会话的原始内容完整；未发现课程文件的其余会话，也不能仅据此认定发生丢失。截图中的账号环境未与本机 profile 作身份绑定。

## 修复策略

优先使用有效服务端标题或已有本地标题；缺失时读取已保存课程的 lesson.title，优先完整文件，再回退到有效用户提问。仅补齐本地显示索引，保留自定义名称，不调用模型，不重生成课程。标题恢复并发最多 6 个会话，已有有效标题时不重复读取课程内容。白板启动的关键同步路径不下载历史标题，维持原有文件发现并发；标题恢复仅在首页后台与显式打开历史侧栏时进行，避免拖慢进入白板。

文件列表错误仍向上抛出，不允许将不完整结果用于清理本地索引。标题来源读取失败不会把已有课程从列表中隐藏。
