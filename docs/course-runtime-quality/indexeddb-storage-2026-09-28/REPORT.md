# 课程和笔迹存储改为 IndexedDB

## 背景与范围

开发环境 localStorage 实测共 5,242,180 字符，240 条课程记录占 90.4%，笔迹占 2.1%。课程缓存挤满额度后，历史笔迹重播恢复触发写入失败；前端失败分支仍标记恢复完成。

用户明确授权从 main 新建分支实施，不保留旧开发数据。本次从 main 的 45bf0c2 创建 `codex/indexeddb-learning-storage`，不做旧数据迁移。

## 实现

- 使用 `octos-learning-documents` IndexedDB 的 `documents` store 保存课程检查点、学生操作、练习进度和笔迹 SVG。
- 启动先打开数据库并读取键索引；播放器创建前仅加载当前课程三类记录。同步播放器接口通过内存缓存适配，异步事务提交才算保存成功。无需改 OLL 包，不增加模型调用。
- 数据库成功打开后，删除 localStorage 中旧 `octos-learning-oll:*`、`octos-learning-ink:v1:*` 和 v1 重播元数据。登录、偏好、学习记录索引、提问记录及 CoursePack 安装库不清理。v2 重播元数据仍是小型 localStorage 记录。
- IndexedDB 不可用时显示错误和重试，不静默退回 localStorage，也不先删除旧记录。
- 写入失败显示全局保存失败提示和“重试保存”。笔迹保存 Promise 保持待提交，恢复空间后重试同一快照，提交成功才继续 Runtime；避免重新导入旧 SVG。
- 合并失败保留源标记，取消原有 1.5 秒无条件“恢复完成”；成功合并的轮次在刷新时不会再次导入旧笔迹。
- 返回首页前等待笔迹保存与已排队的学习记录提交；课程读取期间保留旁白的麦克风占用，避免异步加载间隙启动语音采集。

## 验证

- 完整 Vitest：113 个文件、1057 项通过。
- TypeScript 和公网生产构建通过。
- 真实 Chromium：旧缓存占满后清理、登录与设置保留、长方形及斜率课程笔迹返回/重开/刷新、注入配额失败后重试、重播恢复后连续刷新，存储相关 4 项通过；另有整课全景、窗口缩放和笔迹布局 4 项回归通过，最终浏览器合计 8 项通过。
- 定向 ESLint 无错误，保留原文件既有警告。
- 单元测试使用 fake-indexeddb 验证大于 6 MiB 的文档读写、数据库重开、课程三个子记录、写入失败与重试。Runtime/UI 测试使用独立小型存储夹具；数据库持久性由存储单元测试和真实浏览器验证。

## Android 边界

Web 与 APK 共用这套 IndexedDB 逻辑。历史目标为 SKG M3G2 / Android 13 / WebView 101.0.4951.61；本次旧地址 192.168.1.63 不可达，因此没有实机安装或持久化验收。Android 模式前端资源构建（chrome64 target）已通过；没有生成或安装新 APK。IndexedDB 仍是设备本地数据，不等于云同步或卸载后的备份。

不发布公网、不更新 APK，不自动清空其他存储或安装课程包。新代码运行时会按上述前缀清理旧开发记录，回退旧版本无法恢复已清理记录。
