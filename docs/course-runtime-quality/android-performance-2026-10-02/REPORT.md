# Android 白板性能优化（2026-10-02 至 2026-10-03）

后续继续优化及最新交付见 [Android 导航缓存第二阶段](../android-performance-2026-10-03-phase2/REPORT.md)。以下为第一阶段历史记录。

已在局域网电视 `192.168.1.63:5555` 覆盖安装调试 APK，保留应用数据。本轮改善暂停课程后的手动平移与缩放，并修复真机检查发现的原生书写控件避让问题。动画播放、实际触控笔的端到端延迟与稳定 60 FPS 仍不在本轮验收结论中。

## 实现

- Android 构建使用短时图形预览：空闲时将函数图、几何图、过程图的 SVG 缓存为解码后的 PNG 图片，手动导航时启用世界层合成，停止后恢复原始 SVG。原始图形保持挂载，数学运算、参数与课程运行时继续使用 OLL。
- 电视 WebView 中直接使用 Canvas 预览出现曲线消失，最终版改用 PNG 图片合成；余弦单曲线、正弦／余弦双曲线的曲线、坐标轴、网格与标签已做真机画面对照。
- 更新的单个图形立即恢复实时 SVG；其他静态图形保留缓存。相同属性的重复写入与独立公式卡片的刷新不会清空图形缓存。
- 缓存只在课程暂停且镜头停止时准备，分批让出主线程。像素预算约 24 MiB RGBA，单图上限约 4 MiB，实际占用不含 WebView/GPU 的内部副本。不支持的图形或旧 WebView 保留原渲染器。
- 笔迹编辑器的延迟镜头同步等待下一次显示帧，避免慢帧期间安静计时器提前触发隐藏编辑器重绘。开始编辑时仍立即同步坐标。
- 透明辅助内容宿主横跨世界层，原来的整体 `data-oll-ink-input="ignore"` 会在其子卡片位于屏幕中央时生成覆盖整个视口的原生避让矩形。改为只标记实际问题卡片、辅助卡片、加载卡片；控件和任务保留原有标记。
- 开发服务显式统一 React 预构建，避免 HTML 测试夹具在依赖发现期间加载两份 React。生成的 `.local-dev` 副本不参与源码 lint。

## 后续人工验证发现的历史恢复布局问题

用户在 scrcpy 中发现旧学习记录里的单位圆与余弦图被拆开；删除学习记录、重新进入后布局正常。后续在隔离浏览器中复现：恢复已保存笔迹时只挂载了课程前缀，宿主把这些节点位置固定，随后恢复的其他节点被排到固定节点下方。该笔迹固定逻辑在性能优化前的基线中就存在；旧记录本身不能据此判为损坏。

源码已修复原始 CoursePack 的布局不受笔迹避障和前缀固定影响；后续提问课程继续使用笔迹避障。新回归使用真实 IndexedDB 笔迹保存／恢复，在课程前缀恢复后补全节点，并比较完整节点世界坐标；修复前失败，修复后通过。该修复的七项浏览器回归无重试通过。详细记录见 [历史恢复布局修复](HISTORY-LAYOUT.md)。

下方的性能数据来自当时的旧会话布局，只证明该场景中缓存开关的差异；不能作为修复后正常预制课布局的真机性能验收。当时没有在人工验证期间覆盖安装新包；后续应以第二阶段记录中的电视安装与测量为准。

## 真机性能对照

电视为 M3G2，Android 13，系统 WebView `101.0.4951.61`。屏幕保持 `3840×2160`，物理 density 480、原有 override density 640；WebView 为 `960×540` CSS 像素、DPR 4。

场景为原来的余弦课程实例及其追加课程，共 16 个节点、5 个课程图形、1 项既有笔迹。测量在同一 APK、同一挂载场景中按缓存开启、关闭、再次开启交替执行；关闭仅移除预览的相机订阅，其他代码、数据和系统显示设置相同。每个阶段为 60 次 requestAnimationFrame 采样，产生 59 个帧间隔，使用相同的正弦平移与 ±20% 缩放轨迹。FPS 为帧间隔 p50 的估算，不代表实测触控延迟。

| 阶段 | 平移 p50 / p95（ms） | 缩放 p50 / p95（ms） | 缩放约 FPS |
|---|---:|---:|---:|
| 缓存开启 | 33.3 / 133.3 | 50.0 / 83.3 | 20.0 |
| 缓存关闭 | 50.0 / 116.7 | 150.0 / 200.0 | 6.7 |
| 再次开启缓存 | 33.3 / 183.3 | 33.3 / 83.3 | 30.0 |

原始数据：[measurements.json](measurements.json)。

本次缩放中位帧率约提升 3–4.5 倍，平移中位帧率从约 20 提升至 30 FPS；平移 p95 仍有 133–183 ms，未改善到稳定流畅。平移时有 5 张缓存图片，缩放时部分图形更新后回退为实时 SVG，最大缓存图片数为 2。

所有阶段的课程节点布局保持不变，测量结束后相机与原始 SVG 恢复。缓存准备尚未完成或图形正在更新时使用实时 SVG，性能会随场景和设备负载波动。此前伴随活动重建的系统 1080p 实验改变了场景节点数量，未作为优化效果依据。

可复测脚本：`scripts/measure-android-whiteboard.mjs`。先连接 ADB，将应用的 `webview_devtools_remote_<pid>` 转发到本机 TCP 9240，在完整课程暂停后执行：

```bash
node scripts/measure-android-whiteboard.mjs --compare \
  --camera '-559.057,70.2953,0.326165' \
  --output delivery/android-performance/retest.json
```

脚本使用调试 WebView 内部相机接口，结束时恢复相机与订阅；不调用模型或生成新课程。
