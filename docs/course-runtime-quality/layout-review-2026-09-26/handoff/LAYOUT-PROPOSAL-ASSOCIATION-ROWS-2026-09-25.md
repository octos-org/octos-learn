# 课程白板布局方案：步骤行 × 行内关联区（我的提案）

日期：2026-09-25。作者：本轮接手 agent。前置：`LAYOUT-HANDOFF-2026-09-25.md`（现状与约束）。

## 1. 设计结论

**行 = 教学步骤（保留，被用户认可）；行内不再按"类型列"，改按"关联区"组织；练习卡跟随其控件；全部使用实测自然宽度，不做任何预留。**

每个步骤行内部从左到右分三区：

```
┌─ 互动区 ────────────┬─ 推导区 ──────────┬─ 笔记区 ────────┐
│ 视觉卡1  视觉卡2     │ 公式卡（阅读顺序） │ 笔记卡          │
│  └ 控件（滑块）      │                  │                │
│  └ 练习卡            │                  │                │
└──────────────────────┴──────────────────┴────────────────┘
```

- **互动区**：视觉卡并排（最多 2 张/行，超出折行）；该步骤相关控件在其视觉卡正下方；练习卡在控件正下方。"图→滑块→练习"纵向贴合，伸手可及。
- **推导区**：公式卡按出场顺序流动排列，到行宽上限折行。
- **笔记区**：说明/总结卡。
- 区宽 = 内容的实测自然宽度；空区不占位（收起）。行高 = 最高区。行按教学顺序自上而下追加。

## 2. 为什么这能解决当前问题

**对"空隙"（二元方程课）**：空隙来自按计划数量预留的整格宽度。本方案全部使用实测宽度——推导区只占用公式卡的实际宽度，笔记卡紧跟其后，空隙消失。

**对"练习卡离滑块太远"（偏导数课）**：练习卡从"最后一行笔记列"改为"其控件正下方"。练习开放时，练习卡出现在互动区底部，与滑块相邻。代价：它会使第 1 行变高、把下面的行向下推一次——发生在课后练习开放这个自然切换时刻，镜头本就在移动，可接受（用户已放松绝对不动约束）。

**对"整体乱"**：行骨架提供横向分组（步骤）；行内三区提供固定的局部语法（图永远在最左、公式在中、笔记在右）；所有边缘实测对齐、间距恒定。

## 3. 与三个被否决方案的关系

- 保留矩阵的行列骨架与"追加式行生长"（下方只增不改）；
- 取消"固定类型列宽"（空隙根源）；
- 取消 plannedSteps 预留机制（复杂性高、收益被自然宽度取代；可保留数据管线但布局不使用，或一并移除——实施时定）；用户已确认：不预留，接受新视觉卡出现时同排内容的一次性位移；
- 练习卡归属从 banded 版的"带尾"进一步改为"控件下方"（更贴近簇）。

## 4. 稳定性模型（放松后）

- 上方已封闭的行：永不改变。
- 当前行：新卡到来时行内重排（区位置可能右移/折行）——接受；行内卡数量 ≤5，重排幅度小且发生在教学推进时刻。
- 练习开放在课后：把第 1 行撑高一次，下方行整体下移一次——一次性、可预期。
- 手写批注/pinned 仍走既有保守回退。

## 5. 具体实施

1. `octos-lesson-language/packages/web-runtime/src/teaching-layout.ts`：矩阵的行内单元格从"类型列"改为"三区"：视觉区（2 卡位折行）、推导区（流排）、笔记区；区宽取实测；控件/练习附件挂在锚点视觉卡正下方（练习卡不再放最后一行）。
2. 练习卡重新归属注意多控件簇：挂在 anchorNodeIds 并集的最左视觉卡下。
3. 窄窗口（<1000px）：单列按出场顺序（现状不变）。
4. 测试更新：行序=教学序保留；新增"练习卡在控件正下方""推导区宽度=实测""空隙断言"（相邻卡间距 ≤ 恒定值）；移除 plannedSteps 预留断言。
5. 课程数据无需再改（0.2.3 的锚点修正保留）。
6. 浏览器实测三课 + 全 9 课，产出截图逐张人工评审后再谈"完成"。

## 6. 风险与验证责任

- 区宽实测意味着字体加载后的测量变化会轻微影响同排位置——靠已有的三遍宽度稳定化（board-view 已实现）收敛。
- 多步骤实时课程流式到达、新视觉卡晚于同排公式出现时，同排内容右移一次（幅度=一个视觉卡位宽，发生在教学推进时刻）——用户已确认接受。
