# Android 导航缓存第二阶段（2026-10-03）

后续电视直接触屏起步停顿的诊断和新 APK 见[触屏拖拽起步修复](../android-drag-start-2026-10-03/REPORT.md)。本报告保留第二阶段的版本及测量。

本轮接续 Android 性能优化，使用包含历史笔迹恢复布局修复的版本建立正常预制课布局基线。电视仍为 `192.168.1.63:5555`，4K 屏幕、960×540 CSS 视口、DPR 4、WebView 101；未调整系统分辨率或密度。测量时停止 scrcpy，完成后恢复。

## 定位与修改

真机 MutationObserver / CPU 诊断发现：平移时缓存有 5 张，停止后宿主重写函数图卡片高度（390 → 360、临时 auto），触发布局重算及缓存失效，下一次缩放只剩 2 张缓存；没有课程内容变化。诊断原始文件在 `delivery/android-performance/phase2-panzoom-mutations.json`，包含属性旧值、新值和缓存数量序列。父卡片样式变化期间，部分追加课程节点也暂时重排；只比较手势结束后的布局不足以捕获该问题。

只保留透明 SVG 并加绝对定位覆盖图的中间方案，虽保住了缓存，但真机缩放变慢。加入 visibility 隐藏的诊断也未达到基线；均未作为最终交付。

最终保留导航时 `display:none` 的 SVG 隐藏方式，并进行两项修正：

- 缓存图片使用 SVG 的精确 CSS 小数尺寸和原有 margin，继续在正常文档流中替代原 SVG；停止后恢复原 SVG。此前使用整数 clientHeight 会在比例布局中改变图形内容框。
- SVG 内容框相同，或隐藏时图卡宽度未变的情况下，忽略父图卡临时位置/高度测量写入；只装饰图卡边框的焦点类切换也不影响缓存。实际内容、绘制样式或尺寸变化仍使相应图形失效。

没有更改课程 DSL、数学内容、参数或预制排版。新增浏览器回归检查图像相对于原 SVG 世界矩形的精确位置、连续平移/停止/缩放的缓存数量和图卡尺寸；父图卡焦点/临时高度回归在修改前由 3 张降到 2 张，最终实现保持 3 张。

像素预算、单图分辨率上限、暂停/空闲准备、更新图形立即回退以及停止恢复实时 SVG 的策略与上一阶段相同。导航时极高放大仍可能暂时比 SVG 模糊，停止后恢复；本轮不以降低清晰度换取性能。
