## 问题来源

先前的优化主要针对整块白板移动。滑块是另一条路径：变量改变后，Runtime 更新语义状态，React 发布投影，白板重绘依赖该参数的图形。

所有滑块共有的主要瓶颈是白板的重复尺寸测量。旧实现每次更新都先按固有宽度排版，再按最终列宽测量，最多额外三轮；测量缓存的宽度和约束标记反复切换。即使只有一个曲线参数改变，不相关数学卡片也可能触发布局测量和同步浏览器排版。在电视当前二维课中，变量更新调用中位数约 11ms，而白板 render 中位数约 161ms。

二维图卡每次参数改变还会替换整个内容，重新创建工具栏、坐标轴、网格和 SVG。三维图卡使用 JavaScript 投影、按深度排序，再绘制 SVG 图元，并非 WebGL 网格渲染；旧实现每次截面改变都重建整个 SVG。虽然用于截面计算的网格已有缓存，曲面可视绘制却独立重复求值、投影和排序，因此静止曲面仍付出大量重复开销。

## 实现

通用渲染器源码位于 OLL 仓库分支 `codex/slider-live-performance`，修改 `packages/web-runtime/src/board-view.ts`、`scene3d.ts`、`plot-explorer.ts`。本报告附有 [TypeScript 源码差异](oll-renderer-source.patch)。产品的固定依赖仍为 `7009c4b456ac0d7d4a6bd96b20ca83816b18bb62`，通过 `patches/octos-lesson-language@0.1.0-rc.1.patch` 和 `pnpm-workspace.yaml` 应用可复现补丁。没有直接修改 node_modules，没有推送远端或部署公网。

1. **白板布局复用**：用当前测量结果检查候选布局，先在当前最终宽度更新图卡；语义尺寸、实际尺寸和布局都不变时复用布局。尺寸或位置确实变化、字体测量失效、新操作需要教学镜头时回到完整布局。恢复最终卡片位置/尺寸，避免数学卡片临时自然宽度泄漏。
2. **二维增量更新**：保留工具栏、图内手势容器和探索状态。坐标范围与尺寸不变时保留 SVG、坐标轴、网格、裁切区域；只更新动态曲线、标记和说明。坐标轴定义或曲线结构变化时正常重建。轮滚事件使用单一处理器，避免保留 SVG 后叠加监听。
3. **三维分层更新**：保留 SVG、控制按钮及指针捕获，把原有绘制顺序保持为静态物体/坐标轴、截面、强调层。截面改变只更新截面和交线；相机、物体或表达式实际依赖的变量变化时使对应层失效。
4. **三维曲面复用网格**：可视曲面的四边形直接读取缓存网格，共享相邻顶点，避免每个网格单元四次重复表达式求值。一次视角更新每个共享顶点只投影一次；曲面分辨率、四边形结构、深度排序和颜色保持不变。仅截面更新时不再重复曲面投影和 fit 边界扫描。

未改模型调用、课程生成路径、课程内容、变量最终提交、学生操作日志或持久化策略。

## 电视二维实测

M3G2，Android 13，WebView 101，物理 3840×2160，CSS 960×540，DPR 4。保持原有显示配置；没有启动 scrcpy。

当前二维学习记录含 4 张卡片和 64 项笔迹。按 rAF 提交相同的 20 个斜率数值，随后恢复原值；每组实际出现 11 次白板 render。三版都启用相同 CDP CPU profiler。以下是程序驱动完整 Runtime 的参数更新，**不是手指触屏滑块帧率验收**。

| 版本 | 白板 render 中位数 | 最长 render | rAF 间隔中位数（去掉首帧） |
|---|---:|---:|---:|
| 上一阶段原版 | 160.7ms | 398.5ms | 189.7ms |
| 仅布局/三维优化候选 | 88.9ms | 279.7ms | 121.1ms |
| 加二维增量更新，最终版 | 70.4ms | 98.1ms | 102.8ms |
| 最终版复测 | 62.5ms | 168.7ms | 86.0ms |

中位数相对原版减少约 **56–61%**。仍存在长帧；不能承诺稳定 30 或 60 FPS，也不能把 render 耗时直接换算成完整课程帧率。具体原始数组及汇总见 [metrics.json](metrics.json)、[原版](slider-baseline.json)、[最终版](slider-final.json)、[复测](slider-final-repeat.json)。
