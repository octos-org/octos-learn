# 新增课程上下文的首段速度对照（2026-10-28）

用户 2026-10-28 授权：约 10 对交错课程，预计 0.30–0.50 美元。规则见 AGENTS.md 第 1 条：任何合入不得回退首个可播放片段的生成速度（p50 对照交错基线，零新增模型往返）。

## 测了什么

- **两个前端**：基线 main `0561a0a`；候选 `codex/teacher-experiences` `111cead`（含 #100 老师记得白板上的课，和 #102 老师偶尔提起自己的经历）。两份生产构建交替运行，每个样本用新的浏览器上下文和新白板。
- **后端**：同一个隔离 Octos（本机 `octos` main）和 Learning Coach `codex/teacher-experiences` `2a64a92`（0.19.0，含两轮审查修复），gemini-3.8-flash，测试 Key，所有请求经预算网关。基线前端不发送新字段，Learning Coach 对它使用与以前完全相同的提示词，所以基线就是改动前的行为。没有配置语音，也没有 Jev 预判（隔离环境里预判直接放行）。
- **样本**（18 个，9 对，每对内两版先后顺序交替）：
  - 6 对单节课（一次函数、配方法、估算商各 2 对）。候选事先设为“这节课该提供经历”，请求里多带 12 条老师经历（431 字）。
  - 3 对追问：先在同一块白板上生成并播完一节“估算商”的课（不计时），再问“如果除数是 23 这种不接近整百的数，该怎么估？”。候选请求里多带 `current_lesson`。
- **指标**：
  - `visual_ms`：从提交问题到本节课第一个课程画面可见、播放控件可用（与 2026-10-26 的对照相同），只用于单节课样本。
  - `prefix_ms`：Learning Coach 从开始执行到发布第一段可播放内容（生成记录里的 `lesson-plan-prefix-published`），所有样本都有。追问样本只用这一项：同一块白板上，新课要等前一节课播放结束才显示，画面时间测到的是等待时间，不是生成时间。
- **执行器**：`scripts/benchmark-playable-isolated.mjs`。本次新增：样本可预设本地存储（`storage`）和不计时的第一问（`warmup`）；网关记录每次响应的实际 token 并计算实际费用；`--max-actual-usd` 达到上限即停止。执行单 [CONTEXT_SPEED_PLAN.json](CONTEXT_SPEED_PLAN.json)，原始结果 [CONTEXT_SPEED_RESULT.json](CONTEXT_SPEED_RESULT.json)。

## 结论

- **未发现回退**：两项 p50 候选都不高于基线，没有新增模型往返，满足 AGENTS.md 第 1 条。
- **候选更快不代表改动让课变快**：差异主要来自模型本身的波动（同一题同一版本差 10 秒以上；用 1、2 还是 3 次请求差别很大）。这个测试能说明“没有变慢”，不能说明“变快了”。
- **没有覆盖**：
  - **追问的上下文很小**：三节追问的 `current_lesson` 只有 71–73 字，因为第一节课没有课后思考题和练习。这个测试没有覆盖接近 1800 字上限的情况；按以前的生成记录，提示词多几百 token 时看不出时间差异，但这里没有直接测到。
  - **Jev 预判**：隔离环境没有 Jev，预判多带上下文的影响没有测。
  - **其他**：语音、本人账号、电视设备。

## 冒烟测试中发现的问题（执行器，已修复）

- 第一版网关的用量解析遇到嵌套对象时读不到 token，实际费用记为 0。
- 追问样本按画面计时会一直等，原因是新课要等前一节课播完才显示，所以追问改为按生成时间计。
