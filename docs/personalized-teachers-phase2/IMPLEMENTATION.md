## 已实现的基础

1. 产品服务保存原始学习记录，长期记忆仍统一由 Octos 处理。没有新增模型调用，没有让 Learning Coach 整理记忆。
2. 服务通过 Octos `/api/my/profile` 确认当前认证对应的账号，不接受客户端指定记录归属。沿用原来的 50081 产品进程；正常 Vite 开发入口、生产启动文件和部署模板均已接入新模块。
3. SQLite 使用事务保存记录、重复提交回执和变更顺序。同编号同内容返回已存在；不同内容返回冲突。不同账号相同编号互不影响。问题、回应、课程的所属问题和学习编号不能被悄悄更改。
4. 学习列表、一次学习的原始记录及增量变更支持分页。查询固定本次收到的记录范围；期间删除会要求重新查询，避免在已删除内容上继续提供不完整的旧快照。
5. 删除移除正文并保留必要的内容无关编号，旧设备继续上传同一遍学习的新旧子记录都不能让它复活。此操作没有删除 Octos 会话或长期记忆。
6. 在线备份包含 SQLite WAL 中已经提交的内容，且拒绝覆盖已有文件；已用恢复后的数据库验证普通记录、删除记录和拒绝旧设备补传的行为。
7. 播放实验使用真实 OLL Runtime，确认最后位置不能证明实际播放。采集器只认可同一播放过程内连续通过的片段；查看、跳转、恢复和失败旁白不能冒充成功播放。该采集器尚未接入真实课堂。

## 记录的含义

- `question_submitted` 保存实际问题；生成成功与失败不改变学生曾提问的事实。
- `answer_delivered` 保存实际交付的文字分段，分段稳定绑定原问题。此字段本身不代表已经交付 Octos。
- `course_delivered` 区分部分交付与完整交付；生成完成不等于学完。
- `run_started` 只说明明确启动过，列表字段也叫 `start_recorded`，不把它直接称为“学过一次”。计数仍需要实际播放或练习依据。
- `playback_position` 记录位置及原因；`beat_completed` 单独记录有依据的播放片段；`narration_ended` 区分正常结束、关闭、失败及取消。
- `task_attempt` 与 `task_hint` 独立记录作答及提示。一次作答由学习编号、持久日志编号、题目和操作编号共同识别。
- 每条记录带设备、原发生时间、会话及学习编号。服务端接收顺序另存，不用设备时间安排同步顺序。
- 第一版不接受“已掌握”或凭标题猜出的知识点。知识点课程对应表未通过教学审阅前不参与正式统计。

事件契约限制单批 100 条、单个文字 64 KiB；HTTP 请求体上限 1 MiB。身份由服务端确定，客户端事件中没有账号字段。错误返回不包含正文、文件路径或数据库细节。

## 已完成的验证及边界

- 服务端：`node --test services/learning-history/*.test.mjs services/product-server.test.mjs services/byok/server.test.mjs`，33 项通过。包括重启后重试、错账号、乱序回应、删除后未知子记录、分页中删除、SQL 故障回滚、写锁繁忙、备份恢复及既有 BYOK 回归。
- 全部前端单测：128 个文件 / 1183 项通过，包含 5 项新增播放验证。此结果早于后续设备队列变更，不能代替设备接入后的回归。
- 当时的 TypeScript、完整 ESLint 和构建通过；ESLint 有 37 项已有警告，构建有已有的大分块提示。
- 本机合成测量：10,000 条记录、1,000 遍学习；写入总计约 449 ms，21 次列表查询 p50 约 4.43 ms、最大约 4.92 ms。持有写锁时约 0.095 ms 返回繁忙。脚本见[测量脚本](../../scripts/benchmark-learning-history.mjs)。SQLite 不阻塞等待写锁，客户端保留原编号重试。
- 测量使用本机 Node 24.16.0 / SQLite 3.53.0，不能作为生产容量或课程首片段速度结论。公网只读核对 Node 22.23.2 支持 `node:sqlite` 和在线备份，没有变更服务或访问学习正文。
- 没有部署、切换运行服务、调用付费模型或往本人真实记忆写入测试材料。
