# 真实首段播放测试：脚本已准备，付费测试尚未开始

更新：2026-10-21。对应总清单 N-01 至 N-04、第二阶段 P2-08。本轮完成计时和费用控制脚本，并用免费替身验证；**没有新增真实模型或语音调用，也没有得出新的速度结论。**

## 现在能做什么

`scripts/benchmark-learning-history-live.mjs` 从完整前端的正常提问入口提交课程，交替使用基线和候选构建。它记录本次课程画面真正出现、对应第一段旁白真正开始的时间，而不是把“收到课程文件”当成可播放。

画面必须属于本次生成的课程，音频必须与这次收到的第一段语音字节相符，并且浏览器确实渲染出了非零声音信号。旧课程画面、其他声音、静音和语音失败都不能通过。这仍然是浏览器里的声音渲染检查，不代表验收了电视扬声器。

拿到首段计时后，脚本还会等待课程后台任务结束，读取实际模型请求与重试记录，并与费用检查处登记的请求数核对。一堂课未结束，不能提交下一堂；发生失败则停止，保留资料，不能自动重试整堂课。真实生成的课程文件保留，不自动删除。

## 怎样限制测试调用

这是本仓库的验收工具，不是产品新功能，也不改动 Octos 或 Learning Coach。模型请求通过一个只在测试时使用的本机转发进程：

1. 每堂课提交前，先在本机 SQLite 登记试验编号、顺序和课程会话。登记未完成就不发送课程请求。
2. 每次模型 HTTP 请求，包括技能自己的重试，发送前先占用一份费用额度。额度不足就拒绝发送。流式响应仍逐段转发，不等整份响应完成。
3. 只允许实际首段旁白的一次语音请求。检查文字、音色、资源和音频格式；后续预取、失败后的重复请求也不会继续调用供应商。
4. 请求失败、中断或回执丢失都不退还试验额度，因为无法据此证明没有产生费用。脚本重启后保留原登记；正式执行目录也固定在批准的执行单里；不能换个目录绕过原登记重跑。

这里的“占用额度”是程序先按审核过的最大费用扣留一笔可用预算，**不是供应商账单**。只有单次最大费用的依据可信，总额限制才可信。美元模型费用和人民币语音费用分别限制，不靠未经核对的汇率混算。并发争用数据库时宁可停止，也不先发请求再补记。

模型转发只允许指定 Google 模型、文字输入和已检查的生成选项，限制请求字节数和输出上限，不允许图片、工具等尚未核价的能力。语音仍走现有本人 BYOK 转发。完整前端中，测试产生的学习事实上传返回失败，留在一次性浏览器上下文，避免把合成测试记录交给个人长期记忆；产品页面本身仍正常运行记录代码。
