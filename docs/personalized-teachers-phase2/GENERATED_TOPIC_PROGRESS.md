## 本轮新增的运行代码

之前 `recordDeliveredLesson` 已序列化当次收到的 Canonical events，并计算 SHA-256，但写入事实后只留下指纹。服务端无法仅凭指纹恢复实际旁白、公式和画面操作，也不能用后来同路径的文件代替早先内容。

现在保留这份**当时的原始 JSON 字符串**：

1. 记录器在后台写入时，将课程字节与对应 `course_delivered` 事实放进同一笔 IndexedDB 事务。课程交付调用点复用原来已经生成的 JSON 字符串，没有让生成流程等待上传；后台上传编码和持久保存更大的材料仍有实际开销，不声称完全免费。
2. 课堂空闲时，现有同步请求把事实和材料一起上传。两者在同一笔服务端 SQLite 事务中保存；材料保存失败不会先确认本次新事实。
3. 服务端检查课程交付事件、原字符串 SHA-256、事件数量及基本结构。检查通过只证明材料与记录一致，不证明数学或知识点归属正确。
4. 本人可从 `GET /api/learn/history/materials/{交付事件编号}` 取回原始字节。账号由 Octos 认证确定，其他账号拿同一编号也读不到。
5. 删除一遍学习或整个课堂时，同时删除相关课程材料；旧离线请求重发不能恢复已删除内容。现有 SQLite 备份也包含材料。

普通事实批次仍以 768 KiB 为目标。单份较大课程材料可独立占一批，完整请求上限 8 MiB；HTTP 处理器和 Nginx 示例一致。超过上限的材料及其交付事实保留在本机，报告同步未完成；其他普通问题和播放事实仍继续上传，不被这一条卡住。目前没有分块上传，不声称支持任意大小课程。

旧客户端仍可只上传事实。旧历史没有保存的材料不会凭空补出；只有重新取得**完全相同且指纹一致**的交付内容时，才能补齐。新客户端应与新版产品服务配套使用。服务端学习库格式从 3 升至 4；旧服务会拒绝读取新格式。旧前端也不认识待传记录中的新增材料字段，回退后可能上传事实却移除未传材料，不能声称前端可无损降级。正式发布前必须保存升级前备份并安排回退，本轮未升级正常数据库、电视或公网。

## 已经证明可以复用的 Octos 入口

核对的源码仍为 `413b4b68`，本轮没有修改上游。使用 Octos 现有的应用专属分析对话：

1. `peer/prepare` 准备分析角色及独立的工作目录、记忆范围。这里的“角色”只是一次应用服务的分析身份，与面向学生的老师名单无关。
2. `peer/tools/register` 将可用工具收窄。此次入口验证不授予通用文件、命令或网络工具，只把产品已经读取的材料放进请求。
3. 在该对话中使用 `turn/start`，明确标为 `origin.kind = app`。分析指令由应用发出，不能塞进学生原问题里冒充学生发言。
4. Octos 自己调用该账号的模型，应用通过核心 `session/hydrate` 读回输出。此次验证使用本地模型替身；正常产品模型仍归 Octos 管理，产品不新增供应商客户端。

因此，**目前没有证据表明必须修改 Octos，才能发起这类分析**。先前“验证分析 skill”的目标可以先由该应用发起入口落实；这里并未安装 skill，也不把直接调用后台 skill action 误称为已经调用智能体。分析规则、目录检索和结果检查的正式封装仍需实现。

验证脚本：[verify-learning-topic-octos.mjs](../../scripts/verify-learning-topic-octos.mjs)。它在临时目录启动真实 Octos，创建合成账号，从实际产品 SQLite 读出课程原文与指纹并交给 Octos；模型替身返回预设结果，应用读回并核对 JSON 一致后，确认原课堂对话仍为空。最终验证运行只有一次替身模型调用；预检和验证均没有真实供应商调用，报告中的次数只对应最终运行。合成知识点不属于正式 taxonomy，不能据此宣布归属准确或统计完成。

结果见[结构化证据](GENERATED_TOPIC_EVIDENCE.json)。早期预检纠正了脚本的 UUID、文本数组、临时 profile 模型配置及查询入口；没有据此修改 Octos。当前二进制的辅助消息分页入口在该 fixture 中不可用，最终使用其可用的核心 hydrate 读取，未将所有消息查询能力统称为可用。

## 下一段开发的明确边界

下一段直接做“知识目录 → Octos 分析 → 对应结果保存”，随后接入计数，不再为入口验证扩建工具：

- 固定已有 taxonomy 版本 `533bab591b24c4024f0d70f9296aa4ee560fdd01`；目录作为外部资料供查阅，不放进每个学生的长期记忆。检索出的编号存在，不等于归属正确。
- 原问题与每段实际内容分别判断。例如问题问斜率、课程补讲截距，不能把截距也算成学生问过一次；“还是不懂”缺少明确前文时应保留未知，不能借课程标签倒推。
- 每项结果绑定原问题或交付事件、内容指纹、片段编号、taxonomy 版本、分析规则版本及原文依据；不接受模型自行声明“学生已掌握”。
- 流式课程先后版本分别保存；最终完整版的标签不能直接套到较早播放记录。现有生成课播放事实尚未明确保存交付版本绑定，这一点必须在接入精确片段计数时补上。
- 产品仅机械保存与汇总结果，不做第二次语义判断。未知、没有对应结果和明确零次分别表达；纠正对应关系时重算，不改原始事实。
- 任务派发、重启后补做、本人授权、课堂忙时延后和费用限制尚未接通。入口证明可用不等于已经有自动队列；没有这些约束前不自动发起真实分析，也不假定记忆刷新额度会覆盖它。
