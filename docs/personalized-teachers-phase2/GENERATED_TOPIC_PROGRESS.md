## 本轮新增的运行代码

之前 `recordDeliveredLesson` 已序列化当次收到的 Canonical events，并计算 SHA-256，但写入事实后只留下指纹。服务端无法仅凭指纹恢复实际旁白、公式和画面操作，也不能用后来同路径的文件代替早先内容。

现在保留这份**当时的原始 JSON 字符串**：

1. 记录器在后台写入时，将课程字节与对应 `course_delivered` 事实放进同一笔 IndexedDB 事务。课程交付调用点复用原来已经生成的 JSON 字符串，没有让生成流程等待上传；后台上传编码和持久保存更大的材料仍有实际开销，不声称完全免费。
2. 课堂空闲时，现有同步请求把事实和材料一起上传。两者在同一笔服务端 SQLite 事务中保存；材料保存失败不会先确认本次新事实。
3. 服务端检查课程交付事件、原字符串 SHA-256、事件数量及基本结构。检查通过只证明材料与记录一致，不证明数学或知识点归属正确。
4. 本人可从 `GET /api/learn/history/materials/{交付事件编号}` 取回原始字节。账号由 Octos 认证确定，其他账号拿同一编号也读不到。
5. 删除一遍学习或整个课堂时，同时删除相关课程材料；旧离线请求重发不能恢复已删除内容。现有 SQLite 备份也包含材料。

普通事实批次仍以 768 KiB 为目标。单份较大课程材料可独立占一批，完整请求上限 8 MiB；HTTP 处理器和 Nginx 示例一致。超过上限的材料及其交付事实保留在本机，报告同步未完成；其他普通问题和播放事实仍继续上传，不被这一条卡住。目前没有分块上传，不声称支持任意大小课程。

旧客户端仍可只上传事实。旧历史没有保存的材料不会凭空补出；只有重新取得**完全相同且指纹一致**的交付内容时，才能补齐。新客户端应与新版产品服务配套使用。材料提交将学习库格式从 3 升至 4，本轮加入分析结果及播放版本索引后升至 5；旧服务会拒绝读取新格式。旧前端也不认识待传记录中的新增材料字段，回退后可能上传事实却移除未传材料，不能声称前端可无损降级。正式发布前必须保存升级前备份并安排回退，本轮未升级正常数据库、电视或公网。

## 已接通的正式分析链路

学生继续使用原有提问和课程播放入口。以下流程只在应用打开且课堂空闲时运行，不在开始讲课前增加模型请求：

1. **登记待分析的材料。** 产品接收原问题或带原文的课程交付时，在保存事实的同一笔事务中登记待办。这里只登记编号，不理解内容，不调用模型。旧记录可以通过显式的分页补登记接口加入；没有原文的旧课程不能补出材料。
2. **先检查是否允许执行。** 每个账号默认关闭。启用必须明确设置每日任务数（1 至 20），一次只领一项；已经开始但结果不明的任务，只找回原执行，不自动另调模型。停用阻止新任务，已完成或已删除来源的临时资料仍可清理。
3. **让 Octos 查目录并判断。** 使用独立、一次性的分析对话，标为应用请求。Octos 使用自己管理的该账号模型；仅开放 `learning_topics.search` 只读目录工具，不提供通用文件、命令、网络或记忆写入工具。应用没有供应商模型客户端。
4. **分别给问题与讲解找依据。** 问题输入不包含生成课标签。课程按实际交付片段分析，并提供完整交付事件供理解公式及画面定义。目录是固定版本的外部参考资料，不塞入每个学生的长期记忆。模型根据英文概念查询目录；检索本身只是词面匹配，不在产品里另做语义分类。
5. **核对后再保存。** 每项结果必须对应原输入指纹和全部单位，引用真实目录编号及同一单位的原文片段。多余的“掌握”“置信度”等字段、捏造编号、错版本、缺单位或捏造引文均拒绝。检查通过证明来源和格式一致；语义是否判断正确仍要单独验收。
6. **把结果与真实行为对上。** 原问题对应的知识点只增加该知识点的提问记录。讲解对应的知识点须同时存在同一课堂、课程、问题、片段和交付指纹的实际播放完成事实，才增加播放计数。每个片段开始时固定其材料版本，不能把后来补写的完整版标签套在旧播放记录上。同一遍回放同一版本片段去重。
7. **允许查依据和纠正。** 查询返回准确归属部分的计数，同时列出尚未分析、无法确定及没有版本对应的记录。没有足够依据时返回“尚不能确定”，不伪装成零次。显式重分析保留旧结果及原始事实，新结果完成后才改变后续查询；分页固定事实和分析各自的截至编号，防止翻页时结果悄悄改变。

目录来源为 os-taxonomy `533bab591b24c4024f0d70f9296aa4ee560fdd01` 的 Mathematics 节点。重新下载固定提交的 `data/topics.json`，原始 SHA-256 与先前资料一致；实际文件为 1616 个节点、其中数学 529 个，按原文件计算，不使用 README 可能不同步的数量表。保存的裁剪数据只包含编号、领域、名字、描述、判断依据与年龄范围，原文不改；另存原始/裁剪指纹及 [NOTICE](../../services/learning-history/taxonomy/NOTICE.txt)。数据集合为 ODbL 1.0，原作者文字为 CC BY-SA 4.0，不包含课程标准正文或教学研究全文；它们的声明只针对目录资料，不修改应用代码许可。见[固定版本的上游说明](https://github.com/withmarbleapp/os-taxonomy/blob/533bab591b24c4024f0d70f9296aa4ee560fdd01/README.md#license)。

## 断线、删除、权限和费用怎样处理

**先保存执行编号，再请求 Octos 开始。** 丢掉开始或结果回执时，只重新读取原对话；不会因“没收到回复”再开一次可能收费的执行。结果已保存但回执丢失时，另一个同账号客户端可以接手清理，模型请求不增加。结果不明时保留未知；需要重新做一次，须显式请求重分析，仍占新的每日额度。额度在开始前预留，即使未成功发出也不自动退还，宁可少运行，也不低估调用。

**清理权限不会只留在第一台设备。** Octos 返回的应用分析连接授权，保存在产品服务学习目录旁的 `analysis-host-controls/<本人账号>/` 私有文件中。目录 0700、文件 0600，只经 Octos 本人认证读写，拒绝跨账号路径和文件替换；它不是模型 Key，不读取或复制用户模型/语音凭据，也不写入 SQLite 学习事实、课程、浏览器存储或日志。现有产品服务的学习目录写权限即可容纳，Octos 配置目录仍保持只读。

删掉原学习记录时，原文、对应结果、统计依据和待办一同删除；连接授权暂留，供在线的本人客户端清理 Octos 临时分析空间，清理成功后才移除授权文件。应用全部关闭时不会有人执行这一步，重新打开后继续，不声称已经立刻清除所有临时副本。**保护性运行备份须同时包含学习 SQLite 及 `analysis-host-controls`，授权文件不得放进公开交付包。** 单独复制数据库不是完整的分析恢复备份。原始课堂问答和 Octos 既有长期记忆的删除仍按原有规则分别处理。

**课堂开始时停止继续分析。** 执行器在准备、工具查询和轮询时检查课堂状态及捕获的账号，打断自己的分析执行；已经发出的供应商请求可能仍计费。当前连接最终关闭，原始记录继续在本机保存。关闭网页后不保证运行，服务端待办保留，重新打开时续做。这是复用现有空闲维护，不是新增全天候定时服务。

每日任务上限、最多 8 次目录工具调用和单任务约 120 秒等待，限制的是启动任务及工具循环。**它们不是美元硬上限，也不保证一次任务只有一次供应商请求**：工具交互和 Octos 自身重试可能带来多个请求。正常账号仍默认关闭，没有借记忆刷新额度，也没有改变账号模型路由。真实模型质量试验必须另定有限范围和费用约束；本轮只用本地替身。

## 当前明确的限制

- 图片、选区图像的真实字节还没有送给分析模型；必须看图的问题保留未知。语音转成可用文字后可按文字处理。
- “还是不懂”等追问没有明确前文时保留未知，不拿后续生成内容反推所问知识点。原问题与生成课是分开的输入。
- 单份分析最多 100 个单位、256 KiB 输入，超过时不截断、不调用模型，保留待核对状态。流式交付的不同版本各有待办，可能重复分析部分相同内容并占额度；尚未做跨版本分析复用。
- 旧播放记录没有交付指纹时不能准确挂上生成课知识点。原始作答和提示仍保存，但本轮没有实现生成课练习题的自动知识点归属，不能宣称已有自动知识点作答统计或掌握度。
- 结果的编号和引文正确，不证明语义正确；真实质量、图片支持、实际账号启用、新 APK 和公网验收均未完成；独立代码审查及修复复核已完成。预制课人工对应表仍停用，不因自动分析可用而冒称人工审核通过。
- 分析连接的授权在 Octos 返回后、产品持久保存前若进程崩溃，可能留下没有保存授权的临时空间；现有流程不能承诺原子创建及清理这两端资料。没有为这个窄故障修改上游或建立第二套通用清理系统。
