### 本轮审查发现与处理

独立子 agent 只读审查 `11f5b7c..51f78fe`，作者逐项核实：

1. **已确认缺陷（已修复）**：Runtime 在 `useMemo` 渲染期间 `bind()`，历史绑定却在之后的 layout effect 才更新；交付快照缓存又在父组件 effect 才填。结果：课程修订导致 lesson.open 变化、Runtime 重建时，练习被固定到**上一个**交付版本（错误归属到旧版本的分析结果）；课堂中新到的课程练习则得不到来源（永久未知）。新 hook 级测试在修复前确实得到旧版本指纹而失败。修复：`bind(session, history)` 使用同一次渲染的绑定；工作区同步取得快照（`historySnapshotOf`）。
2. **已确认（已修复）**：旧规则下从未启动的 pending 任务永远不可领取，但 status 仍报 pending，开启分析的账号会永远显示待处理并每 5 分钟重试。现在 status 与领取条件完全互补，不可领取者报 `superseded`（含目录版本不同的情形）。
3. **已修复**：提示没有覆盖统计，无可靠依据的旧提示被静默略去。现报告 generated/analyzed/associated/unassociated_task_hints，计入 partial，界面同时披露。
4. **复核后补强（已修复）**：课程题头先到、尚无步骤时 Runtime 已绑定但无对应 topic，后续无重建，练习一直未知。现在首次作答时用当时绑定固定来源；任何 task 定义变化都会改变 lesson.open 并重建，所以未重建前当时绑定描述的就是 Runtime 正在使用的定义。

**未修改、留作待定**（不是已确认缺陷）：
- 规则升级后 v1 结果不再计入统计，既有材料不会自动用 v2 重新分析（只有 `seed` 接口，产品无调用）。自动重新分析会花用户本人模型费用，属产品/费用决定，需要用户确认。
- 旧规则已有 execution 但 turn 丢失时会反复领取→uncertain，结果不会计入；与 v2 现有行为相同。
- 提示仅按事件 ID 去重（未验证能否重复出现）；outside-catalog 练习计为未对应（与片段语义一致）；task quote 可引用 JSON 键名等弱证据（与片段相同）；总数与匹配的课程类别过滤口径不同（当前不可能发生）。
- 课程包与生成课同时存在、某生成课 turn ID 无法解析时，`forTask` 回退到课程包上下文，其练习可能记到课程包名下（修改前已存在，未验证能否发生；`forStep` 同样回退）。
- StrictMode / 被丢弃的渲染中 `bind` 是 useMemo 副作用（修复前已存在，开发模式影响）。
- 部署瞬间已持有旧规则租约的客户端仍可启动一次 v1 调用，结果不计入。
