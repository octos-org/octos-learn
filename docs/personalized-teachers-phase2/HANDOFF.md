## 已做成什么，新代码如何工作

`11f5b7c` 从当前学习实例内最新的完整、可读、单一 open/close 课程快照推导必需片段，使用累计前缀指纹；缺材料、不完整或歧义时未知。整课播放完不代表练习完成或掌握。

`51f78fe` 把 lesson.open 中每道原始 task 及变量上下文加入同一次 Octos 分析，规则升级为 `separate-question-beat-and-task-units-v2`，单位 ID 为 JSON `["task", 原始别名]`。作答/提示保存 source_task_id、delivery_sha256，查询只匹配本人/会话/课程/问题/实际版本/原 task。尝试、程序判定成功、提示分别去重计数，成功不冒充掌握。没有数据库迁移，仍是格式 5。

### 本轮审查发现与处理

独立子 agent 只读审查 `11f5b7c..51f78fe`，作者逐项核实：

1. **已确认缺陷（已修复）**：Runtime 在 `useMemo` 渲染期间 `bind()`，历史绑定却在之后的 layout effect 才更新；交付快照缓存又在父组件 effect 才填。结果：课程修订导致 lesson.open 变化、Runtime 重建时，练习被固定到**上一个**交付版本（错误归属到旧版本的分析结果）；课堂中新到的课程练习则得不到来源（永久未知）。新 hook 级测试在修复前确实得到旧版本指纹而失败。修复：`bind(session, history)` 使用同一次渲染的绑定；工作区同步取得快照（`historySnapshotOf`）。
