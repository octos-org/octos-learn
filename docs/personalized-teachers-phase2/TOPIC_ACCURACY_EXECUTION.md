## 测哪些内容

[固定材料](TOPIC_ACCURACY_CASES.json)为 6 个学生问题、1 份含两个片段的课程，以及另一份课程的先后两版，共 9 个分析输入。样例原文、判断标准与允许的相邻节点已经固定，原文及代码散列保存在[机器执行单](TOPIC_ACCURACY_TRIAL.json)，模型看不到预期答案。

| 要检查什么 | 样例与判定 |
|---|---|
| 中文问题是否找到实际目录范围 | 斜率方向、两点斜率、三角形缺角；不要求只认某一个相邻年龄段编号，但不接受没有依据的额外主题 |
| 不明白时是否诚实 | “还是不懂”没有前文、图片缺少图像字节，必须保持未知 |
| 非数学请求是否被硬塞入目录 | “声音太小怎么调大”不能变成一次数学知识点提问 |
| 原问题和补讲是否被混为一谈 | 斜率讲解、额外补讲纵截距分别有原文；第二片段只交付未播放，不增加播放次数 |
| 后来的课程是否改写过去 | 同一片段编号先后讲斜率和截距，只播放早先版本；统计必须引用早先交付的分析结果和引文 |

**当前目录的 Linear Function Graphs 同时覆盖斜率和截距。** 两段分析可能正确地得到相同知识点编号，不能凭“编号相同”就声称模型混淆，或凭“编号不同”才算通过。必须看每段原文依据和实际播放版本。首轮没有假装建立更细的斜率/截距子节点，也没有证明学生掌握。

每份模型输出都经过已有产品检查。原工具没有保留被拒收的首份原文；收尾已免费补齐终态原文留存，详见实际结果。自动对照只提示明显偏离预设范围的结果；最终的引文是否支持语义归属由人逐项核对，报告不会自动写“语义通过”。格式拒收虽然阻止了错误计数，仍记为模型没有成功完成该份任务。少量全通过也只支持这组样例，不代表任意问题都准确；真实学生长期使用、图片理解和新设备仍是后续验收。

## 费用为何能被限制

2026-10-22 重新核对 Google 官方 [Gemini 3.8 Flash 标准价格](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.8-flash)：截至 2026-12-31，每百万输入 token 0.75 美元，输出（含思考）3.75 美元。[模型容量](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)为 1,048,576 输入、65,536 输出。整次请求即使用满容量，模型 token 使用费为：

`(1,048,576 × 0.75 + 65,536 × 3.75) ÷ 1,000,000 = 1.032192 美元`

每个请求发送前保守预留 **1.10 美元**，18 次共 **19.80 美元**，低于 20 美元上限。实际内容很短，通常不会用满容量；这里不承诺账单预计值，也不靠假定输出很少来压低上限。执行器另限制请求大小 1 MiB、输出配置最多 32768 token，但没有借更小输出降低预留。

本机拦截只允许固定 Google 标准生成地址、文字和 `learning_topics_search` 目录函数调用/返回；拒绝图片、音频、远程媒体、搜索 grounding、文件搜索、代码执行、显式缓存和其他附加请求特性。正常课堂、后台刷新等没有这份固定 app 输入的流量也会拒绝；只有与当前样例内容指纹一致的分析请求可以通过。Octos 的内部重试同样经过检查，每次实际尝试都新预留一次，失败、超时和缺少回执不退还。

请求及额度写入保护目录中的 SQLite，重启不能清零，策略散列不同不能重用同一额度。实际执行目录固定；脚本拒绝在已有目录重新开始。转发只保留供应商所需 Key，不转发 Octos 登录凭据、Cookie 或任意目标；Key 不进入报告、日志或 Git。产品本身不导入这套试验工具，也没有新增模型客户端。

1. 将本轮人类授权记录到机器单；执行当天重新核价，确认同一模型、没有备用模型。固定使用机器单所指的已审查 Octos 二进制；该版本正常 profile bootstrap 将 embedding 固定为 None，仅使用内置本地 embedding 或关键词检索，不回退远程服务。profile API 目前不返回实际 embedding，因此脚本的额外字段检查不能单独证明它的路由；启动方式和已固定的上游版本也必须核对。检查固定材料和代码散列；准备本人原模型地址的受保护恢复记录，不输出 Key 或配置全文。
2. 使用正常本机 Octos `127.0.0.1:50080`、既有 `~/.octos` 的 alan0x。不另建人工账号、换后端端口、改技能或提供替代人工预览。此脚本是自动验收工具；用于保存合成试验来源和结果的临时学习库不会写入正式产品学习库，也不将试验问答交付给个人课堂。
3. 确认当前没有其他课程任务，并在本轮暂停人工使用；将该账号主模型地址临时改为 `http://127.0.0.1:50189/v1beta`，保留本人既有凭据字段，确认实际生效的路由与无 fallback。需要重启本机 Octos 时沿原启动方式及既有账号启动，不能借环境变量代替本人 Key。
4. 启动已经批准的执行器。它再次确认身份、模型及费用地址，逐项登记输入后再让 Octos 分析；正常账号的持续分析开关保持原样。专用 app 分析空间沿用产品的隔离与清理流程；输入来自保护目录内的临时学习库，结果也保存在那里。
5. 任一分析失败、预期范围明显不符或达到限制，停止提交后续样例，保留失败和费用记录。不自动重跑，不把换一个目录当成新的授权。
6. 正常结束或失败后，先核对本轮遗留的 app 连接及 Octos 执行状态。仍有活动任务就中断并确认终态；临时连接和授权文件清理成功后才按原记录恢复模型地址。若暂时无法确认任务已终止，**先保留被限制或不可达的费用地址，不恢复供应商直连**，避免后台重试绕过限制。不得把仅关闭浏览器或脚本当作所有后台任务已停止。
7. 只恢复此次改动的路由字段，保留用户期间其他修改。核对原模型、本人账号与正常服务；保存报告和原始输出，再作逐项人工语义审阅。不会因为脚本运行完成就开启全量后台分析。
