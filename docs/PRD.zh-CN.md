## 1. 产品目的与需求约定

OctosLearn 是无限白板上的 AI 辅导产品。学习者通过手写、语音、照片或文字提问，在自己的内容旁获得交互式微课。课程结合确定性的数学画面、手写体板书，以及语音或文字旁白。

星图学院通过个性化老师、知识地图、成就和报告，让真实记录的学习活动可见。当前目标是在保留学习核心速度、正确性和可恢复性的前提下，发布可靠的学院体验。

产品支持三个结果：帮助学习者理解眼前的问题；准确保留其活动记录；鼓励继续练习，而不把活动当作掌握的证明。

**需求用语与优先级。** “应”表示必须满足的行为。每个 OL 编号具有一项可独立判断的义务，字段列表描述同一输出或行为。全部核心需求属于第一阶段／P0；OL-069 和 OL-070 为条件性第一阶段／P1，仅在 D03 选择预制课老师音色时纳入。产品和发布负责人在发布清单中记录可选范围的最终取舍。

**验证。** T = 可执行测试；D = 观察演示；I = 检查；A = 测量分析。V-001 验证 OL-001，其余类推。即使多个检查共享一次测试运行，也分别记录结果。必要参数未解决时，相关验收检查被阻塞。写入需求不代表已经实现、验证或发布。

**发布相关决策。** D01–D12 标明需在第 9 节里程碑前记录的产品策略、环境选择和测量值。负责角色提供已批准的决策记录前，这些事项保持开放。列出待决策项不代表免除需求或授权发布。

**语言一致性。** 英文和中文版本共享需求编号、优先级、依赖和数值标准。含义存在差异时，须先同步修正两版，再验收相关需求。

## 2. 用户、需要与发布范围

产品面向小学至高中数学学习者，并逐步扩展到其他学科，同时服务使用课堂大屏展示课程的老师。第一阶段按一个 Octos profile 对应一名学习者组织记录，并区分课堂展示与个体学生评估。具体年龄／年级、语言、课程体系和账号边界由 D01 确认。

| 需要 | 用户结果／理由 | 流程 |
| --- | --- | --- |
| N01 | 利用实际已配置的能力开始或继续学习。 | U01 |
| N02 | 获得关联原问题、经过数学检查且相关的讲解。 | U02 |
| N03 | 在中断和多设备场景中恢复工作并获得准确记录。 | U03 |
| N04 | 理解真实记录的进展，获得不宣称掌握的鼓励。 | U04 |
| N05 | 控制个人数据，防止在共享设备上暴露。 | U05 |
| N06 | 使用本人凭据，并理解和约束可选费用。 | U01、U06 |
| N07 | 在明确支持的环境中使用响应及时、可访问的产品。 | 全部流程 |

| 流程 | 前提 → 操作 → 成功边界 |
| --- | --- |
| U01：首次使用 | 已登录 profile，可能无 Key → 打开白板／配置所选能力 → 不丢失问题地执行可用学习操作。 |
| U02：提问与学习 | 模型可用、输入获许可 → 提交文字／照片／笔迹／语音 → 与正确课程交互，或获得澄清／明确的部分失败。 |
| U03：继续与同步 | 已持久保存白板／轮次 → 重启、重连或继续 → 恢复已知内容，不重复计数、不虚报完成。 |
| U04：查看进展 | 有事件记录，也可能未映射或为空 → 打开星图／成就／报告 → 看到证据支持的事实含义与完整性。 |
| U05：管理隐私 | 已认证学习者或共享电视 → 查看／纠正／遗忘记忆或切换账号 → 执行所选范围和隔离。 |
| U06：管理费用 | 已配置可选后台使用 → 达到上限、关闭使用或供应商失败 → 保持学习访问，不使用未经授权的代付回退。 |

**第一阶段包含：** 学院大厅、老师选择、学习历史与记忆控制、星图、成就、周报／月报，以及文字／笔迹／照片／语音课程、持久化、BYOK 和受支持电视使用的回归。预制课老师音色由 D03 有条件纳入。

**第一阶段排除：** 任务、首领 HP、收藏品、考试、新学科、家庭子档案、班级名单和课程创作工作室。这些属于第 10 节的探索范围，不是第一阶段验收场景。已有保存／预制内容可播放，不意味着所有功能均离线可用。

**支持边界：** 目标环境为桌面浏览器和 Android 触屏电视。Android 8.0/API 26 是最低目标，尚非已验证覆盖。D02 列明具体浏览器／WebView／设备／输入／辅助技术组合，以及手机浏览器状态。仅经过测试的组合进入支持矩阵。完整高中映射不是已有承诺：六个未映射课程包包含三个三角函数和三个多元微积分课程包（REF-04）。

**产品约束：** 不从活动认证掌握；个人 Key 推理，不回退平台代付；内容放在学习者笔迹旁；不因断签扣除奖励。OLL 确定性执行不能证明模型理解或旁白正确；OL-053–OL-055 独立约束教学质量。

## 4. 术语与状态含义

| 术语 | 验收含义 |
| --- | --- |
| 学习轮次 | 一次明确的学习尝试；刷新／继续保留轮次身份。主动重新学习按 REF-01 创建另一轮。 |
| 事件身份 | 某个已观察动作的稳定身份，限定于账号／轮次／日志；网络重传不是新动作。 |
| 已交付／已播放／做出来过 | 内容已接收／真实播放证据／程序检查的任务成功。任何一项单独都不能证明掌握。 |
| 首个可播放片段 | 从明确提交到首个有效片段渲染完成且所需交互已启用的时间。旁白就绪单独测量。 |
| 额度日 | 账号级额度统计区间；时区、重置和失败尝试处理由 D06 决定。 |
| 已保存／已同步 | 分别由持久本地／服务端存储确认。待上传不等于已同步。 |
| 遗忘记忆 | 从后续记忆检索中移除选定存储记忆；不承诺源对话或备份已擦除。 |
| 受支持环境 | 已批准且经过测试的支持矩阵中的具体组合，不暗示支持整个操作系统系列。 |
| LAT95_MAX／RTO_MAX／RPO_MAX | 尚未赋值的 p95 延迟／恢复时长／丢失数据区间上限。D09／D10 必须确定单位、条件和数值。 |

**发布责任记录：** 产品负责人确认范围；工程负责人确认可行性与兼容性；质量负责人确认验证结果；隐私／安全负责人确认数据策略；发布负责人确认运行、监控及恢复准备。每项确认记录文档修订、证据链接和日期。

## 10. 后续阶段探索与依赖

**第二阶段进入条件：** 第一阶段已发布并评审，基线指标可用，D12 选择获批。任务需资格、到期、替换、离线和时区规则。建议首领表达练习进展；若暗示已证明理解，则在实施前提前引入答案验证证据。收藏品需获得、重复和撤回规则。月度考试继续延期。老师引用台词依赖小说章节定稿。

**第二阶段完成条件：** 新的本阶段需求和检查通过；结合质量、费用和中断评审参与度；产品负责人批准继续扩展。第一阶段 E 场景不测试或暗示第二阶段功能。

**第三阶段进入条件：** 选定下一学科和审核范围，固定 OLL／内容依赖。区分高中知识目录与多元微积分拓展。更新更强学习证据、更多老师、数学交互改进、白板交互和课程包缓存的范围与状态。课程工作室和更广课堂生态仍在这些阶段之外，除非明确新增。
