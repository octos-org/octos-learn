# 个性化老师与学习记忆：调整后的推进顺序

更新：2026-10-22。用户当天认可以下判断并要求按此推进：方向和架构正确，但投入过度集中在第二阶段的精确统计，学生真正能感受到的“老师有性格、老师记得我”尚未验证，也没有任何内容进入实际使用。本文件只调整**顺序与验证方式**，不删除[实施方案](PERSONALIZED_TEACHERS_AND_MEMORY_PLAN.md)和[全阶段 TODO](PERSONALIZED_TEACHERS_TODO.md)中的任何目标。

## 为什么调整

1. 第二阶段分支已有 100 余个提交，核心体验（第三、四阶段）尚未开始。数据管道越做越精确，却还不知道它能否让教学明显变好。
2. 老师第一版需要的是粗粒度事实（学过斜率、问过两次、练习做对了），最精确的知识点和练习归属真正必需是在第五阶段的地图与成就。
3. PR 仍是草稿，没有真实使用数据积累；后续所有阶段都依赖真实数据。
4. 每次规则升级都会让旧分析失效、需要用户再付费重跑，应在精度要求确定后再集中打磨。

## 新顺序

### A. 第二阶段收口：让可靠记录先合并、开始积累

- 合并内容：已实现并经独立审查的学习记录、离线队列、课堂采集、删除、核查界面、原问答交付、失败执行、整课汇总与练习归属代码。
- 知识点分析继续**默认关闭**，不作为本次已启用能力；task-v2 真实质量、旧材料重新分析、预制课对应表审核保留为第五阶段前的工作。
- 合并前门槛：首段可播放速度（AGENTS.md 硬门槛）。在当前提交重跑免费完整前端对照（见下文 D2），并由用户确认判定口径。
- 合并不等于发布：公网部署、APK 安装仍需另行授权。

### B. 最小纵向切片：第三、四阶段各取最小可验证部分

目标：在两三次连续课程里，验证“这位老师有可辨认的风格，并且记得我们以前怎么学”。

做什么：

1. **两位差异明显的预设老师**（设定卡 + 情境范例）放在 octos-learn 版本化配置；学生选择绑定到账号，一堂课提交时固定老师。
2. **老师设定进入课程生成**：三个课程入口（文字/语音、摄像头、选区）统一接收 `tutor_context`；Learning Coach 提示说明其用途和边界（不覆盖数学规则和学生本次要求）。不增加模型往返。
3. **记忆进入课程生成**：octos-learn 在课堂打开或空闲时预取 Octos 已有记忆（`memory/overview`，必要时 `memory/search`/`memory/load`）及粗粒度学习事实，作为 `learner_context` 传入；**不放在提交问题后的关键路径上**，读取失败或超时课程照常开始。
4. **明确的“以后……”要求**走 Octos 现有 `memory/request`，不新建记忆流程。
5. **老师身份进入课堂事实**：交给 Octos 的原问答带上当时老师，使 Octos 能区分参与者。

不做（留在原阶段）：固定反应台词与动作、预制课多音色、完整查看/纠正/遗忘界面、多老师共享规则的完整实现、知识地图、成就、报告。

验收：
- 无记忆条件下，同一组问题两位老师可辨认、数学和互动仍正确、学生本次要求被尊重；
- 有记忆条件下，第二、三堂课能引用真实发生过的经历或明确偏好，不编造；
- 首段速度不回退（零新增模型往返；预取不在关键路径）；
- 真实模型验证使用用户自带 Key，需事先批准预算。

### C. 第五阶段之前：补齐精度

task-v2 真实质量、规则升级后的重新分析策略与费用、预制课知识点对应教学审核、提示去重等审查遗留项，在地图和成就开始前按其实际需要完成。

## 需要用户决定的事项

| 编号 | 事项 | 建议 | 理由 |
|---|---|---|---|
| D1 | 第二阶段怎样合并 | 整个分支合并，知识点分析保持默认关闭 | 再拆一个只含基础记录的分支需要重新整理、审查、测试，成本高且易出错；分析代码已独立审查且不启用 |
| D2 | 速度门槛的判定口径 | 当前提交重跑免费 40 对；若各情况 p50 差值都小于一帧（约 16.7 ms，即测量采样精度）且零新增模型往返，判定不回退 | 上次 f28cda2 各情况 p50 约 613 ms，最大差 +3.7 ms（约 0.6%），配对差值 p95 约 17 ms，与一帧采样间隔相当；AGENTS.md 不允许 agent 自行放宽门槛，所以需用户确认口径 |
| D3 | 首批两位老师 | 一位“讲理由的讨论伙伴”（平静、先找第一处分歧步骤、具体认可）；一位“轻松的鼓励者”（一个主要比喻、简短玩笑后回到数学、卡住时具体鼓励）。形象从现有皮肤中各选一个 | 方案原有的两种对照最清楚；先验证风格可辨认 |
| D4 | 老师声音 | 第一版两位老师分别使用用户 TTS 供应商中的两个音色，由用户在设置里选；未设置时沿用当前音色 | 当前每个账号只配一个音色；不能假定供应商音色列表 |
| D5 | 切片里老师之间共享什么 | 学习进展和学生明确说明“以后都……”的偏好对两位老师都可用；共同经历注明参与老师，其他老师不冒称亲历；只对某位老师说的要求，切片中不自动用于另一位 | 最保守、可验证；完整规则仍属第四阶段待定 |
| D6 | 真实模型验证预算 | 切片完成免费验证后，另提交最小执行单（场次、请求上限、费用上限）供批准 | 旧付费授权已关闭 |

D1、D2 决定第二阶段能否合并；D3–D5 决定切片能否开始实现。D6 在切片代码完成后再提出。

## 切片的技术落点（已核对代码）

| 仓库 | 改动 | 现状依据 |
|---|---|---|
| learning-coach | `manifest.json` 三个课程 action 的 `input_schema` 增加 `tutor_context`（摄像头、选区入口再加 `learner_context`）；`lesson-plan-generation.ts` 已把两者放入模型输入，需在提示中说明语义 | 当前只有普通入口接受 `learner_context`，三者都不接受 `tutor_context`，且 `additionalProperties: false` 会拒绝额外字段 |
| octos-learn | 老师设定配置、选择与账号绑定；课程 action 传 `tutor_context`/`learner_context`；预取 Octos 记忆与粗粒度学习事实；原问答附带老师身份 | 前端目前完全不传这两个字段；`use-teacher-skin.ts` 有 7 个现成形象；TTS 设置为单一音色 |
| octos | 切片第一步不改；用现有 `memory/overview`、`memory/search`、`memory/load`、`memory/request` | 若老师参与者/适用范围无法表达，按方案在 Octos 内补通用能力，不在其他仓库另建记忆处理 |

速度风险：`tutor_context` 和 `learner_context` 会增加课程生成的输入长度，需要控制长度并在免费对照之外，用真实模型验证（D6）确认首段时间。记忆读取放在提交前预取，失败或超时不阻塞。
