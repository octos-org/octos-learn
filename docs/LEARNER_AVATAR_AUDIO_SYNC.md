# 配音与嘴型：本机排练与后续接入

日期：2026-11-02。当前仅为动态头像试验室功能；未改变普通课程配音播放器、课程 Take 或 `.olesson`。

## 已实现

在 `https://127.0.0.1:5173/teach/avatar-lab` 的“配音与嘴型排练”中：

1. 点击“载入校准音”，准备 4 秒原创提示音，不含人声。没有自动播放。
2. 使用音频控制播放/暂停；拖动“配音进度”，选择 0.75/1/1.5 倍速。
3. 角色每帧读取 `HTMLAudioElement.currentTime`。暂停保持当前位置，跳转直接采样目标位置，结束回到闭嘴；不使用另一个累计计时器追赶音频。
4. 可以导入本机已生成的配音：最多 60 秒、10 MB、1–2 声道。浏览器支持的格式通过解码确认，不假定扩展名可用。
5. 默认离线分析 20 ms RMS 音量包络，生成 `jawOpen` 基础开合；界面明确其不能识别闭唇/圆唇等发音类别。
6. 可导出嘴型轨，或导入同一音频对应的外部发音嘴型轨。哈希不符、时长偏差超过 50 ms、未知通道/乱序/越界等直接拒绝，保留原可用轨。

音频只在内存与本机 Blob URL 中用于试听，不进片段库、不上传、不保存到课程。不会调用 TTS/ASR 或付费模型，也不申请麦克风。解码上下文在完成、失败或取消时关闭；退出时暂停并释放 URL，迟到任务不覆盖新选择。隐藏页面时暂停播放。

## 嘴型轨 v1

实现：`src/learning/avatar/lip-sync.ts`。

```json
{
  "schema": "octos.avatar-lip-sync.v1",
  "audioSha256": "<实际配音文件字节的 SHA-256，小写 64 位十六进制>",
  "durationMs": 1000,
  "method": "aligned-visemes-v1",
  "keys": [
    { "timeMs": 0, "channels": {} },
    { "timeMs": 300, "channels": { "jawOpen": 0.3, "mouthPucker": 0.7 } },
    { "timeMs": 1000, "channels": {} }
  ]
}
```

以上仅为格式示例，**不是某句配音的真实标注**。

- `method` 只接受 `envelope-v1` 或 `aligned-visemes-v1`；后者代表外部输入类别，不代表系统已验证准确度。
- 最多 6001 个关键帧，严格递增；第一帧时间 0，最后一帧时间等于轨道时长。
- 仅接受标准清单中 `mouth*`、`jaw*`、`tongue*`，权重 `[0,1]`。外部配音嘴型不能覆盖眼睛、眉毛与头部。
- 相邻关键帧线性插值；采样位置由播放器提供。采样函数本身没有前进状态，可任意倒退、暂停或跳转。
- 更换音频会清空旧轨并重新分析，之后必须重新提供对应发音轨。文本与音色的课程缓存还未接入这里。

## 达到高质量还需要的工作

1. 从最终 BYOK TTS 音频取得供应商音素/词级时间；不足时增加音频强制对齐。选择服务前分别检验中英文输出、费用、隐私和供应商兼容性。
2. 把音素映射为星狐实际绑定支持的发音形状，加入协同发音与上下文修正。不能只用音量结果更名为发音嘴型。
3. 确认文本、音色、音频、嘴型生成器和角色版本共同进入缓存标识；实际音频哈希是当前排练轨的强制匹配条件。
4. 在课程准备阶段预生成并缓存，不能在普通 AI 课程首段路径新增模型往返。
5. 暴露真实媒体时钟给头像和板书；当前课程播放器只有开始/完成事件，Web Audio 与 Android 原生播放器还需分别接入时钟。不能把试验室 HTMLAudioElement 的结果推定为 APK 已支持。
6. 保留摄像头表演中的眉眼和姿态，按句子锚点重新对齐；嘴部完全由最终配音驱动。改词/配音后不能沿用原始讲述嘴型或只按整段等比例缩放。
7. 新课包能力需要明确版本、资源哈希、离线与旧读者行为。当前没有把高频嘴型塞进 OLL 板书事件。

声音同步、嘴型类别准确度与美术自然度分开验收；提示音与基础包络不能证明苹果级效果、端到端延迟或人类语音质量。
