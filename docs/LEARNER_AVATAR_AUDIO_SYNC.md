# 配音与嘴型：本机排练与后续接入

日期：2026-11-02。已接入可选的课包嘴型保存、试验室逐卡试听、作品预览及下载课包完整白板播放中的工程角色。摄像头 Take 表演轨与正式星狐尚未接入。

## 已实现

在 `https://127.0.0.1:5173/teach/avatar-lab` 的“配音与嘴型排练”中：

1. 点击“载入校准音”，准备 4 秒原创提示音，不含人声。没有自动播放。
2. 使用音频控制播放/暂停；拖动“配音进度”，选择 0.75/1/1.5 倍速。
3. 角色每帧读取 `HTMLAudioElement.currentTime`。暂停保持当前位置，跳转直接采样目标位置，结束回到闭嘴；不使用另一个累计计时器追赶音频。
4. 可以导入本机已生成的配音：最多 60 秒、10 MB、1–2 声道。浏览器支持的格式通过解码确认，不假定扩展名可用。
5. 默认离线分析 20 ms RMS 音量包络，生成 `jawOpen` 基础开合；界面明确其不能识别闭唇/圆唇等发音类别。
6. 可导出嘴型轨，或导入同一音频对应的外部发音嘴型轨。哈希不符、时长偏差超过 50 ms、未知通道/乱序/越界等直接拒绝，保留原可用轨。
7. 可导入带嘴型的 `.olesson`，切换卡片并直接试听包内配音和已验证嘴型；不会重新分析成基础开合来覆盖外部发音轨。

试验室导入的音频只在内存与本机 Blob URL 中用于试听，不进片段库、不上传，也不会写回课程。不会调用 TTS/ASR 或付费模型，不申请麦克风。解码上下文在完成、失败或取消时关闭；退出时暂停并释放 URL，迟到任务不覆盖新选择。隐藏页面时暂停播放。

## 在录课流程中保存基础嘴型

在“看我的课”的分享准备区域勾选“保存基础嘴型（预览）”，再执行原有的“准备分享”：

- 默认不勾选，继续生成原来的 v1 包，不增加解码或嘴型分析。
- 勾选后，每张卡片仍只调用一次原有 BYOK TTS；从其最终音频在本机生成基础开合，并保存到新 v2 包。最多 60 秒/卡片，分析失败会明确报错，不静默删掉用户要求的动作。
- 选项随本人草稿保存；改变选项、文字或音色会使旧课包标记过期。准备过程中更换选择或退出页面会取消旧任务，迟到结果不会覆盖新预览。
- 原先选择的音色如果不再被当前服务提供，会要求重新选择，或明确点击“使用设置中的声音”；不会静默换音色生成新课包。已经准备好的离线配音不要求当前仍配置该语音服务。
- 准备好的嘴型课包可以直接在作品预览中显示动态工程角色；也可下载后进入 `/teach/package` 的“播放课程包”，播放完整白板、配音与可用嘴型。动态头像试验室仍支持逐卡诊断试听。

## 完整白板播放器的同步与边界

- 作品预览和下载包播放器共享现有旁白播放链路，不建立第二个音频播放器。Web Audio 读取本次 source 对应的 AudioContext 媒体时间；Android 的 HTML 媒体路径读取实际 `currentTime`。停止、取消、切换音频后旧时钟失效。
- 头像按当前卡片与课包哈希选择对应嘴型，不使用墙上时钟推算；暂停回到待机，不借用另一张卡的动作。普通实时 TTS 没有已验证的配套轨，不显示伪同步。
- APK 的 `OctosNativeTts` 原生播放桥目前没有可读时钟，继续保留声音播放并提示暂不支持同步；Android HTML 媒体路径有代码和测试，不等于 APK/大屏真机已验证。
- `/teach/package` 只读取经格式校验的包内音频；缺失或文字不匹配直接失败，不回退调用付费 TTS。读取进度按本机 profile 与课包内容标识隔离；导入内容本身在内存中，不上传。
- 动态角色按需加载，允许隐藏；图形失败时保留声音和白板。嵌入式白板使用紧凑留白，普通工作区继续保留其工具栏空间。
- 用两卡原创提示音课包在 HTTPS 5173 实际验证了白板呈现、配音时钟同步状态、重播、暂停、隐藏与恢复头像。本轮没有真人录制或付费语音调用；提示音不是精细发音质量证据。

## 课包 v2 的兼容边界

`octos.learner-lesson-package.v2` 声明必需能力 `avatar-lip-sync-v1`；每张有配音的卡片都需要一个对应嘴型文件，路径为 `mouth/<n>.json`。v1 读者依据新 schema 明确拒绝，新读者继续接受不带动作的 v1。

除文件哈希外，读取还核对：canonical 课程作者与旁白、卡片 ID、文字哈希、最终音频哈希、轨道时长、嘴部通道白名单、文件角色与唯一引用；拒绝重复文件名/路径、混用不同卡片、未知必需能力和把 v2 改名为 v1。校验值用于一致性和损坏检测，不是作者身份签名。

解包前按 ZIP 目录限制单文件 25 MB、总展开内容 100 MB、最多 513 个条目（含 manifest）；构建端使用一致的文件与总量限制。当前 v2 **只携带配音嘴型参数**，没有正式角色 GLB、眉眼/头部表演、绑定版本或完整离线动画资产，不能称为完整头像课包。

可复用的[校准课包](avatar-animation-phase-a/calibration-mouth-course.olesson)含两张卡片和原创提示音，没有真人声音或表情；它验证链路，不验证 TTS 或发音质量。重新生成：

```sh
pnpm exec vite-node scripts/create-avatar-calibration-package.ts /private/tmp/octos-mouth-calibration.olesson
```

## 嘴型轨 v1

实现：`src/learning/avatar/lip-sync.ts`。

```json
{
  "schema": "octos.avatar-lip-sync.v1",
  "audioSha256": "<实际配音文件字节的 SHA-256，小写 64 位十六进制>",
  "durationMs": 1000,
  "method": "aligned-visemes-v1",
  "keys": [
    { "timeMs": 0, "channels": {} },
    { "timeMs": 300, "channels": { "jawOpen": 0.3, "mouthPucker": 0.7 } },
    { "timeMs": 1000, "channels": {} }
  ]
}
```

以上仅为格式示例，**不是某句配音的真实标注**。

- `method` 只接受 `envelope-v1` 或 `aligned-visemes-v1`；后者代表外部输入类别，不代表系统已验证准确度。
- 最多 6001 个关键帧，严格递增；第一帧时间 0，最后一帧时间等于轨道时长。
- 仅接受标准清单中 `mouth*`、`jaw*`、`tongue*`，权重 `[0,1]`。外部配音嘴型不能覆盖眼睛、眉毛与头部。
- 相邻关键帧线性插值；采样位置由播放器提供。采样函数本身没有前进状态，可任意倒退、暂停或跳转。
- 更换音频会清空旧轨并重新分析，之后必须重新提供对应发音轨。文本与音色的课程缓存还未接入这里。

## 达到高质量还需要的工作

1. 从最终 BYOK TTS 音频取得供应商音素/词级时间；不足时增加音频强制对齐。选择服务前分别检验中英文输出、费用、隐私和供应商兼容性。
2. 把音素映射为星狐实际绑定支持的发音形状，加入协同发音与上下文修正。不能只用音量结果更名为发音嘴型。
3. 确认文本、音色、音频、嘴型生成器和角色版本共同进入缓存标识；实际音频哈希是当前排练轨的强制匹配条件。
4. 在课程准备阶段预生成并缓存，不能在普通 AI 课程首段路径新增模型往返。
5. Web Audio 与 Android HTML 媒体路径已暴露只读媒体时钟；后续为 `OctosNativeTts` 原生桥增加权威位置读数，并分别实测 APK/目标大屏。不能把桌面结果推定为 APK 已支持。
6. 保留摄像头表演中的眉眼和姿态，按句子锚点重新对齐；嘴部完全由最终配音驱动。改词/配音后不能沿用原始讲述嘴型或只按整段等比例缩放。
7. 当前 v2 已支持基本嘴型文件与旧读者拒绝；正式模型、完整表演、映射版本和新能力仍需后续包版本设计。高频嘴型不放入 OLL 板书事件。

声音同步、嘴型类别准确度与美术自然度分开验收；提示音与基础包络不能证明苹果级效果、端到端延迟或人类语音质量。
