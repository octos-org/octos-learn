# 学生当老师模式：计划

日期：2026-10-30。状态：方向探索，尚未开始实现。本文件记录与用户讨论后形成的方案、需要改动的 OLL 表面和待决事项。

## 用户决定

- 产品当前面向美国 K–12 市场（2026-10-30）。本模式的隐私、同意和分享范围按美国规则设计。
- 用户希望孩子能自己讲课、录制并分享；用虚拟形象和声音保护未成年人隐私（2026-10-30）。
- 孩子可以自由选择任何主题讲课，不限于星图中已点亮的知识点；主题类型只影响小章鱼的帮助、检查方式、星图和分享范围（2026-10-31）。
- 互动组件（函数图、单位圆、3D 等）是录课的一等工具，以插入面板为主要入口，不以手写转换为主；“整理一下”后整洁版本原位替换手写（2026-10-31）。
- 录课时不再沿用 OLL 为 AI 老师制定的“学生原稿不可修改、不提供隐藏/删除”规则：孩子是课程作者，可以擦除、隐藏、替换自己的笔迹，这些操作可以成为课程动作（2026-10-31）。

## 核心判断

1. **录的是课堂动作，不是视频。** 笔迹、指点、整理后的公式、讲述文本都按时间线记录，发布物是一堂 OLL 课程，由孩子选的虚拟形象播放。观看者看不到也听不到真实的孩子。
2. **声音用转写后重新合成，不用变声。** ASR 转文字 → 去除姓名、学校、地点等个人信息 → 用选定的 TTS 音色重新朗读。变声会保留孩子的节奏、口音，且有被部分还原的可能。
3. **第一版不用摄像头。** 摄像头只能多带来手势；如果以后加入，只在设备上做姿态识别、只保留骨架数据，永不保存或上传画面。
4. **孩子不写 OLL。** 孩子在白板上讲课，每个操作由**宿主确定性代码**（不是模型）翻译成 OLL 动作。录完时，录制结果本身就是一堂 OLL 课程，播放、重新配音、分享和审核都复用现有 Runtime。
   - 不让模型把录制“编译”成 OLL：那会悄悄改写孩子的讲法，违背 OLL-INP-001“学生原始内容不被改写”的精神；确定性映射也便于测试。
   - 模型只出现在三处：小章鱼扮演学生提问、手写内容的“整理”建议（孩子确认后才生效）、录完后的检查反馈。
5. **价值首先来自“教中学”。** 讲给别人听是最有效的学习方式之一，即使没人观看也成立。所以先做只有自己能看的版本，社区分享放在后面。

## 分阶段

| 阶段 | 谁能看到 | 内容 |
|---|---|---|
| 1. 教小章鱼 | 只有孩子自己 | 任选主题讲给小章鱼听；小章鱼扮演不懂的学生提 2–3 个追问；Learning Coach 按卡片给出带时间点的反馈。保存为可回放的 OLL 课程。 |
| 2. 班级/家庭分享 | 班级码或邀请链接 | 老师或家长批准后其他人才能看到；观看者只能发预设反应（如“这讲清楚了！”），没有自由评论。 |
| 3. 社区 | 公开 | 每堂课发布前必须通过正确性检查和安全审核；需要单独评估法律与运营成本后再决定是否做。 |

第一阶段不需要审核，也能先验证孩子是否真的喜欢讲课，再决定社交部分的投入。

## 录制流程

1. **选主题**：任何主题都可以（见下文“主题范围”）。小章鱼问“听完你的课，我会知道什么？”，回答成为 `goals`。
2. **规划卡片**：孩子给 3–6 张卡片起名。低年级提供模板，例如“题目 → 我的方法 → 试一试 → 为什么对”。组织讲解本身就是学习发生最多的地方。
3. **逐张录制**：
   - 点录制，边说边画，点停止。
   - 工具：➕ 插入组件（见下文“互动组件”）、笔、荧光笔、激光笔、箭头、“整理一下”。
   - 录制中可以直接操作已插入的组件：拖动滑杆、拖动点、旋转 3D。这些操作被记录为课程动作，回放时自动重现。
   - “整理一下”复用现有选区流程：孩子圈出手写的 `y = x² − 2x − 3`，看到排版建议并确认，生成一个关联原笔迹的 `math` 节点，并在原位替换手写（见“互动组件”中的“笔迹由孩子掌控”）。同一选区上还可以“画出图像”“变成点”。
   - 录完显示该卡片的转写文本。高年级可以修正 ASR 错误；儿童语音是 ASR 的已知弱项，这一步必须有。
   - 某张卡片讲错了只重录这一张，不用整堂重来。一次长录制是孩子放弃的主要原因。
4. **小章鱼在卡片之间提问，绝不打断录制**：例如“等等，为什么要把 6 除以 2？”孩子用语音回答。回答作为私有学习证据保存，默认不进入发布的课程，这也满足 OLL-INC-009（课程中不含等待学生回答的控制动作）。
5. **回看与检查**：孩子用选定的形象和声音观看自己的课。Learning Coach 按卡片指出问题，例如“第 3 张：你说顶点是 (3, −4)，但图上是 (−3, −4)”。孩子只重录该卡片。
6. **提交**：进入老师或家长批准（第二阶段起）。
7. **成就**：“第一次讲课”“小章鱼终于听懂了”等成就在整个录制和检查结束后才颁发，不打断讲课过程。星图上讲过的知识点可以有区别于“学过”的标记（例如外环）。

## 主题范围

不设门槛。星图点亮只表示有学习记录，不表示掌握，不能作为讲课资格；而且“为了讲给别人听而去学”本身就是有效的学习方式。主题类型只决定周边行为：

| 主题类型 | 小章鱼的帮助 | 检查 | 星图 | 分享 |
|---|---|---|---|---|
| 星图中、已点亮 | 了解内容，追问有针对性 | 完整正确性检查 | 该星加“讲过”外环 | 与普通课程相同 |
| 星图中、未点亮 | 可选“先学一下？”，不强制 | 完整正确性检查 | 点亮并加“讲过”外环 | 与普通课程相同 |
| 数学、不在星图中 | 通用追问 | 正确性检查，标注置信度较低 | 无 | 需老师批准 |
| 其他（恐龙、游戏等） | 只问是否讲清楚 | 只检查清晰度，不对事实下结论 | 无 | 默认私有；分享需更严格审核 |

开放主题的风险主要在分享阶段（更容易说出个人信息或不当内容）；第一阶段只有自己可见，几乎不增加风险。

## 互动组件

函数图、几何、单位圆、3D 和变量滑杆是录课的一等工具，不是手写的附属品。孩子把组件放上白板，然后**边讲边操作**；回放时这些操作自动重现，观看者暂停后还能自己拖动，因为它是真实的 OLL 组件而不是视频。

### 三种加入方式

| 方式 | 做法 | 适合 |
|---|---|---|
| A. 插入面板（主要入口） | 点 ➕，选函数图、坐标网格、单位圆、数轴、三角形/图形、3D 立体、3D 曲面、表格；填一两个字段（输入 `y = 2x + 1`、选“立方体”）或用预设 | 3–12 年级的大多数情况 |
| B. 由手写转换 | 圈选已写内容 → “画出图像”“变成点”“做成表格” | 孩子已经写出来的内容，例如刚推出的方程 |
| C. 请小章鱼 | 说“小章鱼，画一个 30° 的单位圆”；结果以建议出现，孩子确认后放上白板 | 面板不便配置的内容；需要一次模型调用，较慢 |

三种方式产生同样的节点（`write kind: plot / geometry / scene3d`），区别只在创建方式。

### 操作如何记录

| 孩子的操作 | 记录为 |
|---|---|
| 边说“看高度在上升”边把 θ 滑杆从 0 拖到 90° | 课程变量 `theta` + 讲述期间 0 → π/2 的 `animate` |
| 在单位圆上拖动点 P | 同一变量的变化；点和滑杆共用变量，正弦图跟着动 |
| 旋转立方体露出某个面 | `scene3d` 节点的视角变化 |
| 用激光笔点顶点、棱或面 | `point` 指向该可寻址部件（决定记录 0002） |
| 高亮公式中的“+6x” | `emphasize` 该片段 |

### 结构化的点和标签

在坐标网格上用“点”工具放点：点击吸附到格点并显示坐标，弹出的小标签框预填 A、B、C…，可以保留、改字或用语音命名。这样的点是带标签和坐标的 `geometry` 节点，可以被引用：“画出图像”直接过这些点画线；检查流程能据此算出真实斜率并与讲述比对；小章鱼能问“为什么先选 A？”。

手写的“(1, 2)”和“A”只是图画，系统无法理解。已经手写的坐标可以圈选后“变成点”，确认后得到同样的结构化点。手写保留给自由批注：箭头、“好陡！”、涂鸦。

### “轮到你了”卡片

OLL 已支持互动任务。孩子不需要配置界面就能出一道题：

1. 加一张“轮到你了”卡片；
2. 说出挑战：“把点拖到正弦最大的地方”；
3. 自己做一遍（拖到 90°），宿主记下目标值；
4. 宿主生成任务：`expression_target: sin(theta) = 1`、容差和孩子口述的提示。

观看者得到一道会检查答案的真实练习，来自孩子自己的演示。

### 示例：十年级 Riley 讲“单位圆如何变成正弦波”

| 卡片 | Riley 的操作 | 组件 |
|---|---|---|
| 1 | ➕ 单位圆，点半径：“这条臂长度永远是 1。” | `geometry` + `point` 半径 |
| 2 | 把 θ 从 0 慢慢拖到 90°：“点的高度就是 sin θ。” | `animate theta` 0 → π/2 |
| 3 | ➕ 函数图 `y = sin x`，与 θ 关联；拖满 360°：“高度画出了波。” | 共用 `theta` 的 `plot`，`animate` 0 → 2π |
| 4 | 轮到你了：“让正弦等于 −1。”Riley 拖到 270°。 | 任务 `sin(theta) = −1` |

全程没有手写。手写只是众多工具之一。

### 笔迹由孩子掌控

OLL 中“学生原稿不可修改、不提供隐藏/删除动作”的规则是为 AI 老师制定的：保证 AI 永远不能擦掉学生的作品。录课时作者是孩子自己，这些规则不适用（用户决定，2026-10-31）：

- 孩子可以擦除、隐藏、替换自己的笔迹；
- “整理一下”就是一次替换：回放时先写出手写，再变成整洁公式，手写不再显示；
- 擦除和替换都可以成为课程动作，回放能如实重现“写错、划掉、重写”。

仍然保留的边界（待用户确认）：

| 编号 | 边界 | 建议 | 理由 |
|---|---|---|---|
| K1 | 谁能改孩子的笔迹 | 只有孩子本人的操作；AI（小章鱼、整理建议、检查）只能提出建议，孩子确认后才生效 | 原规则真正要防的是 AI 擅自改动，这一点在录课中同样重要 |
| K2 | 被替换的手写是否私下保留 | 私下保留到课程发布后的检查结束，不出现在发布课程中，也不提供“查看原稿” | 识别出错且孩子没看就确认时还能修正；检查能区分“写对了但说错”和“写错了” |
| K3 | 录制中的小涂改是否进入课程 | 不进入：每次录制只发布最终笔迹，加上孩子明确的“替换”时刻；随手擦改视同撤销 | 回放干净；孩子想展示“划掉重写”时可以用明确的替换 |

## 与 OLL 的对应

OLL 的 Step/Beat 结构正好是录制界面的骨架。quadratic-v2 验收文档对 Beat 的总结——“一个认知变化、可寻址的证据、持久的白板结果、明确的视野焦点”——也正是孩子录一张卡片的单位。

| OLL 概念 | 孩子看到的 |
|---|---|
| Lesson（`title`、`goals`） | “你要讲什么？”和“听完的人会知道……” |
| Step | 章节（多数孩子只需要一个） |
| Beat | 卡片：一个想法，一次录完 |
| `say` | 孩子说的话，转写后显示为可修正的字幕 |
| `write` | 画的内容或放到白板上的节点 |
| `point` / `emphasize` | 激光笔和荧光笔 |
| `focus` | 根据最后触碰的内容自动生成“看这里” |
| `connect` | 从一个内容画箭头指向另一个 |

**时间同步**：OLL 用 `before_speech` / `during_speech` / `after_speech` 语义阶段而不是毫秒（OLL-TIME-003）。由于孩子的声音会被 TTS 重新合成，原始时长本来就不保留；宿主只需判断每个动作发生在讲话之前、之中还是之后。原始时间如有需要，保存在单独的私有录制文件里。

### 宿主生成示例（提议）

一张卡片生成的 Authoring Beat。标注 `// 新增` 的字段在 v0.1 中不存在：

```jsonc
{
  "key": "card-3-halve",                                   // 由卡片顺序生成
  "say": "Take the 6 and cut it in half. That gives 3.",   // 修正并去除个人信息后的转写
  "actions": [
    { "do": "write", "as": "ink-c3", "kind": "ink",        // 新增 kind
      "content": { "resource": "ink:abc123@v4" },          // 现有 OLL-INP-006 笔迹 SVG 资源
      "place": { "relation": "below", "anchor": "ink-c2" } },
    { "do": "write", "as": "neat-c3", "kind": "math",      // “整理一下”且孩子已确认
      "content": { "latex": "6 \\div 2 = 3" },
      "source": { "selection": "sel:9f…" },                // 新增：write 的来源
      "place": { "relation": "right_of", "anchor": "ink-c3" } },
    { "do": "point", "when": "during_speech", "targets": ["neat-c3"] },
    { "do": "focus", "when": "after_speech", "targets": ["ink-c3", "neat-c3"] }
  ]
}
```

## OLL v0.1 的缺口（决定记录草案）

OLL 处于 RC，只接受兼容性修复；以下每项都需要在 `octos-lesson-language/decisions/` 写决定记录并附回归证据，不能直接改 schema。四项都不是新的教学语义：第 2–4 项是元数据，第 1 项是把已有资源正式化。

### 草案 A：`ink` 节点

- **问题**：现有节点 kind 为 `text, math, shape, diagram, geometry, plot, scene3d, image, table, note`，学生笔迹只作为独立 SVG 资源存在，课程无法引用并播放它。
- **提议**：新增 `write kind: "ink"`，`content.resource` 引用 OLL-INP-006 笔迹资源（带格式版本、编辑器版本、文档版本和校验值）。Runtime 可以在 `during_speech` 按笔画顺序重现书写；降低动态效果时直接显示终态。
- **不采用**：把笔迹当 `image` 显示。那是临时绕路，丢失笔画顺序和命中测试，以后还要迁移。
- **证据要求**：Core 归一化与 Reducer 确定性；资源损坏时显式失败；不支持 ink 的 Runtime 产生明确降级状态；普通课程首屏仍不加载笔迹编辑器（OLL-INP-008）。

### 草案 B：课程模式 `learner_taught`

- **问题**：`lesson.mode` 目前只允许 `"explain"`。
- **提议**：新增 `"learner_taught"`，Runtime、检查流程和分享界面据此区分学生课程与 AI 课程（例如不显示 AI 老师立绘、不触发 AI 课堂的后续动作）。

### 草案 C：作者与播放形象

- **问题**：课程无法声明“作者是学生 X，由孩子形象 Y 播放”，默认会落到 AI 老师人格。
- **提议**：Lesson 增加作者元数据（学生档案引用，不含真实姓名）和播放形象引用。孩子形象是独立的一套（小章鱼主题或风格化生物），不复用 25–35 岁的成年老师角色，避免混淆谁是真人、谁是 AI。

### 草案 D：`write` 的来源

- **问题**：学生输入已有选区来源（OLL-INP-007），但课程中的 `write` 不能声明“由选区 S 派生”。
- **提议**：`write` 可选 `source.selection`，引用 Octos 生成的稳定选区编号。验证器拒绝引用不存在的选区。“整理一下”和“画出图像”依赖这一项。

### 以后再说：第二讲述者

如果将来要把小章鱼的追问放进发布的课程，需要 Beat 支持第二讲述者。第一版不做。

## 美国 K–12 约束

- **COPPA（13 岁以下）**：在学校场景下，学校可以为教育用途代为同意。所以第二阶段的自然起点是**班级内、老师批准**。面向 13 岁以下的公开分享需要可验证的家长同意，成本高得多。不存视频、重新合成声音也让收集的个人信息降到最少。
- **FERPA**：学校使用时，学生课程可能属于教育记录。这是先做班级范围分享的另一个理由。
- **联系风险**：真正的危险不是课程本身，而是陌生人借此接触孩子。任何阶段都不做自由评论、私信和关注列表；除形象名外不展示个人资料。
- **年级分段**：

| 年级 | 范围 |
|---|---|
| K–2 | 只做第一阶段（私有）；图卡模板；转写基本不需要编辑 |
| 3–8 | 完整卡片流程；班级分享 |
| 9–12 | 转写编辑、完整工具；以后可能开放公开分享 |

- **设备**：美国课堂主要是触屏 Chromebook 和 iPad，用鼠标画一整堂课很痛苦。PRD 的支持矩阵目前是桌面浏览器和 Android TV，本模式会推动 D02 加入 Chromebook 触屏/触控笔。

## 速度影响

- 普通课程首段播放速度：**零影响**。本模式是独立入口；笔迹 Runtime 仍按需加载，不进主包。
- 录制过程中：ASR 与转写在每张卡片停止后处理，不在书写关键路径上；小章鱼追问在卡片之间生成，可在孩子录下一张卡时预取。
- 播放学生课程：与普通 OLL 课程同一 Runtime；TTS 重新合成可以在提交时预先生成，播放时不再调用模型。
- 实现前需要实测：单张卡片停止后到字幕出现的延迟、整堂课检查反馈的耗时。

## 需要用户决定的事项

| 编号 | 事项 | 建议 | 理由 |
|---|---|---|---|
| L1 | 第一阶段覆盖的年级 | 3–12 年级先做，K–2 晚一步 | K–2 的录制交互需要单独的图卡设计，不应拖住主流程 |
| L2 | 分享的最远范围 | 先定为班级/家庭；公开社区另行评估 | COPPA/FERPA 与审核运营成本差距很大 |
| L3 | 社区阶段由谁审核 | 先不决定；若做第三阶段，需要模型初筛加人工复核 | 正确性和安全都不能只靠模型 |
| L4 | 孩子形象的设计方向 | 小章鱼主题的风格化形象，与成年老师角色明确区分 | 避免混淆真人与 AI；不受老师立绘规则约束 |
| L5 | 发布课程是否包含小章鱼的追问 | 第一版不包含 | 保持课程线性，避免 OLL 第二讲述者的新语义 |

## 附录：完整录制示例

八年级学生 Jordan 讲“用两点求斜率”（课程库 `linear-intro-and-slope`），选了狐狸形象。

1. **选主题**：输入“slope”，匹配到已点亮的星。小章鱼问听完能做什么，Jordan 说“用任意两点求斜率”。→ `title`、`goals`、`mode: "learner_taught"`。
2. **规划卡片**：四张——什么是斜率 / 选两个点 / 竖直变化除以水平变化 / 在图上验证。→ 一个 Step、四个空 Beat。
3. **卡片 1**：边说“斜率就是线有多陡，像坡道”边画两个坡道，用激光笔点较陡的那个。ASR 把 slope 听成 soap，Jordan 点词修正。→ `say`、`write kind: ink`、`point`、`focus`。
4. **卡片之间**：小章鱼问“斜率可以是 0 吗？”，Jordan 答“可以，平的线”。回答进入私有学习记录，不进发布课程。
5. **卡片 2**：Jordan 插入坐标网格，用点工具在 (1, 2)、(4, 8) 放点并命名 A、B（结构化 `geometry` 点，可被引用）。
6. **卡片 3**：手写 `(8−2)/(4−1)`，圈选后“整理一下”并确认，排版公式原位替换手写；但口头说成“3 比 6，斜率二分之一”（讲反了）。
7. **卡片 4**：圈选两点“画出图像”，得到经过 A、B 的直线，沿线指点。
8. **检查**：用狐狸形象和 TTS 回看；Learning Coach 指出卡片 3 应为 6/3 = 2，并说明卡片 4 的图与 2 一致。Jordan 只重录卡片 3。
9. **结束**：保存到“我的课程”，斜率星加“讲过”外环；第二阶段可提交给老师批准；全部结束后才出现“第一次讲课”成就。

保存位置：OLL 课程与笔迹资源、TTS 音频与课程同范围；原始语音转写后删除或仅私有；小章鱼问答与检查反馈只进入 Jordan 的学习记录。全程约 10 分钟。
