### 怎样工作

- **老师设定**（`src/learning/teachers/teachers.ts`）：阿澜（scholar 外观，看重理由、先找第一处分歧步骤、具体认可）与豆豆（coral 外观，一个主要比喻、简短玩笑后回到数学、卡住时具体鼓励，认可时不夸大成已经掌握）。名字为方案示例，可再改。设定文本含保守共享规则：不把其他老师的经历说成自己的，只对其他老师的要求不适用，除非学生说明对所有老师生效。
- **选择**：本设备保存（与现有外观设置相同方式）；选择老师同时切换到其默认外观。账号级保存是后续工作。
- **学生背景**（`learner-background.ts`）：Octos `memory/overview` 的长期记忆（最多 1500 字）+ 产品学习记录最近 5 次学习的程序统计（提问、播放片段、练习作答次数，注明“播放不代表掌握”）。按账号缓存；课堂空闲时最多每 2 分钟刷新一次，连接建立时强制刷新；8 秒超时，失败保留旧值；只复用已有连接读取记忆，不为此新开连接；读取期间账号变化则丢弃结果。**提交问题时只读缓存，不等待任何网络。**个人记忆文本只在内存中，不写入浏览器存储、学习记录事件或追踪日志。
- **兼容旧安装**（`lesson-context-support.ts`）：课程 action 会拒绝未声明的字段。前端在页面加载和每次连接建立时读取已安装 action 的输入定义（只采用最新一次结果），只向声明了 `teacher_profile`/`learner_background` 的 action 发送；未知时不发送。旧版 Learning Coach 不会收到任何新内容，部署先后不会导致课程失败。老师身份只在设定确实发送时才写入记录。
- **记录与 Octos**：`question_routed` 可带 `teacher_id`/`teacher_name`（必须成对，严格校验）。交给 Octos 的老师回复副本前加“【阿澜老师】”，以便 Octos 提炼记忆时区分参与老师；学习记录中的原回答保持原文；已暂存的交付不受影响（INSERT OR IGNORE）。这是临时约定：Octos `session/append_message` 没有说话者字段，按方案应在 Octos 内补通用能力（待办）。

| S2 带老师标签的回复再进入 Octos 后，可能把原本未注明老师的事实变成“某老师讲过” | 推测，未验证 | 未改；依赖 Octos 补说话者/参与者能力，列为待办 |

| S5 记忆文本会出现在课程 action 参数中，可能被 Octos 任务记录保存 | 成立 | 位于学生本人 Octos 内；列为待核对 |

原审查者复核 `63bef19`/`7c1482c`：D1–D4 确认修复；新发现两项并已修复（`d9f1ccf`）：
- N1（确认）：页面刚加载时空闲读取已在进行且读不到记忆，连接建立后的强制刷新直接复用了这次读取，最多 2 分钟没有 Octos 记忆。现在强制刷新会在进行中的读取结束后再读一次；缓存测试在修复前失败、修复后通过。工作区冷启动测试覆盖连接晚于加载的顺序，但其模拟读取瞬间完成，没有重现两次读取重叠，重叠由缓存测试覆盖。
- N2（确认）：上课中途重连会立即读背景。现在只标记待刷新，下一次空闲时强制刷新。
- S-a（推测，已处理）：普通对话路径的 agent 模型自己填写工具参数，可能编造老师设定或学生背景。Octos 只按各 action 自己的 schema 校验（已核对 `ui_protocol_transport.rs`），因此新字段只保留在三个课程 action 上，从 agent 可见的工具 schema 移除（`48041ae`）。
- 残余：记忆与学习记录仍可能来自不同身份（另一个标签页切换账号而连接未跟随），已列入限制。

## 已知限制与未做

- 打开页面后极快提交的问题可能不带学生背景（预取未完成）；真实输入通常需要数秒。
- 学生背景中的 Octos 记忆与学习记录可能来自不同身份：记忆读取使用当前已连接的连接，若另一标签页切换账号而连接未跟随，二者可能不一致。
- Octos 记忆没有老师归属，保守共享目前只靠提示约束（含 S2）；需要 Octos 补说话者/参与者表达后才能程序保证。
- 只覆盖直接课程 action；普通对话 turn 路径未接入老师。
- 学生背景只在学习记录模块可用时读取（预览/固定课程模式不读取）。
- 发布时必须先部署产品服务端，再更新网页和 APK（S4）。
- 老师音色未接入（D4 待定）；固定反应台词、动作、预制课音色、查看/纠正/遗忘界面不在切片内。
- **未做真实进程端到端检查**（真实 Octos + 新 Learning Coach + 本地模型替身，确认 Octos action 校验接受新字段并传入模型）：与 D6 真实模型验证需要同一套隔离环境，合并入 D6 准备。
- **未做真实模型质量验证**：两位老师是否可辨认、记忆引用是否真实，需要按 D6 批准预算后验证。
