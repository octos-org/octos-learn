## 已实现

1. 独立、按需加载的试验室路由；没有在普通 AI 课程路径增加模型往返。
2. 自制三维工程测试角色，连续嘴型开合、左右眼、眉毛、头部与视线控制；目标 30/60 FPS 可选，停止后停止连续渲染。
3. MediaPipe 0.10.32 的 CPU 识别在独立经典 Worker 中运行；模型与 WASM 本机托管。
4. 摄像头只请求视频；只有用户点击后才请求权限，不采集音频、不上传画面。
5. 生命周期覆盖退出路由、隐藏页面、停止、权限迟到、位图迟到、加载失败与加载超时；对应测试验证资源释放。
6. 统一命名的 52 通道兼容清单；按来源保留实际支持的通道，不以数组序号硬套映射。
7. 自然表情校准、不同部位的平滑、失跟返回待机。
8. 不使用摄像头的演示动作，以及真实本机模型对空白画面的自检；二者在界面明确区分。
9. 最长 60 秒的表情片段录制、暂停/回放/定位、JSON 导入/导出。只包含角色参数，当前片段留在内存；用户可主动导出或保存到本机片段库。
10. 实际显示帧率、识别与取帧到结果的 p95、绘制提交耗时，以及观察报告导出。界面明确这些不是完整动作延迟或 GPU 总耗时。
11. 复用现有 `TeachBoard` 与 Ink Runtime 的试写区；试写内容与本机 profile 对应，不加入课程草稿。
12. 已选星狐三张概念图保存到 `public/teach-avatars/star-fox/`，试验室展示其为正式模型的参考。
13. iOS 原生 ARKit 捕捉伴侣的 Xcode 工程源码；捕捉、校准、最多 60 秒参数导出、后台停止。当前用文件导入打通数据格式，尚无实时网络配对。
14. 本机表情片段库：使用 IndexedDB，复合账号/片段键隔离；主动命名保存、重开、改名、移入回收站与恢复。元数据与动作原子写入，列表不加载全部动作帧；重名 ID 拒绝覆盖。存储失败明确提示，仍可导出当前片段。清除浏览器数据会丢失库，需自行导出备份；无云同步。
15. 六段固定 4 秒、121 帧的合成排练：张嘴与闭嘴、左右眨眼、微笑着讲述、圆唇与放松、转头与点头、遮挡与恢复。均标记 `demo`，无需摄像头，可播放、定位、导出并保存，不能作为真人捕捉质量证据。
16. 配音与嘴型本机排练：导入已生成的短配音，读取真实媒体时间以支持暂停/跳转/变速；离线 RMS 包络基础开合、音频哈希绑定的外部发音轨导入/导出。详见[配音与嘴型说明](LEARNER_AVATAR_AUDIO_SYNC.md)。
17. 正式模型接入契约、按名称绑定运行模块、GLB 元数据检查命令与[星狐模型交付规范](LEARNER_AVATAR_MODEL_SPEC.md)。要求精确模型哈希、52 通道覆盖/缺失声明、基础嘴眼通道和唯一节点/目标；没有正式 GLB，未替换工程角色。
18. 录课作品预览的“准备分享”可选保存基础嘴型：复用每卡唯一一次 TTS 的最终音频，生成自包含音频/嘴型 v2 课包；默认仍为 v1。试验室可导入 v2 并逐卡读取原始嘴型试听。格式校验、取消/迟到任务和不可用音色处理已加入；没有把工程测试模型当正式角色打包。

### 2026-11-02：配音时钟与正式模型接入准备

- 新增 `lip-sync.ts`，嘴型关键帧只接管嘴/下颌/舌部，绑定实际音频 SHA-256；校验时长、顺序、范围和字段。默认仅 RMS 基础开合，外部 `aligned-visemes-v1` 轨道也明确提示尚未验收准确度。
- `AvatarAudioPreview` 使用独立 HTMLAudioElement，每帧采样真实媒体位置；暂停保持当前位置，跳转不依赖累计计时器，结束回到待机。无需麦克风、摄像头、网络或语音服务；解码最多等待 20 秒，取消/失败/结束分析释放上下文，退出释放音频 URL。
- 现有普通课程 Web Audio/Android 配音播放器只有开始/完成通知，尚未加入可读媒体时钟；本轮未修改这些公共播放路径。
- 正常 HTTPS 5173 浏览器真实加载原创 4 秒校准 WAV，解码/生成基础嘴型、播放、结束、暂停、定位和 1.5 倍速验证通过。DOM 实际观察：`currentTime=1.501888`、`duration=4`、`paused=true`、`playbackRate=1.5`。这只是同步链路验证，未做语音发音质量或端到端延迟验收。
- `rig-contract.ts` / `rig-binding.ts` 支持标准通道→命名 morph、头部相对静止姿态的旋转和重置；单元验证覆盖缺失通道、冲突绑定、歧义节点和资产哈希不符。
- `scripts/check-avatar-rig.ts` 对独立生成的 2360 字节三角形 GLB 夹具通过，声明外链图像的负例被拒绝。夹具不是角色模型；脚本不是完整 glTF 校验器，正式交付仍需 Khronos 校验、实际加载及视觉/性能审查。
- [正式模型交付规范](LEARNER_AVATAR_MODEL_SPEC.md)、[映射模板](avatar-animation-phase-a/rig-manifest.template.json) 与[配音嘴型格式/后续待办](LEARNER_AVATAR_AUDIO_SYNC.md) 已建立并进入文档索引。
- 当前没有自动提取/对齐音素、没有真实 TTS 质量测试、没有正式模型加载器接入或已验收角色，也未连接手机/电视。
- 本轮最终全量 184 文件/1602 项通过，TypeScript 与生产构建通过；没有增加运行依赖或付费服务调用。配音舞台的性能未纳入既有主捕捉舞台的观察报告。

### 2026-11-02：基础配音嘴型接入课包

- 普通打包默认保留 v1 和原有语音调用次数；明确勾选“保存基础嘴型（预览）”后，每卡最终配音在本机分析一次，写入 v2。错误/取消不静默删轨，草稿保留选择，更换选项/文字/音色会使缓存过期。
- v2 必须声明 `avatar-lip-sync-v1`，每张旁白卡都有唯一对应的动作文件；新读者兼容 v1，旧读者拒绝新 schema。读取验证文件/文字/音频哈希、卡片匹配、轨道/文件角色及展开大小，拒绝降版本伪装、未知必需能力、重复引用和非法动作。
- 试验室新增课包导入与逐卡试听，保留包内外部发音轨，不重新替换为 RMS。Blob 读取支持 FileReader 后备；账号切换会重建试听组件。发现并修正片段库与试听区使用同一 React key 的重复显示问题。
- 作品预览发现旧音色不可用时曾会静默使用账号音色：现要求重新选择，或明确选择“使用设置中的声音”。已准备好的离线包不依赖当前语音服务；新打包与未打包试听不静默替换选择。
- 浏览器真实导入两卡原创校准课包，切换第二卡、播放至结束、暂停/定位均通过。实际媒体观察 `currentTime=1.518353`、`duration=4`、`paused=true`；校准音没有人声，不代表 TTS/发音准确度测试。
- [校准课包](avatar-animation-phase-a/calibration-mouth-course.olesson) 134,328 字节，内容哈希 `e88c78e0cb83d668882de4d4e4276fa3b24b6cb0da23afae20b9dc23f84f7ccd`。`scripts/create-avatar-calibration-package.ts` 可重新生成，逐字节一致。
- 最终全量 185 文件/1614 项、TypeScript、生产构建及中英消息检查通过。TTS 接入测试使用模拟供应商；没有实际调用付费服务、录制真人声音或更改设备权限。

## 已知边界与下一步

1. 本机只有 Command Line Tools，没有 Xcode/iOS SDK。无法编译安装 iOS 应用。后续安装完整 Xcode 后按 [Apple 捕捉验证说明](LEARNER_AVATAR_CAPTURE_IOS.md) 继续。
2. 本机未发现 `adb`/默认 Android SDK platform-tools，目标大屏尚未连接实测；不能确认电视帧率与摄像头兼容性。
3. 当前模型仅由程序生成少量形体来验证驱动；正式星狐需要专业三维拓扑、面部绑定和组合修正。
4. 当前网页可导入 Apple 参数文件，但没有手机实时配对/低延迟传输。
5. 摄像头表演片段尚未写入课程 Take；最终配音的基础嘴型已可存入 v2 `.olesson` 并在试验室逐卡试听。正式白板播放器仍未叠加动态角色，无自动音素对齐/精细发音生成。
6. 尚未完成真实人脸、儿童、弱光/眼镜/遮挡、20 分钟持续录课、端到端动作延迟和与 Memoji 的对照。
7. 当前采集使用 CPU Worker；GPU delegate 是否更好要与数学组件竞争资源的结果一起测量。
8. 网页降级提示 WebGL 2 需求；安卓原生捕捉、原生渲染和旧电视视频降级仍待实现。

测试模型演示帧率、空白画面自检和表情数据格式验证，均不能代表正式角色或电视的最终性能。
