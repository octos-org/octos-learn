## 已实现

1. 独立、按需加载的试验室路由；没有在普通 AI 课程路径增加模型往返。
2. 自制三维工程测试角色，连续嘴型开合、左右眼、眉毛、头部与视线控制；目标 30/60 FPS 可选，停止后停止连续渲染。
3. MediaPipe 0.10.32 的 CPU 识别在独立经典 Worker 中运行；模型与 WASM 本机托管。
4. 摄像头只请求视频；只有用户点击后才请求权限，不采集音频、不上传画面。
5. 生命周期覆盖退出路由、隐藏页面、停止、权限迟到、位图迟到、加载失败与加载超时；对应测试验证资源释放。
6. 统一命名的 52 通道兼容清单；按来源保留实际支持的通道，不以数组序号硬套映射。
7. 自然表情校准、不同部位的平滑、失跟返回待机。
8. 不使用摄像头的演示动作，以及真实本机模型对空白画面的自检；二者在界面明确区分。
9. 最长 60 秒的表情片段录制、暂停/回放/定位、JSON 导入/导出。只包含角色参数，当前片段留在内存，用户可以主动导出。
10. 实际显示帧率、识别与取帧到结果的 p95、绘制提交耗时，以及观察报告导出。界面明确这些不是完整动作延迟或 GPU 总耗时。
11. 复用现有 `TeachBoard` 与 Ink Runtime 的试写区；试写内容与本机 profile 对应，不加入课程草稿。
12. 已选星狐三张概念图保存到 `public/teach-avatars/star-fox/`，试验室展示其为正式模型的参考。
13. iOS 原生 ARKit 捕捉伴侣的 Xcode 工程源码；捕捉、校准、最多 60 秒参数导出、后台停止。当前用文件导入打通数据格式，尚无实时网络配对。

- `scripts/prepare-avatar-assets.mjs` 校验模型，复制固定依赖的 WASM，打包经典 Worker。MediaPipe 的加载器使用 `importScripts`，因此不能简单照搬 ESM Worker。
- `public/avatar-runtime/` 约 27 MB，是忽略的生成目录。只在开启摄像头或自检时请求识别资产；角色渲染与试验室本身也按路由加载。
- `predev`、HTTPS 预启动与各构建预处理调用准备脚本。APK 资源已接入准备流程，但 APK 尚未构建或实测。

## 验证记录

- 最终完整单元测试：178 文件、1563 项全部通过，覆盖失跟回放、摄像头迟到授权/位图释放和页面未就绪时的录制限制。
- 最终生产构建与 TypeScript 检查通过。既有大分包/样式与动态导入提示保留，不作为已验证首段速度无回退的证据。
- ESLint 完整检查 0 error、38 warning；生成的头像运行目录现已加入忽略。
- 中英消息成对与漏翻扫描通过：76 UI 文件、2582 对消息。
- 真实浏览器：进入正常 HTTPS 应用；三维角色可见，演示可运行；真实 Worker/WASM 对空白图的模型自检通过；开启真实白板并画出两笔。
- 演示动作录满 60 秒并自动结束，浏览器真实导出 2877 帧 JSON，重新导入、回放至结束、暂停以及定位到 18 秒均通过。[导出证据](avatar-animation-phase-a/browser-demo-track.json) 只含 `demo` 来源，不含真人表情。
- 本机内置浏览器、工程测试角色和暂停回放场景：目标 60 FPS 时观察约 48 FPS；切换到目标 30 FPS 后观察 30 FPS，绘制提交 p95 约 0.4–0.5 ms。这是短时桌面观察，包含已启用白板；不是正式模型、实时捕捉或目标大屏的性能结论。
- 中途全量测试发现 Android 准备脚本入口字符串契约不兼容；改为在原准备脚本内部导入头像准备任务，保持原入口。针对性 30 项及最终全量均通过。
- 摄像头启动操作已触发权限请求，但尚未取得“真实面部跟随”的实测结果，不能记作捕捉验收通过。录制按钮在相机尚未就绪时禁用，停止/卸载会使迟到授权立即释放。
- Swift 纯参数录制模块在 macOS 编译运行，并将其产出的 JSON 送入网页验证器；52 通道清单一致，原生→网页契约通过。
- 三个 Swift 文件语法解析通过，Info.plist 和 Xcode 工程结构检查通过。这些检查不等于 iOS SDK 类型检查、签名、运行或 ARKit 真机测试。

## 已知边界与下一步

1. 本机只有 Command Line Tools，没有 Xcode/iOS SDK。无法编译安装 iOS 应用。后续安装完整 Xcode 后按 [Apple 捕捉验证说明](LEARNER_AVATAR_CAPTURE_IOS.md) 继续。
2. 本机未发现 `adb`/默认 Android SDK platform-tools，目标大屏尚未连接实测；不能确认电视帧率与摄像头兼容性。
3. 当前模型仅由程序生成少量形体来验证驱动；正式星狐需要专业三维拓扑、面部绑定和组合修正。
4. 当前网页可导入 Apple 参数文件，但没有手机实时配对/低延迟传输。
5. 当前片段只是工程验证格式，尚未写入课程 Take 或 `.olesson`，没有原声/TTS 对齐、发音嘴型生成或课程同步。
6. 尚未完成真实人脸、儿童、弱光/眼镜/遮挡、20 分钟持续录课、端到端动作延迟和与 Memoji 的对照。
7. 当前采集使用 CPU Worker；GPU delegate 是否更好要与数学组件竞争资源的结果一起测量。
8. 网页降级提示 WebGL 2 需求；安卓原生捕捉、原生渲染和旧电视视频降级仍待实现。

测试模型演示帧率、空白画面自检和表情数据格式验证，均不能代表正式角色或电视的最终性能。
