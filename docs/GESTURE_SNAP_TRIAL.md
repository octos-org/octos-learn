# 响指手型试验（2026-11-06）

入口：本机正常运行环境 <https://127.0.0.1:5173/gesture-lab>；头像互动试验室增加相同入口。实现放在当前运行的 `octos-learn-studio`，复用既有登录、MediaPipe HandLandmarker、手部模型、摄像头租约与独立线程，不新增依赖或调用云端模型。

## 试用

1. 点击“开始识别手型”，允许摄像头访问，把整只手放进画面。
2. 对比张手、拇指与食指捏合、拇指与中指捏合。黄色点是拇指尖与中指尖；中指捏合稳定 80 毫秒后显示准备手型。
3. 指尖距离按掌部大小归一化并修正图像宽高比，可调松紧。手型命中不是模型给出的准确率或置信度。
4. 可选开启麦克风，试响指、拍手、敲桌、说话。声音门槛越低越灵敏。记录手型次数、短促声音次数和配对候选次数。
5. 停止、离开页面或切到后台时释放本页的摄像头租约、音频设备、工作线程和音频上下文。既有摄像头共享规则继续适用。

## 实际判断范围

- 视觉只识别“准备打响指”时中指尖与拇指尖靠近的启发式条件；食指捏合和张手用作对照。没有训练响指动作分类模型，也没有证明释放动作确实发生。
- 音频在 AudioWorklet 中逐块检查高通后的峰值和相对背景能量，避免依赖摄像头帧率。默认“音量突增”模式在起音时触发，另有“短促声音”严格模式，要求声音在 180 毫秒内结束。不是 ASR，也不是针对说话的 VAD，更不是专门的响指声分类模型。
- 稳定准备手型和短促声音在 ±250 毫秒内配对，联合候选有 600 毫秒冷却。允许声音先到、视觉稍后处理的情况。拍手、敲桌或其他人的声音仍可能误命中。
- 视频与音频只在本机处理，不录制、不保存、不上传。本页不接入课程控制，仅用于观察。

## 滚动与触发反馈修正

用户试用发现页面不能滚动。根因是应用的 `html/body/#root` 统一禁用滚动，试验页最初漏设自身高度和滚动区域；首轮浏览器检查只验证了横向溢出，没有验证实际滚动。已给本页设置视口内独立滚动，触发计数移至摄像头画面顶部，底部状态条显示实时准备手型、延迟与保留的最近触发。真实浏览器新增滚轮检查：桌面和 390px 窄屏均可滚至底部“清空计数”，桌面首屏计数可见，且模型/音频启动和停止设备释放继续通过。

## 声音有输入但不命中的修正

用户确认声音条会动，但声音计数不增加。旧实现默认峰值门槛 0.08、滑杆最低 0.01、只接受 80 毫秒内结束的声音，并且每 50 毫秒仅显示单个音频块的峰值，存在轻声过不了门槛、尾音被过滤和短峰值显示遗漏的问题。这些是代码中确认的限制，尚未采集用户真实音频，因此不把其中某一个宣称为真实环境的唯一根因。

- 默认峰值门槛降至 0.008，最小可调至 0.001；先适应 250 毫秒背景音，再检测相对背景的突增。
- 默认“音量突增”在起音时触发，用于先验证设备和配对；可能把说话也算声音命中。严格模式保留尾音验证，允许到 180 毫秒并继续拒绝持续长声。
- 声音条汇总每个音频块的峰值并缓慢衰减，显示最近峰值、当前门槛以及低于门槛/接近背景/持续太长/已命中的解释。画面上计数统一称“声音命中”，避免把宽松模式误称为专门的响指声分类。
- 工作处理器新增低幅瞬态、低于旧滑杆下限、带尾音、持续声、峰值保留、背景声和 44.1/48 kHz 回归。
- Chromium 使用生成的低幅衰减脉冲（幅度约 0.02）作为模拟麦克风输入，穿过真实 MediaStream → AudioWorklet → 页面回调链路，确认宽松模式计数达到 1，切换严格模式后达到 2；仍验证滚动、模型加载与设备释放。合成音频不代表用户真实响指准确率。
- 本轮全量 227 个测试文件、1,948 项测试通过；构建和本次目录 ESLint 通过。全仓 lint 未重新启动，保留前述未完成边界。
