# 学习白板的隔空手势交互设计

2026-11-06 · 设计提案。范围为普通摄像头下的学生白板 `/board`。现状依据是本地与 `origin/main` 一致的 `bfd0fb00`，实验入口为 `/handwriting-lab`。下文把已有行为、候选设计和准入条件分开记录。

## 一名学生怎样用它

学生想知道直线为什么变陡。她开启隔空输入，前臂靠着桌面，手在摄像头取景框内。移动手，屏上的空心光标跟随；滑块高亮时，捏住滑块就能调整斜率，图像随手变化。她松开手，选「写字」，在旁边写下自己的猜想。写错一笔，移到「撤销」捏一下。再选「框选」，框住自己的式子，看到选区后点「解释这部分」。同一个动作始终有一个可见的对象，老师也能收到她指的是哪一部分。

建议以**移动手来瞄准、捏合来按住、松开来结束**作为首选试验方案。为滑块、笔、选区及命令分别定义按住后的结果。保留学生试过的松握方案作书写对照，默认动作由真人对照结果决定。

Apple 的文档支持这些交互语义。下面的手部锚点、时间窗、按钮尺寸及质量门槛都是针对 Octos Learn 的候选设计。

## 操作由手势开始时的目标决定

开启时先进入「指向」工具，屏上写明当前工具。松开拇指和食指即可移动光标，另外三根手指可自然放松。工具栏固定在白板可达范围内，明确区分按钮和绘图区。首版仅在课程暂停或等待学生、且现有运行时允许输入时提供操作。

| 光标下的目标 | 学生怎么做 | 反馈与结果 |
| --- | --- | --- |
| 空白、文字、图像 | 移动手，停在想看的地方 | 空心指针随手移动，可用于讲题指示。停留只显示焦点；静止多久都不会落笔或发出请求。 |
| 工具栏按钮 | 瞄准「写字」「框选」「撤销」等，轻捏后松开 | 按下亮起，在同一按钮的容差内松开才执行一次。移出可取消，长按不会重复执行。 |
| 空白画布，已选「写字」 | 对准起点后捏住，移动，松开 | 由空心笔尖变为实心，落点固定在捏合前可见的位置。完整轻捏、没有移动时写一个点，支持小数点。写字模式下滑过公式也能批注。 |
| 学生笔迹，已选「擦除」 | 瞄准笔迹，捏住涂过，松开 | 先显示擦除范围，按现有橡皮规则处理学生笔迹，可用原有撤销恢复。 |
| 白板，已选「框选」 | 从一角捏住拖到对角，松开 | 拖动时只显示选框；松开显示选中内容和适用动作。框空时提示重新选。 |
| 已有选区的「解释这部分」「检查并建议」 | 看清选区和动作后，再轻捏该按钮 | 复用当前选区快照和请求处理。该按钮在发送中禁用；继续捏住、双帧或结果返回均不重发。 |
| 课程滑块／可拖几何点，「指向」工具 | 瞄准高亮手柄，捏住拖动，松开 | 锁定该参数或点，实时更新数值或图形；松开按课程已有的步进、约束和任务判定结算。相邻点可扩大命中区；难以区分时提示放大，滑块也能点「＋／−」精调。 |
| 空白画布，「指向」工具 | 捏住后拖动画布；轻捏并松开则停在原处 | 超过移动门槛才开始平移；全过程保持同一视图坐标参考。用显式缩放按钮改变倍率。 |

**一次捏合只交给一个目标。** 工具栏和当前可见的选区命令优先；课程控件仅在「指向」时可操作；其余可写区域交给当前工具。覆盖在画布上的实体控件在写字模式下仍是避让区。拖动滑块经过工具栏，继续控制原滑块；写到工具栏边界，结束在最后合法点。两种情况都要先松开再捏，才能点中另一个目标。课件、遮罩或选区若已变更，旧目标立即失效。

## 让学生知道笔何时落下、何时已经抬起

1. **准备。** 初次体验给一张可跳过的练习卡，只做「移到圆里、捏住画短线、松开移到下一个圆」。光标用手腕和四个指根定位，悬停和书写沿用同一个锚点与镜像。可以用左右手，可把肘放桌上。需要时用两三次自然开合估计个人捏距；开合样本重叠则重试或使用现有输入。校准随时可跳过，鼠标、触摸和手写笔都能完成原有流程，命令按钮保留键盘焦点和激活方式。
2. **准备落笔。** 优先用现有三维关键点算「拇食指尖距离 ÷ 腕到中指根的长度」，图像坐标回退时做宽高比修正。先要求看到明确分开的双指，再允许合拢。第一帧可信的合拢趋势锁住最后的稳定焦点和起点，光标变成带短弧的空心圈。确认前撤回就回到悬停，手指开合本身不能拖动目标。
3. **确认与跟手。** 初始对照可用现有归一化捏距 0.28 合、0.42 开；中间区维持原状态。试验用连续有效样本加时间确认，起笔先比较 50–90 ms，收笔比较 30–60 ms；低帧率仍须至少两个有效观测。确认后从锁定点起笔，显示实心笔尖，再按掌部相对位移移动。小数点走完整的按下和释放，无需跨过拖动距离。漏掉的极短捏合计入测试。
4. **先停墨，再确认松开。** 一旦出现可信的松开趋势就冻结待提交尾段。确认松开，只把松手前的有效点交给笔迹引擎；短暂抖动后重新闭合，同一笔继续。实验中分别比较 50/75/100 ms 尾段窗口，以淡线预览未确认点，实线表示已提交。记录拖尾的同时测量正常短横被截短的长度，防止靠删掉笔尾得到漂亮数字。
5. **中断。** 丢手、越界、长时间没有新帧、追踪位置突跳或输入源换手，立即冻结，在最后可信点结束已开始的笔画。按钮按下后丢手按取消处理。恢复先要看到摊开的拇食指，闭手入镜只能显示准备提示。鼠标、触摸、手写笔可随时接管；隐藏页面、开启模态窗口、切课或播放时暂停。暂停释放采集后，沿用可点击或键盘激活的「继续」重新启动。

光标状态除颜色外也改变形状；必要时在光标附近出现「先松开手指」「手移回框内」。调试页保留骨架和数字，正常学习时只需看到落点、当前工具和摄像头状态。按钮命中区初始试用 56 CSS px，边缘加小幅容差防止焦点来回跳；相邻命中区互斥。这是桌面/电视的试验起点，需按观看距离分别测量。

## 接入现有系统的顺序

| 阶段 | 交付和边界 |
| --- | --- |
| 1 · 修复收笔并验证手形 | 先修复并回归上面复现的漏抬笔，再在实验页并列修复后的「当前松握」和「掌部定位＋捏合」。同样的画布、大小和增益；先只做悬停、画点、画线、抬手。可独立选择用鼠标按键触发落笔、摄像头只负责定位，以区分瞄准误差和手形误差。通过下表的书写门槛后再决定主白板默认；松握若更适合部分学生，作为显式书写选项，单次操作只运行一种开合判定。 |
| 2 · 打通学习闭环 | 在 `BoardHandwritingInput` 的识别与输出之间加目标分派，首批只登记工具切换、撤销/重做、写字、框选和选区通用动作。按钮复用白板命令，笔迹和选框走现有 Ink Runtime；控件内部导向动作，未登记控件继续遮挡。以「写一行 → 撤销一笔 → 框选 → 解释这部分」端到端通过为交付条件。 |
| 3 · 操作课程 | 先开一个已有课程滑块，再开放有明确可拖标记的几何点及画布平移、缩放；随后接入橡皮。滑块走现有 start/update/commit 与 operation ID，几何点走现有变量输入与约束。若运行时无法区分失踪与主动完成，则先支持显式增减按钮，等可取消或可安全结束再开放手势拖动。录课和头像表演另行验证。 |

落地要处理四个现有边界：

- **工具切换与相机移动。** 将「采集是否运行」与「谁正在接收动作」分开。手势点击写字、框选或撤销应结束上一次动作，保持采集并等待下一次捏合。手势自己触发的平移只更新视图，外部平移、缩放、教师镜头或窗口变化则使本次目标失效。保留真实指针优先、后台暂停和代次检查。
- **命中与收尾。** 屏幕坐标用于悬停和按钮命中，笔迹转换仍由 Ink Runtime 处理。每个已派发的按下必须有且仅有一次结束或取消。专测「同一帧松开且浮层出现」：现入口先更新控制器，再判遮挡，遮挡分支会舍弃那一帧返回的动作。分派层须记住实际收到按下的对象，即使它已失焦也能收尾。
- **撤回与提交。** 擦除遵从现有笔迹历史；取消中的选框丢弃临时选框。课程拖动中断要清理排队的更新并结束该次操作，禁止因丢手而提交答案或完成任务。白板按钮直接调用已登记的命令，避免通用的页面模拟点击。
- **提问与图像。** 当前选中笔迹后，白板可后台分类选区；「解释」「检查」会另行发起学习请求。手势悬停与拖框预览只做本地反馈，完成选区后沿用原有分类流程，点名具体动作后才提问。沿用共享摄像头和现有使用权限，手势识别在设备上完成，「给老师看画面」由其独立入口控制。

## 用什么证据决定上线

先在同一设备上做交叉对照，轮换方案顺序。首轮建议 8–12 位试用者，覆盖目标学龄、不同手大小与惯用手；桌面先跑通，再单列 Android 大屏／电视摄像头结果。每人每方案做 20 次有指定起止点的短笔画（含小数点、等号、分数线），再写两行算式；另做 2 分钟只指不写、贴近边缘、遮挡后闭手回场、换手和低照度任务。用指令标记或经同意的本地侧录对齐动作与画面，分别记手形、落点、视觉反馈和操作结果。普通使用无需留存视频。

| 项目 | 候选准入条件，均为目标值 |
| --- | --- |
| 空移误落笔 | 每人每方案报告次数与暴露分钟，目标整组合计每 10 分钟至多 1 次；闭手回场、跨遮挡或跨会话续线均为 0。 |
| 写字的起止 | 至少 95% 意图笔画首次产生恰好一笔；分别报告漏起、假断、意外连笔和漏点。在笔画任务的固定显示比例下，起点偏移与抬笔拖尾 P95 各 ≤ 目标字格边长的 10%，并报告短笔截断量。 |
| 可感知延迟 | 从人工标定合拢到首个已确认墨点、从开始松开到画面停止延伸，两项 P95 暂定各 ≤ 150 ms。另列从抓帧到屏显的延迟；按实测采样率分组。 |
| 命令与学习任务 | 第一次点中预期按钮 ≥ 95%；每个发送动作最多产生一次提问，越过按钮、丢手或取消导致的误发送为 0。至少 90% 的试用者能在一次简短教学后独立完成「写式子 → 改一笔 → 框选并提问」；第三阶段加测把滑块调到题目指定值且只结算一次。 |
| 舒适度与决策 | 每轮结束记录手臂疲劳 0–10 分、需要重新准备的次数及偏好。按人、设备和主要失败类型列出原始计数及分母。候选先过绝对门槛，且误落笔和起止错误合计率较原版降低、疲劳中位数不升，再扩大试用；设备分别准入。小样结果用于选择下一版，推广前补测目标人群。 |


## 第一批实现与验证 · 2026-11-06

实现分支为 `codex/air-gesture-interaction`，基于最新拉取的主线 `bfd0fb00`，独立工作目录为 `octos-learn-air-writing`。录课 agent 使用 `octos-learn-studio`；本轮仅在自己的目录修改。语言新增项放在既有手势条目旁，减少与录课文案的合并冲突。

已接入正式 `/board` 的实验功能入口。开启后先进入浏览，默认试用掌部定位与捏合；暂停后可切回原松握方案。实验页也保留新旧对照。捏合按掌长归一化，有开合滞回、60 ms 准备／落笔确认和至少 40 ms 松开确认，共用掌部相对定位、过渡锁点与原有 100 ms 笔尾缓冲。新旧方案均为实验候选，下一步仍需按上表真人对照决定默认动作及参数。

正式界面有可见焦点与按下反馈，笔尖通过实心／空心及虚线圈区分操作状态。手势可切换浏览、画笔、橡皮、框选，点击撤销／重做、选区通用学习动作和课程参数加减。浏览下可拖动画布，控制面板可缩放。原选区、请求防重与笔迹自动保存继续承担相应操作。按钮释放前丢手、移出、禁用或卸载均取消该次按钮动作；笔画跨遮挡不能转成按钮点击。

漏抬笔现由实际事件接收端负责配对收尾。即使控制器已结束笔画而本帧进入遮挡，接收端仍会收到一次抬起。另一项浏览器发现的问题也已修复，ResizeObserver 初始通知在尺寸未变化时不会暂停刚启动的输入。手势自己平移时维持采集；空闲时收到异步视图通知会清除定位参考并重新准备，正在书写时外部视图变化仍暂停输入。手势关闭和暂停命令后会拒绝当前帧余下回调，避免光标重新出现。
