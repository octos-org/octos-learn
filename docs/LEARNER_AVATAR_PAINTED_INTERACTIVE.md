## 画面与接入

1. **统一画稿**：沿用前一轮 512×512、眼线转正的同一张原始插画面肩裁剪。没有采用被用户否定的独立头/躯干/双臂拼接图，也没有逐帧重新生成整张脸。画稿本身仍有轻微非对称，耳尖位于裁剪外；本轮没有声称得到新的全身正面立绘。
2. **连续眨眼**：`painted-eyes.ts` 将原图与局部底画的差分分配给眼皮/眼球，固定眼球采样坐标，改变上下眼皮的遮挡和曲线。从自然睁眼开始连续重建，修复上一轮“原图切到重画眼睛”的跳变。没有单独实现视线移动。
3. **嘴型**：`painted-fox.ts` 分开连续变形原画闭唇线上下部分，用同画风口腔素材填充逐渐露出的内部；圆唇、微笑改变宽度与嘴角。闭唇通道压制张颌。微开口不再突然切换 PNG，也不同时保留旧嘴角。当前仍以一种口腔绘画素材衍生基本口型，不能宣称音素级发音准确。
4. **眉毛**：小范围移动原画眉线差分，保留画风；不是重新绘制卡通眉毛。
5. **头部**：14×14 纹理网格做浅层偏转、点头和侧倾，颈部权重渐变到零、衣服下部与图像边界保持稳定。使用统一的逆向像素采样，避免三角形 Canvas 抗锯齿缝和中性重绘跳变。这是有限画面视差，**不恢复隐藏侧面，不是三维头部旋转**。
6. **原有流程**：`IllustratedAvatarStage` 改为加载四份 `painted-v0.1` 素材（约 1.3 MiB），同时影响试验室与其中的配音试听/固定示例共享舞台。既有 `FaceCapture`、`FaceSmoother`、校准、失跟归位、停止/退出释放、片段格式和账号隔离继续使用；没有给课程生成增加模型往返。完整课程中的旧三维角色未在本轮替换。
7. **当前范围一致**：撤下暂缓的手臂预设、身体滑杆与身体捕捉开关；普通摄像头调用 `start()`，不请求姿态或手部模型。历史 v2 身体片段仍可读取，其身体通道被当前面部绘制器忽略。新增圆唇滑杆，默认目标改为 30 FPS；60 FPS 仍可显式选择，不能把选项目标当成实测帧率。

素材与来源、提示词、哈希在 `public/teach-avatars/star-fox/painted-v0.1/asset-info.json`。图像生成发生在前一轮素材准备，本轮没有重新生成形象或调用付费模型。制作脚本使用既有可选的原生 Canvas 依赖，没有新增产品依赖。

## 实际检查与结果

### 图像、组合与录制回放

[像素检查](avatar-animation-phase-a/painted-v0.1/render-report.json)实际运行产品绘制器，非模拟 Canvas 调用：

| 检查 | 结果 |
|---|---|
| 自然状态与同位置源图、复位、非法数值归位 | 最大逐通道像素差 0。 |
| 只张嘴时的嘴部区域以外 | 最大像素差 0。 |
| 张颌 1 + 闭唇 1 | 与自然闭嘴像素差 0。 |
| 八种正负极限头部组合 | 没有网格折叠；画稿内部 alpha 最小 255；画稿下部衣服像素不变。 |
| 极小输入连续性 | 开口/圆唇/微笑/眉毛 0.0001 最大差 0，左右闭眼最大差 1；头部三轴同时 0.0001 为 5，0.000001 为 0。只描述接近中性的连续性，不是质量评分。 |
| 合成记录的序列化回放 | 七个已记录时间点，实际绘制像素差 0，见[往返报告](avatar-animation-phase-a/painted-v0.1/round-trip-report.json)。 |
| 媒体 | 实际解码 160 帧、536×536、20 FPS 的 MP4；GIF 实际时长 8000ms，见[媒体检查](avatar-animation-phase-a/painted-v0.1/media-report.json)。 |

初次头部网格输出出现半透明缝隙、衣服下部有 21 档像素差、中性趋近仍有 15 档差；修复为逆向统一采样后按上述检查重新通过。保留这项失败原因，不用肉眼连续或测试全绿掩盖它。衣服检查范围是目标画面 y≥420，不能外推为所有衣领像素均固定。

### 真实浏览器与未完成的边界

在浏览器可用时，正常 HTTPS 5173 的既有本机免密码登录后，实际看到新绘制器并点击“微笑开口”，保存了上面的截图。随后刷新最新代码、开始连续演示，实际点击录制；录满 60 秒自动结束后点击回放，界面进度从 0.0 到 0.2 / 60.0 s，按钮变为“暂停片段”。这是实际合成动作录制和回放，不是将参数测试冒称为真人。

一次短时读取显示 **30 FPS、绘制提交 p95 11.0 ms**。它仅代表当时这台桌面电脑的浏览器演示，不含摄像头采样/识别延迟，不代表长期性能、Android 电视帧率或跨设备保证。

前一双眼阶段已在浏览器完成相同本机 Worker / 模型对空白图的推理自检，确认无人脸；本轮在原入口也点击了自检，但只观察到加载提示，后续浏览器连接超时，当前工具明确报告本地浏览器控制被 Work 设置关闭。**没有看到这次自检最终成功状态，未完成最终页面重跑、真人跟随、真实权限拒绝/恢复、音频听音或 iPhone/Android 大屏验收。** 没有更改设置、另起浏览器环境或绕过控制限制。

本轮后来修复的“手动滑杆变化提前结束录制”通过实际 React 回归测试验证，关闭浏览器控制后未再点击复测。既有权限拒绝、迟到授权释放、摄像头帧传递与平滑参数记录仍由对应测试覆盖，不能视为实际真人效果。

## 复现

先按项目正常开发约定使用已有 Node 22 与依赖；无需启动新端口、新账号或付费推理：

```sh
node_modules/.bin/vite-node scripts/export-painted-fox.ts /private/tmp/octos-2d-preview scratch/avatar-painted --animation
scratch/avatar-single-image/venv/bin/python scripts/encode-painted-fox.py
pnpm test:unit
pnpm build:public
pnpm check:i18n
```

原生制作用 `@napi-rs/canvas` 的路径可换为准备好的其他 tools 目录；Python 编码使用已有 Pillow / NumPy / imageio / ffmpeg 环境。这些只用于复现实验媒体，不是用户运行应用的前置依赖。

## 交付判断与后续

本轮“在原有入口交付可操作、可录制回放的统一原画风二维版本”已实现并完成当前可进行的验证。**这不等于最终美术验收、正式 Live2D 绑定、全录课社区链路或电视适配已完成。** 头部只有小角度视差，口型仍是基本衍生形状，耳朵/头发物理、视线和手臂没有实现；用户尚未实际评价这次整合效果。后续优先做最终浏览器复核及真人自然讲话/快速眨眼/侧身书写的质量检查，再决定是否需补口腔、眼皮素材或更完整的正式绑定。

当前不要求用户立即操作、测试设备或再次批准继续。此前反复在局部结果处结束属于执行问题；已建立跨轮持续目标，但上一轮该目标实际触及平台用量限制（状态 `usageLimited`）。本轮用户再次要求继续后按直接指令完成剩余工作；没有谎称目标机制可绕过额度，或把用量停止当成目标完成。
