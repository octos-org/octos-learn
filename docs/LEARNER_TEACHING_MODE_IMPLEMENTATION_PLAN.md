# 学生当老师模式：实施计划

日期：2026-10-31。状态：计划草案，待用户确认。产品方案见[学生当老师模式计划](LEARNER_TEACHING_MODE_PLAN.md)；OLL 样例与发现见 `octos-lesson-language/docs/LEARNER-TAUGHT-V1-FINDINGS.md`（分支 `claude/learner-taught-samples`）。

## 1. 最终目标

孩子可以完整地**创建、录制、发布**自己的课程：

1. **创建**：任选主题，规划卡片；
2. **录制**：逐张卡片边讲边画、使用互动组件，单张重录，小章鱼在卡片之间提问；
3. **检查**：用自己的形象和合成声音回看，按卡片得到反馈并修改；
4. **发布**：保存到“我的课程”；经家长或老师批准后分享给家庭或班级；最终（如果决定做）发布到公开社区；
5. **观看**：观看者以真实 OLL 课程播放，暂停后可以自己操作组件，课后可以做“轮到你了”练习。

“完全可用”的判定：上述五步在目标设备上端到端可用，全部数据边界（同意、可见范围、删除）在服务端强制执行，课程播放不依赖观看者的 Key。

## 2. 已确认的决定

| 日期 | 决定 |
|---|---|
| 2026-10-30 | 面向美国 K–12；用虚拟形象和合成声音保护未成年人隐私 |
| 2026-10-31 | 任意主题都可以讲；主题类型只影响帮助、检查、星图和分享范围 |
| 2026-10-31 | 互动组件是录课的一等工具，插入面板为主要入口 |

## 3. 总体架构

```text
           ┌──────────────── octos-learn 前端 ────────────────┐
 孩子 ──▶  │ 录课工作室                                        │
           │  卡片规划 · 录制器 · 插入面板 · 笔迹 · 回看检查   │
           │      │ 录制文档（卡片/录制/带时间操作/转写）      │
           │      ▼                                            │
           │  录制编译器（确定性，纯 TS）──▶ OLL Authoring     │
           │      │ OLL Core：校验 · 规范化 · Reducer          │
           │      ▼                                            │
           │  OLL Web Runtime（录制时实时显示 = 回放）         │
           └──────┬───────────────────────────┬────────────────┘
                  │ 技能动作（BYOK 模型）     │ 提交课程包
                  ▼                           ▼
        learning-coach                 services/learner-lessons（新）
        小章鱼追问 · 检查反馈 ·         课程包存储 · 状态机 · 可见范围 ·
        整理识别 · 请小章鱼画           批准队列 · 观看 · 反应
                  │                           │
                  ▼                           ▼
        Octos（认证 · profile ·        learning-history（星图“讲过” · 成就）
        会话 · 文件 · 模型配置）
```

关键设计：

1. **录制时看到的就是回放的内容。** 录制器以 OLL Authoring 文档为编辑真源：孩子每个操作立即追加为当前卡片 Beat 中的动作，经 OLL Core 规范化后由同一个 Web Runtime 显示。重录一张卡片 = 替换该 Beat 后重新规范化并重放。不存在“录完再转换、转换后变样”的第二条路径。
2. **编译器是确定性代码，不是模型。** 模型只负责小章鱼追问、检查反馈、整理识别和“请小章鱼画”，结果都要孩子确认才进入课程。
3. **课程包自包含。** 提交时预先生成每个 Beat 的 TTS 音频，与 Canonical OLL、笔迹快照、形象引用一起存为课程包；观看者播放时不调用模型、不需要 Key。
4. **产品专属逻辑留在 octos-learn。** 分享、班级、批准、审核都是产品逻辑，放在新的 `services/learner-lessons`（Node + SQLite，与 learning-history 相同模式）。只有通用能力确实缺失时才改 Octos。
5. **AI 课程不受影响。** 本模式是独立入口；不改变 AI 课程生成链路，不增加其模型往返，满足 AGENTS.md 首段速度门槛。

M0 实际范围比计划大。原以为是一个回退，复核发现所有正向样例都在失败，原因多在检查本身（字体时序、过时的卡片宽度门槛、不随缩放的字号指标、Harness 与产品排版不一致），另有一个真实的产品问题：小屏幕上多卡片同框时镜头缩得过小。用户决定：课程进行中必须可读、结束全览不要求；检查 1366 × 768 与 1920 × 1080；正文屏幕字号门槛 12.5 px；在 M0 修复。修复后五个正向样例两种尺寸全部通过，9 门已发布课程在真实应用中课程进行中正文均 ≥ 12.5 px（一处已记录的例外）。详见 OLL `docs/PLAYBACK-GATE-REVIEW-2026-10-31.md` 与应用 `docs/course-runtime-quality/readable-camera-2026-10-31/REPORT.md`。

M1 说明：四项决定记录 0005–0008 经用户批准后实现；替换改为放置关系 `replaces`（行为不变）。笔迹快照通过宿主的资源解析器提供，可附带 SVG 用于笔画重现，Runtime 只保留绘图元素。应用侧使用 0.6 能力前需要升级 OLL 依赖，并让资源解析器提供笔迹快照。

对学生讲课模式的影响：M3 的提交前检查直接复用这套检查（两种白板尺寸、12.5 px、无法同框时逐张取景的规则）。

## 4. 里程碑

规模记号：S 约 1 周以内、M 约 1–3 周、L 约 3–6 周（单人估计，不含审查等待）。

### M0　测试基础修复（OLL）· S

后续每一步都靠浏览器教学播放检查判定，必须先让它可靠。

- 修复数学卡片刚写入时间歇性 `G3_CONTENT_OVERFLOW`（斜率样例 5/10、quadratic-v2 3/4）：定位测量时序（预计在 KaTeX 字体就绪前测量），在 Runtime 修复并加回归测试；
- 定位并修复 `quadratic-v2` 在 `main`（2b25c43）上稳定失败（4/4，`G3_FOCUS_TOO_SMALL`），二分查找引入提交；
- 独立分支和 PR，不与学生讲课功能混合。

验收：两个学生讲课样例和全部现有正向样例连续 10 次通过；完整测试套件通过。

### M1　OLL 合同扩展（OLL）· L

四份决定记录，每份附学生讲课样例作为回归证据；全部为新增能力，通过执行版本协商门控（与 `geometry:regular-polygons` 相同机制），旧客户端明确拒绝而不是静默忽略。

| 决定记录 | 内容 |
|---|---|
| 学生讲课课程 | `mode: "learner_taught"`；`lesson.author`（学生档案引用，不含真实姓名）与播放形象/音色引用；该模式下 AI 老师人格与 AI 课程专用行为不生效 |
| 学生笔迹 | `kind: "ink"` 引用冻结的选区快照（v4：SVG、范围、SHA-256），按笔画顺序重现；两种归属：自由批注（独立节点，参与自动布局）与组件上的标注（附着在组件上，跟随组件）；笔迹编辑动作 `replace` / `hide` / `erase`，**仅限 `learner_taught` 模式**，修改 AUTHORING §10、OLL-INP-001、OLL-BRD-008 的适用范围说明 |
| 内容来源 | `write.source`：由哪个选区派生、由孩子确认 |
| 3D 视角意图 | 课程内视角动作，表达“转到能看到某个面/高亮部件”或预设视角，不写原始相机数值（符合 OLL-VIEW-002） |

实现范围：Authoring/Canonical schema、语义校验、规范化、Reference Reducer、Player Core、Web Runtime 渲染与回放、能力协商、conformance fixture、降低动态效果行为。

验收：`lesson.proposed.json` 改写为正式样例并通过 `check:examples`；两个样例 + 一个新增 3D 样例在 Chrome 教学播放中稳定通过；AI 课程（`explain` 模式）使用笔迹编辑动作时被校验器拒绝。

### M2　录课工作室：录制器（octos-learn）· L

可以与 M1 并行起步：先用 v0.1 已有能力（组件、变量、动画、任务）做无笔迹版本，M1 合并后接入笔迹。

- **入口与主题**：大厅新增“我来讲”；任意主题输入，按主题类型分类（星图已点亮 / 星图未点亮 / 数学非星图 / 其他）；
- **卡片规划**：3–6 张卡片、模板、重命名、排序；
- **录制**：单键录制/停止；语音采集复用现有 `src/home/voice` 采集与 ASR 路由；卡片停止后转写，显示可修正字幕；
- **工具**：笔、荧光笔、激光笔、箭头、橡皮、“整理一下”、➕ 插入面板（函数图、坐标网格、单位圆、数轴、图形、3D 立体与曲面、表格）、点工具与自动标签、“画出图像”“变成点”、“轮到你了”；
- **笔迹**：复用 OLL Ink Runtime；笔迹属于卡片，讲述与指点属于某一次录制；卡片停止时冻结选区快照；
- **录制文档**：卡片、录制版本、带时间操作、ASR 原文与修正文本；本地可恢复存储（复用 `recoverable-storage`）并同步到服务端草稿；
- **单张重录**：替换该卡片的讲述与指点，保留笔迹（孩子也可以擦除重写）。

验收：Jordan 与 Riley 两个样例可以在真实界面中完整录出，导出的课程与手写样例在语义上一致（同样的节点、绑定、动作阶段）。

### M3　录制编译器与提交前检查（octos-learn）· M

纯 TS 模块，前端和 `services/learner-lessons` 共用（服务端在发布时重新校验）。

- 动作阶段：按操作时间与讲述区间确定 `before_speech` / `during_speech` / `after_speech`；
- 拖动分段：在方向反转或停顿 ≥ 300 ms 处切分，每段一个 `animate`，按时长选 `brief` / `normal` / `extended`；
- 变量：插入组件时声明课程变量和 binding（“与 θ 联动”在插入对话框中选择）；
- **结束焦点**：优先选一个可读目标；多目标仅在彼此相邻时使用；
- “轮到你了”：孩子演示后从已绑定读数中选择检查对象，生成课后任务（目标值、容差、口述提示）；
- 提交前检查：OLL 校验 + 在客户端用 Web Runtime 的教学观察评估（`evaluateTeachingObservation`）逐 Beat 检查可读性，不通过时自动调整焦点，仍不通过才提示孩子。

验收：编译器单元测试覆盖每条规则；两个样例的录制文档编译结果与手写样例 golden 一致。

### M4　小章鱼与检查（learning-coach + octos-learn）· M

全部使用账号本人的 Key（BYOK），不在 AI 课程首段路径上。

| 技能动作 | 时机 | 输出 |
|---|---|---|
| 小章鱼追问 | 卡片之间；在孩子录下一张时预取 | 1 个问题（K–2 更短）；回答只进私有学习记录 |
| 整理识别 | 圈选后“整理一下” | LaTeX 候选，孩子确认/修改后生成 `math` 节点并原位替换 |
| 请小章鱼画 | 孩子语音请求 | 一个 OLL 组件节点建议，孩子确认后放上白板 |
| 课程检查 | 回看后 | 按卡片的反馈：星图主题做正确性检查；数学非星图标注较低置信度；其他主题只检查清晰度；对照手写快照、整洁版本和讲述，区分口误与理解错误 |

验收：每个动作有离线评测集（含儿童风格输入）；检查反馈在样例上能指出 Jordan 卡片 3 的错误并判定为口误；记录每个动作的延迟与费用。

### M5　声音、形象与隐私处理（octos-learn）· M

- **儿童形象**：独立的一套（小章鱼主题或风格化生物），不复用成年老师角色；按现有美术流程出图；
- **音色**：若干适合儿童课程的 TTS 音色；提交时按 Beat 预生成音频（作者账号 Key）；
- **个人信息去除**：转写文本先用确定性规则（姓名、学校、地址、电话、邮箱等模式），再由模型检查，命中项提示孩子修改；
- **原始语音**：转写完成后删除；不上传、不保存视频；
- **课程包**：Canonical OLL + 笔迹快照 + 预生成音频 + 形象/音色引用 + 内容哈希。

验收：发布的课程包中不含原始语音和真实姓名；去除规则有测试集；离线播放课程包不调用任何模型。

### M6　我的课程、播放与奖励（octos-learn）· M　→ 第一阶段完成

- `services/learner-lessons`：课程包存储、状态机（草稿 → 已提交 → 已批准 → 已发布 → 已撤回）、删除与导出；
- “我的课程”页面；观看页：OLL Runtime + 儿童形象 + 预生成音频，暂停后可操作组件，课后练习；
- learning-history：新增“讲过”事件；星图“讲过”外环；成就（第一次讲课等），全部在录制和检查结束后颁发，不打断讲课。

第一阶段验收（教小章鱼，仅自己可见）：在目标设备上完成 Jordan 与 Riley 两堂课的创建 → 录制 → 检查 → 重录 → 保存 → 回放全流程；Playwright 端到端测试覆盖。

### M7　账号、同意与班级/家庭分享 · L　→ 第二阶段完成

- **年龄与同意**：注册时记录年龄段；13 岁以下需可验证的家长同意（COPPA）或学校代为同意（教育用途）；同意记录可查询、可撤回；
- **家长账号**：与孩子账号关联，查看、批准、删除孩子的课程；
- **老师与班级**：老师账号、班级、班级码；学生加入班级需老师或家长批准；
- **分享范围**：私有 / 家庭 / 班级，服务端强制执行；
- **批准队列**：课程分享前由家长或老师批准；
- **观看者互动**：只有预设反应，没有评论、私信、关注；
- **FERPA**：学校场景下课程作为教育记录处理：访问控制、导出、删除、保留期限；
- 角色、班级、批准都在 octos-learn 产品服务中实现；若需要跨 profile 读取等通用能力，再评估 Octos 改动。

验收：权限测试覆盖每个角色 × 每个可见范围；未批准课程对他人不可见；撤回同意后孩子的分享内容立即下线；法律顾问审核同意流程与隐私政策。

### M8　公开社区 · L　→ 第三阶段（需单独决定是否做）

开工前置条件：法律审核（COPPA、各州儿童隐私与适龄设计法规）、审核人员与运营安排、费用评估。

- 公开目录、按主题浏览；
- 审核流水线：自动检查（正确性、个人信息、安全）+ 人工复核队列 + 举报 + 下架；
- 13 岁以下公开发布的额外要求；
- 存储与流量费用由平台承担，需要预算。

### M9　K–2 图卡模式 · M（第一阶段之后）

固定三张图卡模板、语音提示、印章工具、无转写编辑；原始语音只私有保留，不分享。前置条件：确认有足够 K–2 数学内容。

## 7. 主要风险

| 风险 | 应对 |
|---|---|
| 儿童语音 ASR 准确率低 | 字幕修正为必经步骤；K–2 不依赖转写 |
| 触屏书写手感（延迟、掌触） | 早期在目标设备上验收 Ink Runtime；必要时调整默认值 |
| 录课流程对孩子太长 | 卡片短录制、单张重录；第一阶段收集完成率数据 |
| 合规成本超出预期 | 第二阶段先做班级范围（学校代为同意）；公开社区单独决策 |
| OLL 合同变更影响 RC 冻结 | 全部为新增能力并经执行版本门控；每项有决定记录和回归证据 |

## 8. 需要用户决定的事项

| 编号 | 事项 | 建议 |
