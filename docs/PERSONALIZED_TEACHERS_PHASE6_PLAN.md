## 2. 交付顺序（S6-01）

三项逐项交付，每项验收后再开始下一项。列入计划不等于自动开启。

1. **学习周报**：几乎全部由程序从事实计算，正确性最容易保证，也不需要后台任务和模型费用。
2. **主动学习建议**：依赖周报同样的事实和前置关系；风险在于措辞（“没有记录不等于不会”），可以先用固定规则和台词实现。
3. **月考试卷**：题目正确性、判分和讲评都需要模型和严格检查，风险和费用最高，最后做，届时另写详细方案并申请预算。

## 3. 学习周报（S6-03）

### 3.1 周期与时区

- 一周为学生本地时间的周一 00:00 到周日 24:00，时区由客户端提供（与学习地图相同）。
- 周报在打开“学习记录”时按需计算，不预先生成、不定时推送。因此第一版不需要后台任务，也不会因为后台失败而缺一周。
- 可以翻看过去的周报。删除某节课或某段学习后，相关周报跟着变化，与成就撤回规则一致。
- 月报与周报用同一套计算，只换周期；周报验收通过后再加。

### 3.2 内容（全部来自程序计算）

**发生过的学习**（只描述事实）：

- 本周学习了几天、几节课、播放了几段讲解、做了几次练习、提了几个问题。
- 学过的知识点列表，按学科和领域分组，中文名沿用学习地图。
- 本周新获得的成就。

**有证据的变化**（只写状态变化，不写“进步”）：

- 本周新点亮的知识点（从“暂无记录”变为任一状态）。
- 本周状态提升的知识点，例如“正在练习 → 做出来过”，并列出对应的那次练习作为依据。
- 只列状态变化本身。不写“进步了”“掌握了”“比上周更好”，因为目前的事实不足以支持这些判断。

**不写的内容**：

- 学习时长。播放时长不等于专注时长，容易误导。
- 与其他学生的比较、排名、分数。
- 对没学的内容做负面描述，例如“本周没有学习几何”。没学就不出现。

### 3.3 老师的话

- 默认：标题和结尾各一句当前老师的固定台词（与成就颁发语同一做法），随语气开关切换为普通说法。不调用模型。
- 可选（默认关闭）：由老师用自己的语气写两三句评语。评语只能引用报告里已有的事实，由程序检查不出现“掌握”“进步”等词，失败时退回固定台词。每份周报约一次模型请求，开启前需单独确认预算和真实模型质量验证。

### 3.4 给谁看、在哪里看

- 推荐第一版只在应用里给学生本人看：“学习记录”页新增“周报”标签。
- 家长视角涉及账号关系、授权和隐私，目前账号体系中没有家长身份，建议作为独立后续事项，不在第一版做。
- 不发推送通知、不发邮件。是否需要“每周一提醒有新周报”放到 S6-05 统一设计。
- 关闭方式：学生可以在设置里隐藏周报标签，隐藏后不计算、不显示。

### 3.5 示意

```
周报 · 10月13日–10月19日                         ‹ 上一周
豆豆：这周的地图又亮了两盏灯，来看看！

学了 3 天 · 4 节课 · 播放 18 段 · 练习 6 次 · 提问 2 个

新点亮
  数学·代数  一次函数图像        已探索
  数学·代数  斜率是变化量之比    正在练习
状态变化
  数学·代数  一次函数的参数      正在练习 → 做出来过（10月17日，不用提示达到练习要求）
新成就
  亲手搞定

这些记录说明你学过、练过什么，都不等于已经掌握。
```

## 4. 主动学习建议（S6-02，周报之后）

- 依据只用程序可验证的两类事实：前置关系（目录里的 prerequisite）和地图状态。例如“一次函数图像”正在练习，而它的前置“坐标系”只是已探索，就可以建议先回看坐标系。
- “回顾”只基于学生自己学过的内容和间隔天数，措辞为“隔了一段时间，要不要回顾一下”，不说“你可能忘了”。
- 没有记录的知识点只作为“可以去探索”，不说“你还不会”。
- 每次最多给 1～3 条，可以跳过或拒绝；拒绝的建议一段时间内不再出现，并作为学生选择保存。
- 第一版只在学习页或周报末尾显示，不主动打断正在上的课。
- 具体规则、台词和界面另写小节，周报验收后提交审阅。

## 5. 月考试卷（S6-04，最后）

只列边界，详细方案在前两项完成后另写：

- 范围只取本月有“正在练习”或“做出来过”记录、且知识点对应关系已确认的内容。对应关系不确定时不出题。
- 题目需经过与课程相同的数学正确性检查；判分优先用程序可判定的题型（数值、选择、图像参数）。
- 考试结果作为新的学习事实保存，可以更新地图状态，但同样不等于“掌握”。
- 每份试卷涉及多次模型请求，执行前单独申请预算。

## 6. 后台执行与费用（S6-05）

- 周报按需计算，第一版不需要后台任务。
- 将来需要定时任务（提醒、试卷生成）时，复用 Octos 的定时任务和后台任务能力，要求：按账号去重、失败后补做一次、记录执行结果、设每日费用上限。不在 Learning Coach 中另建语义记忆或调度流程。
- 本阶段不开启任何定时任务；开启前需要用户明确授权。

## 8. 实施步骤（周报）

1. 服务端：`report.mjs` 按周期和时区汇总事实、状态变化和成就；`GET /report?period=week&start=…&utc_offset_minutes=…`。规则版本 `report-v1`。
2. 测试：跨时区周边界、删除事实后的变化、状态提升的依据、没有学习的周、目录或对应表升级。
3. 客户端：“学习记录”页新增“周报”标签，可翻看上一周，可在设置中隐藏。
4. 老师台词：`teachers.ts` 增加周报开头和结尾的固定台词，以及普通说法。
5. 顺带修改：给老师的学习地图说明加一句“做出来过只表示做对过一次，不要说成总能做到”（阶段五验证中发现豆豆措辞偏肯定），在下一次付费实验中验证。
6. 验收（S6-06）：用真实学习记录核对周报数字；确认报告中没有“掌握/进步”等措辞；确认周报计算不影响正在上课。
