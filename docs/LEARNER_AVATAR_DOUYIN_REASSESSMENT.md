## 后续选择更新：用户否定 DeepAR 的价格与外观

用户看过官方静态图后认为收费且效果不满意。**下文 DeepAR 作为第一候选的建议已撤回**，保留原调研依据供追溯；未安装或购买。

用户已授权先筛选成品。最新三组真实角色图、作者动作来源、费用与许可状态见[现成角色初筛](LEARNER_AVATAR_CHARACTER_SHORTLIST.md)；仍未安装运行时或选定正式资产。

新的优先候选是：**现成的丰富表情 VRM 角色 + 项目已有 MediaPipe 捕捉 + Three / three-vrm 渲染**。这是选型建议，尚未找到用户认可外观并通过验证的正式资产。

- [pixiv 的 three-vrm](https://github.com/pixiv/three-vrm) 使用 MIT 许可，运行库无需按活跃用户付费。角色资产的费用、商用与网页分发许可独立判断。
- [VRM 表情规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/expressions.md) 包含基础情绪、五种元音、眨眼与自定义表情。**支持 VRM 不代表有 ARKit 52 通道**；优先筛选真正包含丰富口、眉、眼、颊形变的角色，并检查组合表情，不能只看“Perfect Sync”标签。
- [Kalidoface 3D 原项目](https://github.com/yeemachine/kalidoface-3d) 可作为网页摄像头驱动 VRM 的参考，不是本项目实测，也不应直接复制其旧捕捉依赖。
- 找到作者提供的 [Free-to-Use Daemon](https://booth.pm/en/items/3817866?registration=1)：页面列明 52 表情通道、免费、署名条件下可商用/修改/再分发，禁止转售。这是资产可获得性的实例，**不等于已选定适合儿童的外观**；需进一步检查服装、模型内容、包内条款及运行效果。
- 排除不适合分发的“免费”资产：Miyamaru 明确禁止法人和个人商用；フロウ页面同时存在禁止再分发及页面私有状态提示，即使允许游戏/应用嵌入，也不能直接当作可随网页发送的正式资产。

第二候选是 **专业绑定完成的 Live2D 角色 + Cubism Web**。可先比较 [Haru、Hiyori 等官方样例](https://www.live2d.com/en/learn/sample/) 的成品质量；不重新自行切图和绑定。它适合细腻插画风及有限角度的头部转动，仍不等于真正三维侧脸。

[Live2D 官方许可](https://www.live2d.com/en/sdk/license/) 允许在同意条款后无初始费用验证；正式发行需依据应用类别、规模和素材分别判断。尤其 [Expandable Applications](https://www.live2d.com/en/sdk/license/expandable/) 对个人和小企业也有单独要求，不能承诺本产品正式接入必然免费。

两条候选均需先展示真实现成角色外观及原有连续动作，不把技术名称当作质量保证。优先验证 VRM 的张嘴行程、侧面轮廓、组合表情及最终配音回放；下文匿名输出、课程时钟、包格式和电视验证要求继续有效。

## 首轮商业 SDK 调研结论（历史候选顺序已撤回）

用户最新选择：**“先用现成的完整虚拟角色，优先效果和匿名。”** 手臂暂缓，不要求第一版就是星狐。

建议路线：**专业制作并完整绑定的现成角色 + 成熟的表情捕捉/动画系统**。先以 DeepAR 的现成角色作为低成本验证候选，Banuba 的表情角色作为备选。供应商尚未最终选定，不能把公开示例当成接入验收结果。

暂停继续打磨当前单图星狐变形器。保留其代码和资产供对照，第一轮不再生成新星狐、不自行建模、不做手臂、不重做课程流程。

这里可以采用 3D：用户之前否定的是我们制作的粗糙三维效果；本轮改用已经完成建模、材质和表情绑定的角色。**更换 SDK 本身不会自动改善劣质模型**，需要把角色和驱动系统一起比较。

## 抖音线索能确认什么

仅凭用户截图，无法确定具体特效名称、版本或算法。不要声称已还原该特效。

字节的官方工具中确实存在两种不同能力：

- TikTok Effect House 的 [Cartoon](https://effecthouse.us.tiktok.com/learn/guides/workspace/objects/generative-effects/cartoon) 被归类为生成式特效，对输入人脸进行卡通化。这证明这一类方案存在，不能据此认定用户的抖音截图就是同一实现。
- 火山引擎的 [Animoji 定义](https://docs.volcengine.com/docs/intelligent-beautification-effects/product-quotation?lang=zh) 是捕捉人的细微表情，驱动已有角色。

按本次选择，应重点验证第二类。固定角色不必保留儿童真实脸型、发型和服装；但只有完全不输出真实摄像头画面、使用最终合成声音，才能满足本项目的匿名呈现目标。表情/动作参数也不能自动视为完全匿名数据。

转头时，完整三维角色依靠几何旋转、遮挡关系和侧面模型生成画面，不需要横向扯动一张正面立绘。丰富表情依靠眼、眉、颊、下颌、嘴唇等已制作的变形目标。它仍受捕捉精度、角色绑定及角度范围限制，不能保证任意动作都准确。

## 候选与选择理由

| 候选 | 一手资料已确认 | 尚未确认 | 本轮定位 |
|---|---|---|---|
| DeepAR + 现成角色 | 有浏览器端角色示例、Web SDK、运行时参数接口；有小规模免费测试许可 | 具体角色商用权、纯虚拟画面、全部表情控制、脱离摄像头回放、离线许可行为、实际延迟 | 第一验证候选 |
| Banuba + 表情角色 | 官方提供 action units 驱动的三维表情示例、Web 集成示例 | 角色权利、报价、纯角色输出、外部配音与参数回放、目标电视表现 | 第一候选不过关时比较 |
| 火山 / BytePlus Effects | 有 Animoji 与生成式特效；原生端能力与授权文档 | 用户截图特效是否可授权、网页版本是否包含、实际报价与回放接口 | 暂不作为首个采购方案 |
| 可导出完整角色 + 现有 MediaPipe / Three | 当前工程已有捕捉、参数、回放和 Three 基础 | 满意且可商用的角色资产、完整绑定、材质和运行成本 | 封闭 SDK 不满足课程回放时的备选架构 |

### DeepAR：先挑角色，不先改产品

官方 [Animojis & Characters 示例](https://www.deepar.ai/demos) 包括 Baby Owl、Mr. Robato 等；优先比较猫头鹰和机器人这两个完整角色。公开可体验不等于获得资产分发权，商用前必须核对具体素材许可。

[价格页](https://docs.deepar.ai/deepar-sdk/pricing/) 当前列出：10 MAU 以内开发测试免费，带水印；1,000 MAU 以内为每月 25 美元或每年 250 美元。部分素材另收费，同一人跨设备/浏览器可能分别计数。这是公开 SDK 价目，不是角色资产或本项目的完整报价。

[Web 接入文档](https://docs.deepar.ai/deepar-sdk/platforms/web/getting-started/) 支持关闭默认相机、传入视频源及录制渲染输出；部署许可按域名配置。不能借用官方演示的许可，也不能假设 `localhost` 的示例豁免适用于项目的 `127.0.0.1`。

[Web API](https://docs.deepar.ai/deepar-sdk/deep-ar-sdk-for-web/api-reference/classes/DeepAR.html) 有 `changeParameterFloat` 等接口；[参数教程](https://docs.deepar.ai/deepar-sdk/tutorials/change-parameter/) 解释了控制已存在的 blendshape。**这只证明存在控制入口，不证明现成角色公开完整绑定、不会被内部追踪覆盖或支持无相机渲染。** `useExternalTrackingData` 文档也不足以证明可输入任意人脸参数；不能仅凭名称采用。

### Banuba：比较表情能力的备选

[官方表情示例目录](https://docs.banuba.com/far-sdk/tutorials/capabilities/demo_face_filters/) 包含 action units + blendshapes 和表情转移到三维模型的示例。可从 ActionunitsRabbit 等完整效果入手，不只比较贴脸面具。

[官方 Web quickstart](https://github.com/Banuba/quickstart-web) 需要客户端 token。未获得本项目试用许可前，只能完成资料与代码审阅，不能宣称 SDK 已集成。具体角色许可和商业费用尚未查明。

### 为什么暂不直接采购“抖音同款”

[BytePlus 官方 FAQ](https://docs.byteplus.com/en/docs/effects/docs-faq-sdks) 明确网页仅包含部分能力，需要确认具体特效是否提供。

火山 [公开刊例价](https://docs.volcengine.com/docs/intelligent-beautification-effects/product-quotation?lang=zh) 中，Android+iOS 贴纸 SDK 为每年 120,000 元，Animoji 素材每个每年 50,000 元；素材需要搭配 SDK。它不是本项目正式报价，也不代表网页授权。以当前小团队验证阶段，先确认可用性与效果，再考虑商务采购更合适。

## 和 Octos Learn 现有能力怎么接

已有、可复用：

- `src/learning/avatar/face-capture.ts` / Worker：本地捕捉、明确点击后启动、停止释放资源。
- `face-frame.ts`：按名称表达的脸部通道、头部角度和失跟状态；现有录制与回放轨迹。
- `performance-track.ts` / 片段存储：表演参数记录基础，不能因此声称已写入课程包。
- `lip-sync.ts`、`lesson-avatar-preview.tsx`、课程查看器中的 `AudioPlaybackClock`：配音嘴型与媒体时钟基础。
- 课程白板、M6 保存与播放流程。

两种接法必须区分：验证厂商实时效果时，让它单独承担捕捉和渲染，不同时运行第二个人脸追踪器；只有证明它支持参数驱动后，才考虑让现有 `FaceFrame` 成为统一输入。不能预先承诺商业 SDK 一定能接收 MediaPipe 或 ARKit 的全部通道。

现有渲染器只是消费了部分通道。收到 52 类检测系数，不代表角色已经有 52 种可靠表情；MediaPipe 与 ARKit 同名项的响应也不能不校准就视为相同。

### 录制时和发布后是两个验收场景

录制时：相机 → 表情/姿态 → 角色。渲染和可分享记录都必须只含虚拟场景。

发布后：课程的**最终合成语音** → 对应嘴型，另用安全的头动、眨眼、表情轨迹驱动角色。最终语音时长与孩子原始讲话可能不同，不能把整条原始嘴型轨迹原封不动套上去；非嘴部表演也需要按课程卡片对齐或重定时。

当前嘴型主要是音量包络，不是完整音素/视素。第一轮可以验证连续开口，后续若要逼真发音，需要更多嘴型与最终音频对齐。不能把“嘴巴动了”作为口型准确的结论。

课程播放器复用唯一的 `AudioPlaybackClock`，用真实播放位置取样，覆盖暂停、跳转和倍速。不要为头像另起一个声音播放器。

目前还有既有缺口：正式 `teach-lesson-player-page.tsx` 仍显示静态角色；`teach-watch-page.tsx` 的可选动态预览使用旧舞台。前端已有可带嘴型的 v2 包，但 `services/learner-lessons/package-check.mjs` 仍只接受 v1、MP3/白板/课程白名单与 32 MiB 限制。新角色无法靠替换实验页自动进入正式课程。

优先保持“完整角色 + 参数轨迹 + 最终语音”的播放形式。若 SDK 只能输出实时视频，不能据此绕过限制：需要另行评估匿名视频生成、音频重配、包格式、体积和离线播放，不能简单放开 MP4 上传。若这些代价过高，转用可导出的专业绑定角色，而不是继续打补丁。

## 下一步验证顺序和退出条件

以下是实施计划，**不是已完成结果**。先完成 1–3，再决定正式接入；现阶段不要求用户开摄像头或测试电视。

1. **资产与接口预检。** 确定一个完整示例角色及其授权来源；检查可控表情、渲染背景、丢脸行为、相机关闭后的状态和许可证要求。输出明确的支持/不支持/未确认表，不安装一串候选替代这个判断。
2. **最小视觉小样。** 有合法项目许可后，在现有本地开发入口隔离验证一个角色。先做静态参数扫描与受许可的输入回放，再按用户意愿做摄像头测试；无来源的公开视频、现有参数轨迹不能当作新的真人输入。交付同尺寸连续视频与定格：自然、大张嘴、闭嘴、圆唇、微笑、皱眉、单眼眨眼、左右转头、抬低头。
3. **匿名与回放闸门。** 检查首帧、模型加载失败、丢脸、重新识别、停止捕捉、授权失效时，显示/记录结果均不出现真人。关闭相机后尝试参数回放和最终音频驱动，覆盖暂停、跳转、倍速、重新打开页面；同时验证网络与离线行为。
4. **通过后接入课程。** 建角色目录与渲染适配层，版本固定并记录资产权利；打通逐卡表演/嘴型、两处正式播放入口和包校验。必要时改产品服务，但保持旧包可读。
5. **安卓触摸大屏验证。** 回放优先，可由电脑/iPhone 录制。要在大屏上捕捉，还取决于摄像头、WebView 和驱动；浏览器支持表不能替代实际测试。Web 不满足时再评估厂商原生 Android 路径。

建议验收门槛（不是厂商承诺，也不是当前测量值）：

| 项目 | 最小通过标准 |
|---|---|
| 张嘴 | 小/中/大三档可明显区分；最大开口符合角色设计；闭嘴无残留口腔 |
| 转头 | 左右约 30° 内有真实侧面与遮挡，头发/耳朵不被平面拉长；超范围有明确限制 |
| 表情 | 独立左右眨眼、抬眉、皱眉、微笑、圆唇及组合表情逐项展示，不靠宣传片替代 |
| 匿名输出 | 所有正常/异常状态，导出画面零真人帧；不上传、保存原始相机流 |
| 课程回放 | 不开相机即可播放；最终配音可控制嘴型；暂停/跳转/倍速不漂移 |
| 性能 | 电脑首轮目标稳定 30 FPS、端到端响应约 100–150 ms 内，连续运行 10 分钟；记录设备和分位值，再决定电视目标 |

角色设计不同，不能用人嘴像素开口与动物嘴像素开口相除评估准确率。需要结合捕捉参数、角色最大行程和实际主观观感判断。
