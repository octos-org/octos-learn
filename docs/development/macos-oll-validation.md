## 2026-09-21：空间白板与教学焦点

- 用户确认 v4 验证通过，继续推进。再次核对 app main b670417、OLL main 2b93d67 未变化，继续原特性分支。
- 用 SpatialBoard 替换固定双列布局。卡片原生测量，Rust spatial 按 placement/align/gap 计算位置与组范围；图像与公式放在同一世界坐标中。
- 增加嵌套组框、全览、拖动、鼠标锚点滚轮缩放、按钮缩放、恢复教学跟随。普通刷新保留手动视角，新教学目标才恢复自动取景，正在拖动时延迟请求。
- 对照原 Web：取景公式保持一致，CSS 使用 680ms cubic-bezier(.22,1,.36,1)，核心与原生宿主采用相同参数。暂停同时冻结过渡，恢复继续。数学按字形绘制并共享缩放矩阵，不改成图片。
- 首次启动发现自定义组件在 prelude 快照中不可见，补充导入注册模块后恢复。GPU 检查确认相机转换与裁剪正确；单位圆绘图区四边留白调整为相同总量，保持等比例。
- 滚轮锚点自动测试首次失败，经独立实例诊断，原因是 /snap 的控件 rect 取整，而实际布局顶部含 0.4 像素。增加只读精确视口状态，测试按真实坐标验证；没有改动正确的缩放公式。
- shared runtime 合计 15 项测试，应用 6 项测试通过，构建无新增警告。Metal 实际交互证据与最终验证见 OLL_MACOS_SPATIAL_VALIDATION.md、macos-validation-v5/evidence。
- 决策：当前实现明确限定单个 canonical 区域与现有课程动作序；旧 Web 的阅读栏、宿主障碍与附件、多区域和复杂关系重排不在本轮覆盖范围。跨节点连线仍用文字说明，不把分组边框误称为完整连线实现。Android 未安装。

- 补充处理连线两端落在同一节点不同片段时的取景：递归访问路径按分支隔离，不把合法的重复节点误认为循环；循环引用仍拒绝。新增独立回归用例。
