# 个性化老师与学习记忆：真实环境验收

日期：2026-10-24。用户决定在发布前先做真实环境验收（“合并#76，开始真实环境验收”）。

这次验收要回答整个计划的核心问题：一个真实学生连续上几天课后，老师是否**记得过去、了解学生、仍然认得出来**；学习地图、成就、周报和建议是否与真实经历一致。之前的验证用的都是合成数据，加上少量真实模型测试，不能替代这一步。

## 1. 环境（按 DEVELOPMENT_HANDOFF.md 的正常环境）

这台机器（yy）上原来没有正常环境：`~/.octos` 里只有 cache，没有账号、配置，也没有安装 Learning Coach。上一位开发者的环境在另一台机器上，不能拿来用。按项目约定，我不另建临时账号。下表中需要用户本人完成的步骤已经标出。

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 1 | agent | 构建 Octos main `5d9e70b4` 的正式版（不带内置向量模型，因为本机没有 cmake），已包含 #2859 |
| 2 | 用户 | 安装本机 HTTPS 证书：`brew install mkcert`，然后在 octos-learn 目录运行 `pnpm setup:https`（会在系统钥匙串加入本机证书，需要输入密码） |
| 3 | agent | 启动 Octos：`octos serve --solo --port 50080`，使用默认 `~/.octos`。启动前端：`pnpm dev:https`，地址 `https://127.0.0.1:5173/` |
| 4 | 用户 | 在浏览器打开前端，创建本机账号并登录；在设置里填写**你自己的**模型 Key。agent 不读取、不复制、不输出 Key |
| 5 | agent | 把 Learning Coach main `4685438`（0.16.5）正式安装到这个账号：`octos skills --profile <账号> install ../learning-coach` |
| 6 | 用户 | 设置里选一位老师。确认“自动分析知识点”“周报”“老师评语”“下一步建议”都是开启状态 |

费用：上课和分析都用你自己的 Key 计费，由你自己承担。每节课的生成费用约 0.01 美元；自动分析约 0.06 美元一节课，每天最多 10 节；周报评语每周最多一条，约 0.02 美元。验收全程估计在 1 美元以内。

## 2. 验收流程（跨至少两个自然周）

周报评语只针对已经结束的一周生成，所以评语要到下一周才能验收。

### 第一天

1. 提一个问题生成一节课，例如“斜率是什么？”。完成两次课后练习：第一次用提示，第二次不用提示。
2. 让老师知道一条长期偏好，例如“以后讲新东西先给我看图”。白板上没有单独的“告诉老师”入口，输入框里的话都会作为一次提问发给老师。两条路分开验收：
   - 在同一块白板的输入框里说这句话：看老师怎样回应（是否硬生成一节课，是否声称“已经记住”），以及 Octos 之后能否从对话中提炼出这条偏好；
   - 在设置 →“老师记得的事”→“让老师记住一件事”里直接添加：这是明确、可控的入口。
3. 下课后检查：
   - 学习记录 → 学习经过：问题和练习是否都在；
   - 学习地图：这节课涉及的知识点是否点亮，状态是否正确；
   - 成就：“初来乍到”“亲手搞定”是否颁发，颁发老师是否正确；
   - 下一步建议：是否合理，措辞有没有说“你不会”。

### 第二天（或隔几天）

4. 再问一个相关的问题。看老师有没有引用上次的偏好或经历，有没有准确提到地图状态（不把一次做对说成“已掌握”）。
5. 在设置的“老师记得的事”里查看记忆，试着更正一条、忘记一条，然后再上一节课，看是否生效。
6. 换成另一位老师上一节课：新老师不能把前一位老师的经历说成自己的。
7. 点一条建议：“回到那节课”能否打开原来的白板；“在新白板上问问”是否只预填问题、不自动发送。

### 下一周

8. 打开上一周的周报：数字是否与实际一致；老师评语是否准确、像这位老师；本周的建议是否更新。
9. 如果某天正好隔了 14 天，检查“回顾”建议和“老朋友重逢”成就。

## 3. 记录方式

- agent 在每一步之后检查服务端记录（学习地图、成就、周报、建议的接口输出），并与你实际做过的事对照。
- 发现的问题都记在本文第 4 节，写清现象、原因和处理结果，失败记录也保留。
- 不提交 Octos 日志（日志里有配对码），不记录 Key。

## 4. 发现与处理

| 日期 | 现象 | 原因 | 处理 |
|---|---|---|---|
| 2026-10-24 | 阶段五决定开启的“自动分析”实际上一直没有开启：服务端默认关闭，设置页也没有开关 | 费用测量完成后，没有落实开启 | 改为默认开启、每天最多 10 节，设置页加了开关（分支 `codex/acceptance-prep`） |
| 2026-10-24 | 用户指出：白板输入框里的话都会当作提问去生成课程或卡片，说“以后先给我看图”的场合并不明确 | 产品上偏好只能（1）混在提问里由 Octos 事后提炼，或（2）在设置里手动添加；白板上没有专门入口 | 第一天第 2 步改成两条路分开验收；白板上的体验问题待验收结果再定 |
| 2026-10-24 第一天 | 在白板输入“以后讲新东西先给我看图”，输入框上方出现红色提示“你想了解关于……的哪部分内容呢？请具体告诉我。”，这句话没有发给老师 | 客户端的提问快速检查（`src/learning/admission-fast-gate.ts:277`）把它当成含糊的提问拦下了，老师和 Octos 都没有收到。所以白板上说偏好这条路目前走不通 | 用户决定忽略这个功能（2026-10-24，产品重点改为老师角色、星图和成就）。偏好可以在设置里手动添加 |
| 2026-10-24 第一天 | 用户上完一节“斜率”课（豆豆），做了两次练习（一次用提示），但学习记录里只有提问和老师讲解，没有开始学习、播放片段、作答和提示的记录；学习地图、成就、周报都是空的 | 起初怀疑是没配语音导致旁白失败，复查后排除：旁白正常播放（4 条 ended）。浏览器本地保存了作答，但待上传队列为空。用这节课的真实内容在本地测试中复现：开发版运行在 React StrictMode 下，课程运行时会被构建两次，只保留其中一个，而记录器在构建时就绑定了运行时，结果绑到了被丢弃的那个，所以看不到真实的播放和作答。不开 StrictMode 时记录正常 | 改为在运行时实际提交后（layout effect）再绑定记录器，并保留构建它的那次渲染的记录上下文；新增 StrictMode 回归测试（修复前失败，修复后通过）。生产构建没有 StrictMode 的双重构建，但 React 并发渲染同样可能丢弃一次构建，所以照样要修 |
