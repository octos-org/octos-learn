# 数学课程质量优化方案

日期：2026-09-05，实施状态更新于 2026-09-06。本文保留设计依据；当前实现和验证结果见
[数学质量实施状态](MATH_QUALITY_IMPLEMENTATION_STATUS.md)。

## 结论

优先建立“教学目标 → 可用教学画面 → 确定性编译 → 播放前校验”的约束链。
模型负责理解与讲解，程序负责图像的数学正确性和可读性；不能让用户承担选组件、配坐标和写教案的工作。
先修坐标、错误图表和互动承诺不一致，再改善短问题教学设计，最后完善无明确问题的入口。

## 硬约束：不得回退已有生成速度优化

用户补充要求：项目已经多轮优化 prompt 长度和生成速度，所有数学质量修复必须保留这些成果。
质量和速度是同时通过的发布条件，不能用增加长提示词、多轮审查或等待整课完成换取质量。

1. 保留专用 action 快速路径，不回到外层通用 Agent；保留 outline + first_section 合并 bootstrap、流式输出、
   渐进可播放前缀、部分响应挽救和局部章节修复。首段只等待自身及其依赖，不等待整课校验完成。
2. 正常成功路径不新增模型往返。不新增独立的意图扩写、选图、审稿或修正调用；短输入理解沿用已有 admission/outline。
   不在正常路径默认启用额外模型或扩大 hedge。异常修复沿用现有预算，不提高重试上限或改成整课重生成。
3. prompt + capability catalog + JSON Schema 一起按模型实际输入 token 核算，不能仅看 system prompt 字数。
   原有案例的对应请求总输入 token 不高于冻结基线；新规则优先替换、合并旧规则，不追加长例子或全量教学手册。
   新能力使用简短、无歧义的声明；完整适用规则和验证数据留在代码中，不自动注入每个请求。
4. 不扩大每节模型输出负担：对象 ID、坐标、绑定、控件说明、验证报告和重复教学意图均由程序推导。
   优先复用现有计划字段，只为无法推导的教学选择保留最少结构化信息，不要求额外长篇 reasoning 或自检报告。
5. 数值与互动校验在本地有界执行：限制采样量和候选数，复用公式解析结果，避免全参数笛卡尔积扩张。
   不把重型符号求解、截图审查、全课扫描或 LLM 评分放进首段关键路径；拖动计算也不能阻塞播放。
6. 任何实现即使质量测试通过，只要证实造成性能回退，就不合入；先调整实现。不能靠降低模型质量、删减核心教学内容，
   或把旧 15 秒目标当成允许退化的余量来抵消性能损失。

实施前冻结当前优化基线的提交、prompt/schema、调用拓扑、重试/hedge 设置和 trace。
使用同一模型、输入、机器、缓存状态和可比课程目标做基线/候选交错对照；分别报告正常路径和含修复的整体表现。
记录请求数、逐请求输入/输出 token、首 token、首个真正可播放片段、后续播放断档、完整课程耗时、编译/校验耗时及修复率。
首段和整课 p50/p95 都不能出现可重复的回退；不能以首次返回文字或加载占位符代替“首个可播放片段”。
有限样本不能证明绝对零回退：结果落在噪声内时增加配对样本，不把不确定性算作通过；p95 不用三次样本宣称达标。

## 已查明的原因

### 1. 自动视窗只考虑数值可计算，没有充分考虑教学可读性

Learning Coach `src/lesson-plan-compiler.ts` 中：

- `deterministicFunctionViewport` 默认依次尝试 [-4,4]、[0.05,8]、[-10,10]，主要以有限采样比例选择横轴。
- `paddedNumericRange` 用 2%–98% 分位与 12% 留白确定纵轴。
- 参数曲线把所有参数的最小值、中值、最大值组合一起采样；移动点的范围也可能扩大横轴。
- 这能避免部分空图，但不保证顶点、交点、周期和局部变化清楚可见，也不保证参数极值时关键点仍在画内。
- 模型面对的函数图 Schema 不开放坐标范围，因此本问题不能简单归因于模型乱填范围。

已做无模型、可重复的编译对比：使用现有 `quadratic_translation` fixture，h、k 均为 [-5,5]。

| 输入 | 编译后横轴 | 编译后纵轴 |
| --- | --- | --- |
| 原 fixture，人工填写范围 | [-6,6] | [-6,12] |
| 删除范围，模拟模型自动视窗路径 | [-4,4] | 约 [-14.34,87.69] |

后者初始抛物线被明显压缩，h=±5 时顶点还在横轴视窗外。人工指定视窗的 fixture 会掩盖自动路径缺陷。

OLL `packages/web-runtime/src/board-view.ts` 的 plot 和 geometry 都会把 mapX(0)、mapY(0) clamp 到边界。
因此零点在视窗外时，边框会被画成坐标轴。原点的数学定义没变，但画面表达容易误导。
函数图默认 SVG 为 300×150，横纵单位长度也不一定相同；讲反函数对称、几何形状时需额外处理。

### 2. 图表匹配验证的是功能特征，没有充分验证证明适用性

`src/lesson-plan.ts` 的 `geometric_rearrangement` 只有三种 construction：
`right_triangle_square`、`square_area_identity`、`triangle_to_rectangle`。
没有圆面积扇形重排。目录阶段看到的是 `polygon_pieces / rigid_rearrangement / area_relation`
等概括特征，容易把“面积证明”误匹配到通用重排。

已有 unsupported 机制和提示词禁止错误替代，但这依赖模型先正确识别能力边界。
Schema 合法、控件有效、生成成功，仍不代表三角形画面能支持圆面积结论。
本次未取得用户那节错误课程的原始 trace，因此这是代码证据支持的原因分析，并非该历史请求的完整复盘。

### 3. 测试覆盖能力执行，缺少自然输入和教学质量门槛

已阅读旧 testsuite 的 `math-complete-course-cases.json`：共 12 个主题，原用途主要是完整课程时延测试，首段目标 15 秒。
提示词明确告诉模型教学顺序、例子、图表与控件；没有圆面积案例。
当前 `scripts/eval-lesson-plan-generation.mjs` 主要检查覆盖声明、章节、画面类型、曲线数、动画和控件等结构。
这些检查有价值，但不能单独证明选图正确、图像可读、推导成立或短输入不退化。

当前 admission 已接受“勾股定理”这类短主题，也已有 clarify / ignore 和摄像头识别分支。
应在此基础上增强教学意图补全，不另建一套重复入口。

### 4. 旁白承诺两个移动点，实际只编译一个

用户补充案例：斜率课要求移动图上的两个点，但画面仅一个点，控件卡片也只有一个变量。
代码核查：`compileFunctionPlot` 的采样点路径只读取一个 number，生成单个 `moving-point`，
并将它的 x、y 绑定到同一个变量及 f(x)。registry 中的多个 number 输入用于曲线参数，不能当成多个独立点。
当前函数图声明的操作方式是 slider，不能因为图上有点就承诺可直接拖拽点。

这属于“教学话语 → 可操作对象 → 控件自由度 → 数学反馈”断裂，不只是少画一个点。
现有控件有效性检查不能证明旁白承诺的对象数量、操作方式和反馈都实现了。
尚无该历史课程的 trace，本次确认的是当前能力边界，不声称已经复盘该请求的全部生成过程。

## 实施方案

### P0：坐标与曲线可读性

主要改 Learning Coach 编译器和 OLL Runtime，前端只负责升级锁定版本与交互验证。

1. 将数学定义域、教学视窗、控件范围分开。控件可取值范围不直接等于画面必须一次容纳的范围。
2. 在现有公式解析基础上，为一次、二次、指数、对数、三角、反比例等常见函数增加视窗策略。
   使用截距、顶点、交点、渐近线、周期和当前教学目标决定关键区域；一般表达式保留采样回退。
3. 视窗应覆盖当前关键点，留白并采用易读刻度。正弦通常展示少量完整周期；指数不能因尾部极值压扁主要区域；
   多曲线比较同时评估每条曲线，不能只看整体有限采样率。
4. 基础认识课默认包含零点；局部分析、远离原点的函数或正定义域可用局部视窗。
   零点在画外时只画真实边框与刻度，不伪装成 x=0 / y=0 坐标轴。不要一律强制原点位于画面中心。
5. 同一讲解阶段使用稳定视窗，避免拖动时每帧自动缩放而掩盖参数变化。
   参数越界时提供明确的重新取景或阶段切换；不能为容纳所有极值而无限扩大固定视窗。
6. 几何圆和反函数对称等任务使用等单位比例；一般趋势图允许不同尺度，但刻度必须清楚。
7. 复核间断点断线、裁剪、标签遮挡和移动点可见性。对 1/x、tan(x)、ln(x)、sqrt(x) 增加专项验证。

不让模型直接输出像素尺寸。确有需要时，让计划表达“观察顶点/比较交点/观察周期”等教学意图，程序决定具体视窗。
优先使用现有轴范围字段修复编译策略；新增视窗策略字段前先核查 OLL 的兼容性与回放确定性。

### P1：函数图卡片的探索与阅读能力

用户补充希望支持坐标轴范围缩放、卡片放大缩小及其他必要功能。
当前 Runtime 已有无限白板整体平移缩放，但函数图仍使用固定 SVG viewBox；不能把白板缩放当作函数视窗缩放。
建议明确区分三层操作，默认保持界面简洁：

| 操作 | 改变什么 | 保持什么 |
| --- | --- | --- |
| 图内放大/缩小、平移 | x/y 可见数值范围 | 函数、参数值、卡片位置与尺寸 |
| 卡片放大/缩小 | 单张卡片的显示面积与阅读空间 | 函数与参数；默认保持当前坐标范围 |
| 整块白板缩放 | 所有卡片在屏幕上的整体比例 | 各图内部的数学视窗 |

首版优先提供以下功能：

1. **图内缩放与平移。** 卡片工具栏提供 + / −、探索入口与“回到课程视图”。
   探索模式下，滚轮或双指捏合围绕指针/手势中心缩放，拖动图内空白平移；按钮围绕图中心缩放。
   默认同步缩放 x/y 的范围，保持原比例；进入探索前，滚轮仍按白板原有规则工作，避免无意缩放图像。
   若支持点拖动，命中可动点时优先改变该点，命中空白才平移；两者均不得同时移动整块白板。
2. **可靠的恢复入口。** “回到课程视图”恢复当前教学阶段的推荐视窗，不重置学生参数或播放进度。
   “重置参数”是独立动作。不得把无界函数的“显示全部”解释为显示整条曲线；需要时使用“适合当前关键点”并限定教学区域。
3. **放大查看。** 提供大图/全屏查看，共享同一个图像状态和参数；关闭后回到原卡片。
   优先于首版实现任意拖拽卡片边角，因为大图模式更容易避免遮挡旁边板书和破坏课程布局。
   放大后重新计算绘图区、刻度密度与采样精度，文字保持可读，不只是拉伸原来的小 SVG。
4. **读点与读曲线。** 鼠标悬停或触屏点按可查看曲线上的 x、y，显示十字参考线及对应公式。
   多曲线时明确当前选中哪条；靠近间断点不跨支吸附。数值近似要有适当精度，不把采样估计显示成精确证明。
   观察探针默认不计入课程中的 A/B 教学点、不改变学生变量，也不满足互动任务条件。
5. **清楚的曲线标识。** 图例展示公式、标签，并用颜色加线型区分；可临时显示/隐藏曲线和辅助线。
   教学所需曲线被隐藏时给出恢复提示，不能让练习在关键图形缺失时看似正常进行；课程视图恢复时恢复教学图层。

第二阶段再加入：

- **卡片尺寸调整**：先提供小/标准/大尺寸，确有需要再提供拖拽边角。重算布局、连线锚点与课程聚焦边界，避免卡片重叠。
  不用 CSS transform 假装卡片布局尺寸已改变。
- **高级坐标设置**：手动填写 x/y 最小最大值、只缩放一根轴、锁定横纵等单位比例、网格开关。
  范围须有限且 min < max，限制极端缩放。高级设置折叠，日常学习无需填写。
- **关键点辅助**：按教学目标显示截距、顶点、交点等；只对可可靠计算的结果展示，数值近似与精确值区分。
  两点斜率、割线和切线功能使用下文的真实互动契约，不能拿只读探针冒充可操作教学点。

比例和尺寸必须有明确规则：普通图调整卡片大小默认保留轴范围；等单位比例模式下优先保持数学比例，
可通过绘图区留白适配卡片，不能将圆拉成椭圆。非等比例图中，屏幕上的倾角不等于数学斜率；斜率始终用 Δy/Δx 算出。

播放、状态与性能约束：

- 用户探索视窗与课程推荐视窗分开保存。自动聚焦、字幕更新或每帧参数变化不能夺回用户视窗；提供“回到课程视图”恢复跟随。
  切换到不同教学阶段时明确提示可恢复新的推荐视图；练习所需点在画外时提供取景入口，不默默改学生变量。
- 视窗、图层可见性和卡片尺寸属于用户查看状态，不改写原始 OLL 课程；按用户/白板/稳定节点标识隔离，
  阶段或内容版本不兼容时丢弃旧视窗。刷新恢复合理的查看状态，正式课程回放可明确选择恢复课程视图。
- 点拖动和滑块属于教学变量操作，继续走现有输入与回放协议；不能混入仅用于查看的缩放事件。
- 支持触屏、键盘与可读按钮标签；大图关闭后恢复焦点，缩放按钮与“回到课程视图”让不熟悉手势的用户也能完成操作。
- 所有查看功能在前端/Runtime 本地执行，**零新增生成请求、零新增模型 prompt 字段**。
  按帧合并交互事件，仅重绘当前卡片，缓存解析结果；采样自适应但有上限，并保持奇点断线逻辑。
  不在拖动时重编译整课、不发送逐帧服务端请求、不影响首个可播放片段的生成关键路径。

验收覆盖三层缩放互不串扰、指针锚定、探索/点拖动/白板手势冲突、数学比例、关键点可见性、
全屏前后参数一致、布局与连线、阶段切换、刷新/回放、窄屏触控和键盘；性能同时检查连续操作的帧耗时与播放断档。
这些功能增强用户探索能力，但不能替代 P0 的合理初始视窗：课程首次出现就应清楚可读。

### P0：图表适用性与圆面积能力

1. 在能力 registry 增加适用概念、能解释的关系、前提、不能用于什么证明及必要参数。
   目录阶段也要拿到具体 recipe 的边界，不能只看到泛化的 area_relation。
2. 计划记录每个关键结论由哪个画面、哪一步推导支持。编译前校验主题、对象、公式和 construction 是否一致。
   优先从现有目标、画面引用和动作推导支持关系，不新增冗长的模型证明报告。
   固定 recipe 的适用性用程序规则兜底；开放式讲解的额外模型语义评估仅用于离线评测，不新增在线审稿调用。
3. 首批补足“圆面积扇形交错重排”：展示等分圆、交错拼接、分片逐渐细化、底趋近 πr、高趋近 r、面积守恒，最后推出 πr²。
   有限个扇形不能被说成精确矩形；画面与旁白明确区分近似形状和极限关系。
4. 先验证 OLL 现有圆弧、多边形、变换和绑定能否可靠表达这个过程。
   若只能用内接多边形近似，应说明近似来源并验证误差随分片数减少；能力不足再新增 sector/path 原语及测试。
5. 半径、分片数、重排进度各有明确作用，首版只暴露教学需要的控件，不为互动而添加无效参数。
6. 不匹配时只修复相关计划或章节，沿用现有重试预算；仍失败则明确说明该可视化暂不支持。
   可提供诚实的文字讲解选项，但不能把文字方案记为视觉任务已完成。
7. 第一段发布前完成它依赖的校验；后续章节在进入播放队列前校验。不可让错误证明先播完再修复。

### P0：互动承诺与画面、控件一致（首例：两点与斜率）

1. 在程序侧建立互动契约：实际对象及数量、固定/可动状态、独立自由度、支持的输入方式、绑定关系和反馈量。
   契约从 recipe 和编译结果生成，不能让模型自行声明“支持两个点”后就视为通过。
   检查应与现有控件有效性校验合并，输出仅包含修复所需的短错误信息。
2. 提供明确的两点斜率能力：A=(x₁,f(x₁))、B=(x₂,f(x₂))，两点标签、连线、Δx、Δy 与
   m=Δy/Δx 同步更新。两点均可独立移动时必须有两个独立输入通路；若采用滑块，应清楚标明它们分别控制 A、B。
   不要求用户另外配置四个 x/y 变量。若只移动 B，必须同时画出固定 A，讲解明确“固定 A，移动 B”。
3. 首版优先复用已验证的滑块与数值绑定，操作提示由程序依据实际契约生成，例如“调整 x₁、x₂ 两个滑块”。
   不能写“直接拖动图上的点”，除非 Runtime 确实支持点拖拽、定义域约束、双向数值同步及回放。
   recipe 的公式、点、连线与反馈由程序展开，不让模型逐项生成。
4. 区分数学目标：固定直线 y=ax+b 上移动两点，斜率应始终为 a；曲线上两点决定的是割线斜率。
   固定 A、让 B 趋近 A 可以讲导数，但不能把重合点处的 0/0 直接称为切线斜率。
   x₁=x₂ 时标明不可按该式计算；极近、跨奇点、越定义域或非有限函数值需要明确处理，不能显示伪数值。
5. 在章节入队前核对所有被引用或要求操作的对象已经出现、目标点可见、操作方式真实存在、独立控件均有效、
   连线及斜率反馈跟随变化。结构化互动提示由程序生成；自由旁白中的对象/动作表述用轻量一致性检查补充。
   不能声称规则能理解所有自然语言，漏检通过离线图文评审和回归样例持续补足。
6. 无法满足时拦截相关互动任务，在现有局部修复预算内修复；不得静默删掉一个点或把两个输入绑定为一个来“通过”。
   明确要求两点独立移动的课不得降为单点课；一固定一移动仅适用于教学目标本就允许的场景，且要同步修正讲解。

专项验收包含：一句“斜率是什么”、直线斜率不变、曲线割线变化、明确要求两点独立移动、固定一点、重合点、
趋近时的分母保护、定义域边界、画面与操作提示数量不一致，以及刷新/回放后的点位和控件一致性。
浏览器必须分别操作两个输入并验证对应点和反馈实际变化，不能只数 DOM 中有两个点或两个滑块。

### P1：短输入也能得到完整、适当的课

在现有 admission + outline 流程内补足教学意图：主题、学习目的、已知基础、核心疑惑、必要解释链和检查点。
优先复用已有目标、章节和覆盖字段，程序派生内部意图，不要求模型重复输出一套长结构。
区分用户明确要求与系统默认安排，不伪造用户年级或基础；不增加意图扩写调用，不把短输入先扩成长提示再请求生成。

| 用户输入 | 预期行为 |
| --- | --- |
| “圆的面积为什么是 πr²？” | 识别为推导请求，重点是面积守恒与 πr、r 的来源，不只代入数值 |
| “二次函数” | 采用可调整的入门深度，概念 → 图像 → 参数 → 一个小检查；不要求用户指定组件 |
| “导数看不懂” | 从局部变化率建立直觉，再连接割线、切线与公式 |
| “我不会问，但这一步不懂”且有明确选中内容 | 利用相关白板/题目上下文定位困难，不重复整节课 |
| “数学不会”且没有上下文 | 一个低负担问题或主题选择，不强行猜某个知识点 |
| 空白、噪声或仅语气词 | 保留 ignore；界面提供可点选主题、例题或拍题入口，不自动编造课程 |

课程完整度按目标衡量，不强制固定章节数或每课必有动画、练习。
“为什么”必须补推导因果，“怎么算”必须有步骤与检验，“是什么”必须有直观意义和适用边界。

### P1：把旧测试集升级为自然输入质量回归集

保留 12 个原始详细提示作为兼容回归；为每个主题增加四类表达：一句自然问题、只有主题、表达困惑、带明确上下文的指代。
初步形成 60 个变体，另补圆面积、两点斜率互动、信息不足、噪声、错误前提与不支持能力案例。
上下文案例必须固定图片/选区/历史输入，不能仅把“这个”当成自包含问题。

同一主题共享数学目标，但按输入意图设置不同门槛；不要求主题词版本机械复刻详细提示中的数字和所有交互。
评测期望保留在 evaluator，不能拼回用户提示或提前告诉模型选什么组件。

分三层评测：

- 确定性：公式/域/轴/关键点、控件范围与绑定、对象数量/独立自由度/操作提示一致性、recipe 适用性、圆面积守恒或近似误差、播放前拒绝错误内容。
- 真实生成：固定 provider/model，保存输入、结构化计划、编译 OLL、修复原因、token 与首段/总时延。自然输入重复至少 3 次看稳定性。
- 浏览器：实际锁定 OLL 依赖下截图与交互，覆盖初值、中间值、极值、窄屏、课程刷新和回放。人工按图文一致性与教学完整度复核；模型评分仅辅助。

建议发布门槛（待首轮基线后校准，不是当前已达成的指标）：

- 确定性数学错误与已知错误替代回归案例全部拦截；严重错误零容忍。
- 核心自然输入集至少 95% 同时通过正确性、选图、可读性、目标覆盖；分别报告四项，不能以总分掩盖错误证明。
- 同主题简短输入相对详细输入的通过率差距不超过 5 个百分点；小样本同时报告失败数量。
- 速度必须同时满足本文的冻结基线无回退约束与旧集 15 秒首段目标；后者不是允许变慢的预算。
  检查 prompt/schema token、正常路径调用数、首段/整课 p50/p95、播放断档、编译成本与修复率。
- 不得用丢失核心推导、无效互动或错误画面换取速度和通过率。
